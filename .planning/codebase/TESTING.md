# Testing Patterns

**Analysis Date:** 2026-08-13

## Test Framework

**Unit runner:** Go `testing` driven through `gotestsum` (`task test`,
`Taskfile.yaml:185`):

```bash
task test                        # gotestsum -- -race -count=1 ./...   (+ task test:gorules)
task test -- ./internal/command/ # scope to a package
task test -- -run TestX ./internal/command/
task test:verbose -- ./pkg/...   # standard-verbose format
task test:gorules                # analysistest suite for the gorules/ analyzer module
task test:cover                  # -coverprofile=coverage.out -coverpkg=./...
task test:int                    # integration tier (needs Docker)
task test:int:focus -- -ginkgo.focus="..."   # focused, -race hardcoded
task test:e2e                    # Playwright in Docker
task web:test                    # vitest + svelte-check
task test:bats                   # bats shell tests under scripts/tests/
task test:bench / task test:fuzz # benchmarks / fuzzing
task quarantine:audit            # fail if a quarantined spec's issue is closed
```

**Assertions:** `stretchr/testify` (`require` for preconditions, `assert` for the
check under test) at the unit tier; **Ginkgo v2 + Gomega** at the integration tier.
**Mocks:** `mockery` (`.mockery.yaml`, `with-expecter: true`), regenerated by
`task mocks:generate`.

**MUST run `task test` before claiming an implementation complete;
MUST run `task lint` before committing** (`CLAUDE.md`).

## The tier model (the core of this document)

| Tier | Dependencies | Runner | Build tag |
|------|--------------|--------|-----------|
| unit | none | `task test` | (none) |
| bus-integration | embedded NATS (`eventbustest`) | `task test:int` | `//go:build integration` |
| audit-integration | embedded NATS + Postgres testcontainer | `task test:int` | `//go:build integration` |
| full-stack integration | embedded NATS + Postgres + real `CoreServer` | `task test:int` | `//go:build integration` |
| whole-system plugin | the above + ALL in-tree plugins loaded | `task test:int` | `//go:build integration` |
| external-NATS | a **real** single-node NATS JetStream container, per-replica `*nats.Conn` | `task test:int` | `//go:build integration` |
| E2E | full Docker stack driven through a real browser | `task test:e2e` | Playwright |
| web unit | none | `task web:test` | vitest |

**`task test` does NOT compile `//go:build integration` files.** Refactors of
shared types/interfaces break the integration tree silently — always run
`task test:int` on a refactor (`CLAUDE.md`, MUST).

### Integration harness — `internal/testsupport/integrationtest`

Canonical in-process stack (Postgres testcontainer + embedded NATS JetStream +
production `CoreServer`):

```go
// internal/testsupport/integrationtest/harness.go:403
func Start(t *testing.T, opts ...StartOption) *Server
```

`integrationtest.Start(t, integrationtest.WithInTreePlugins())` is the
**whole-system plugin tier** — loads every in-tree plugin through
`setup.PluginSubsystem` → `Manager.LoadAll` (INV-5, INV-WS-1). It requires binary
plugin artifacts, which `task test:int` builds automatically via
`plugin:build:host`. Options live in `options.go`; `real_abac.go` supplies the real
ABAC engine and a `DenyAllEngine` denial path.

### Embedded vs real NATS

Embedded NATS (`internal/eventbus/eventbustest`) matches production and is correct
at **every** tier EXCEPT external-mode-specific behavior — external dial /
fail-closed boot, single-principal account scoping, multi-node per-replica crypto
invalidation, DLQ against a real broker. Those need N replicas with independent
connections to one broker, which the shared in-process connection cannot express:
use `internal/testsupport/natstest`.

### Session store needs Docker even under `task test`

Session-store tests MUST use `sessiontest.NewStore(t)`
(`internal/testsupport/sessiontest/store.go:37`) — the deliberate SharedPostgres
exception to the "unit tier has no dependencies" rule.

### E2E

Playwright specs live in **`web/e2e/`** (not `test/e2e/`). `task test:e2e`
(`Taskfile.yaml:310`) builds the Docker image, refuses to start if a
`holomush-e2e` compose project is already up, runs `npx playwright test` in the
`playwright` service, and always tears down with `docker compose … down -v`.
`task test:e2e:cover` runs the binary-coverage-instrumented variant.

## Test File Organization

- Unit tests co-located: `foo.go` → `foo_test.go`.
- Integration tests: `*_integration_test.go` beside the code, **or** feature suites
  under `test/integration/<domain>/` (access, audit, auth, crypto, eventbus_e2e,
  eventbus_external, plugin, presence, privacy, scenes, session, wholesystem, …).
- Plugin store integration tests live at `./plugins/<name>/` with the integration
  tag — **not** under `test/integration/plugin/`.
- Meta-tests (the repo's self-guards) live in `test/meta/`.
- Shell tests: bats under `scripts/tests/`.

Every integration file starts with the tag:

```go
//go:build integration

package scenes_test
```

## Test Naming — ACE

A test name is a **sentence**: Action, Condition, Expectation.
`TestConfigDirUsesXDGEnvVarWhenSet`, not `TestConfigDir_EnvVar`. With subtests, the
parent names the unit and the subtest strings carry the sentence
(`t.Run("rejects empty password", …)`). Subtest strings are lowercase; no
`"success"` / `"error case"` / `"test 1"`.

*Enforcement:* `test/meta/ace_naming_registry_test.go` is a **ratchet** that
enforces the MUST, not the SHOULD — underscores are fine as a separator; what it
flags is an underscore-form name whose FINAL segment is a single CamelCase word
(`TestStatus_String`, `TestClient_Subscribe`), i.e. a name terminating in a bare
topic with no expectation clause. Two exemptions exist and deliberately no
mechanism for a third.

## Test Structure

**Table-driven** is the default unit shape:

```go
tests := []struct {
    name     string
    input    EventType
    expected string
}{
    {"returns say for event type say", EventTypeSay, "say"},
}
for _, tt := range tests {
    t.Run(tt.name, func(t *testing.T) {
        assert.Equal(t, tt.expected, tt.input.String())
    })
}
```

**Ginkgo/Gomega** at the integration tier (`test/integration/scenes/…`):

```go
import (
    . "github.com/onsi/ginkgo/v2" //nolint:revive // ginkgo convention
    . "github.com/onsi/gomega"    //nolint:revive // gomega convention
)

var _ = Describe("INV-SCENE-17 + INV-SCENE-24: AutoFocusOnJoin terminal filter", func() {
    It("excludes non-terminal connections from FocusedConnectionIDs", func() { ... })
})
```

Async: `Eventually(func() int { return len(results) }).Should(Equal(expected))`.
Never assume a `_test.go` is BDD — plain `func TestX(t *testing.T)` files are common
in `test/integration/eventbus_e2e/`; verify with `rg "var _ = Describe" <file>`.

## Test Quality Rules (`.claude/rules/testing.md`)

| Rule | Enforcement |
|------|-------------|
| MUST write tests before implementation (TDD) | GSD `tdd_mode` gates when enabled; otherwise convention |
| Every exported function gets a positive AND negative test | convention only |
| No zero-assertion "doesn't panic" tests | convention only |
| One behavior per test — if it needs "and", split it | convention only |
| Prefer `errutil.AssertErrorCode` / `assert.ErrorIs` over string matching | convention only |
| `require.*` for setup, `assert.*` for the check under test | convention only |

## Mocking

**mockery** — config `.mockery.yaml`, `with-expecter: true`, boilerplate from
`.mockery-boilerplate.txt`, output to `{{.InterfaceDir}}/mocks` (package `mocks`).
Mocked interfaces include `core.EventStore`, `grpc.{Auth,Reset,Character}ServiceProvider`,
`plugin.{Host,EventEmitter,ServiceProxy}`, `hostfunc.KVStore`, world interfaces.
Regenerate with `task mocks:generate`.

```go
pub := mocks.NewMockPublisher(t)
pub.EXPECT().Publish(mock.Anything, mock.Anything).Return(nil)
```

**Mocking style varies by package** — `internal/web/` uses hand-rolled struct mocks
(`mockCoreClient` in `internal/web/handler_test.go`); `internal/grpc/` and
`internal/world/` use mockery `EXPECT()`. Verify with
`rg -n 'EXPECT\(\)|type mock.*struct' <package>/` before writing a new test.

### ABAC test engines

`internal/access/policy/policytest` supplies the authorization fakes:

```go
mockAccess := policytest.NewGrantEngine()
mockAccess.GrantCommandExecution(subject, "say", "look") // layer 1
mockAccess.Grant(subject, "emit", "stream")              // layer 2 / capability
```

Also `AllowAllEngine()`, `DenyAllEngine()`, `NewErrorEngine(err)`,
`NewInfraFailureEngine(t, reason, policyID)`.

these imports from any non-`_test.go` file outside `internal/testsupport/**`,
`internal/cluster/clustertest/**`, `test/testutil/**`:

- `internal/eventbus/eventbustest`
- `internal/core/coretest`
- `internal/testsupport/quarantinetest`
- `internal/testsupport/natstest`
- `internal/testsupport/integrationtest`

`task lint:test-helpers` (`Taskfile.yaml:818`) adds a shell gate banning
`policytest` imports from production `internal/`/`pkg/`.
`test/meta/depguard_config_test.go` guards the config itself against silent removal.

## Quarantine

Quarantine is for **flakiness with an open GitHub issue and no reproducible
cause** — if the root cause is known (contention, race, undersized CI), fix it.

Three marker idioms:

| Stack | Marker |
|-------|--------|
| Go unit/integration | `quarantinetest.Skip(t, "holomush-xxxx")` |
| Ginkgo | `if !quarantinetest.Enabled() { Skip("quarantined: holomush-xxxx") }` |
| Playwright | `{ tag: ['@quarantine', '@holomush-xxxx'] }` |

Every marker needs a row in `test/quarantine.yaml` with `id`, `kind`
(`go|ginkgo|playwright`), `bead` (marker token), `issue` (GitHub number), `since`,
`reason`. New entries mint `holomush-i<issue-number>`.

*Enforcement:* `test/meta/quarantine_registry_test.go` (INV-2) enforces the
marker ↔ row bijection; `task quarantine:audit` → `scripts/quarantine-audit.sh`
(INV-3) fails when a cited issue is closed. Quarantined specs self-skip in gating
CI and `task pr-prep:full`; run them with `HOLOMUSH_RUN_QUARANTINED=1`.

**CI-only integration failures** showing `connection refused` / `unexpected EOF` /
testcontainer-start errors are usually a transient Postgres testcontainer drop
under load — check the parent commit's CI and re-run before filing or quarantining.

## Invariant bindings in tests

A test that genuinely proves a registry invariant carries
`// Verifies: INV-<SCOPE>-N` immediately above it, and the YAML entry flips to
`binding: bound` with `asserted_by:`. Never annotate a test that merely touches the
code — `TestBoundInvariantsAreGenuinelyAsserted` in
`test/meta/invariant_registry_test.go` fails a `bound` entry whose sites are all
Skip-only placeholders, but it cannot detect a *partial* binding (a test asserting
one clause of a multi-clause invariant) — that needs human review.

## Coverage

Coverage is measured by **codecov** at two granularities — **patch** (the lines a
PR changed) and **project** (whole repo). It is **NOT** measured per package, so
there is no per-package floor.

| Status | Config (`.codecov.yml`) | Meaning |
|--------|-------------------------|---------|
| `patch` | `target: 80%`, `threshold: 5%` | changed lines should hit 80% |
| `project` | `target: auto`, `threshold: 0%` | rising-floor ratchet — no drop below base |

Both POST statuses on the PR but are **not** required protect-main checks today;
they gate merges only if added to ruleset `11923801`. Required checks are
[Build, Lint, Test, CodeRabbit, Integration Test, E2E Test] plus `Vuln`.

Local: `task test:cover` — `-coverpkg=./...` instruments **all** packages so a test
in A that exercises B credits B. HTML generation is best-effort (`|| true`;
build-tagged files can produce "inconsistent NumStmt"). `task test:int` also writes
`coverage-int.out` with `-coverpkg=./...`; `task test:e2e:cover` produces
`coverage-e2e.out`. Three uploads → three codecov sessions; a reading is final only
once `state: complete` and the expected session count are both observed
(`.codecov.yml` documents an observed 69.12%-vs-79.11% partial-evaluation window).

**Race detection:** `-race` is on for every unit run (`task test`, `test:cover`).
It is deliberately **off** on the per-PR integration path (2–10× multiplier) and
runs nightly via the Soak workflow (`task test:int RACE=-race`). Opt in locally
with `RACE=-race task test:int`. `task test:int:focus` hardcodes `-race`.

## Web unit tests

`task web:test` (`Taskfile.yaml:710`, `dir: web`) runs `pnpm test:unit`
(`vitest run`) then `pnpm check` (`svelte-kit sync && svelte-check --tsconfig
./tsconfig.json`). `web/package.json` does **not** include
`@testing-library/svelte` — importing it would add an undocumented dependency.
