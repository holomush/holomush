**The claim-site qualifier gate — why it can fail.** It is line-scoped, not file-scoped.
Three specific traps were tested and are closed:

1. *File-scoped `rg -qi lockfile` would be vacuous.* CONTRIBUTING.md will contain the word
   "lockfile" in the new Dependency-only bullet regardless of whether line 114 or line 162
   was amended, so a per-file grep goes green with the carve-out entirely absent. The gate
   therefore checks a 3-line window anchored at each `scripts/**` match line, independently.
   Verified pre-fix: all five windows lack the qualifier, gate exits 1.
2. *A glob-set grep would be vacuous.* `rg -q 'uv\.lock'` is satisfied by the restated glob
   list alone. That is why the gate keys on the word `lockfile` in the assertion's own
   window, not on a filename anywhere in the file.
3. *`.github/workflows/scripts-tests.yaml` is a false positive twice over.* It matches
   `scripts/**` (a `paths:` filter, not policy) AND contains `--frozen-lockfile` at line
   106, so a naive discovery scan would silently mark it "qualified" and mask a real
   miss. It is excluded via `-g '!**/workflows/**'`, verified to leave exactly the four
   policy files.
4. *Vacuous-empty and drift are both guarded.* The discovered file set is compared for
   equality against the four expected paths, so an `rg` that matches nothing fails loudly
   rather than skipping the loop body, and a newly-added claim site elsewhere under
   `.github/` fails until it is listed and qualified.

A repo-wide variant was rejected: it also matches
`docs/superpowers/specs/2026-05-25-retire-lefthook-license-eye-design.md`, a historical
design doc that is not contributor policy.

**Tooling:** `yq` (mikefarah v4) is on PATH at `/opt/homebrew/bin/yq`.

**Shell hazard (applies to every gate below).** `set -o pipefail` does NOT extend to
process substitution: in `while … done < <(yq -e …)` a failing `yq` leaves the loop body
unexecuted and the gate exits 0. Every loop in this plan therefore captures its input into
a variable first, checks the capture's exit status, and iterates with a here-string.
