`web/buf.gen.yaml` from `buf.build/bufbuild/es:v2.12.1` to `:v2.14.0` and running
`task --force web:generate` rewrote **30 files** under `web/src/lib/connect/**`:



exactly as `CONTRIBUTING.md` describes for regenerated code. Per the decision gate,

## Accepted risk: the playwright grouping rule was deliberately dropped

Per explicit direction, **no `packageRules` entry grouping `@playwright/test` with
the `mcr.microsoft.com/playwright` Docker image was added.** The reason is the
standing cost: a grouped PR necessarily contains `compose.e2e.yaml`, which is
deliberately non-exempt from the Issue Gate (`CONTRIBUTING.md:172-173`), so the group
could never auto-merge and would always require a chore issue.

**The consequence, stated plainly:** Renovate continues to track the two halves as
independent dependencies — the Dependency Dashboard (#4450) lists
`mcr.microsoft.com/playwright v1.61.0-noble → [Updates: v1.61.1-noble, v1.62.1-noble]`
separately from the npm package. Future playwright bumps will therefore keep arriving
as two separate PRs, and **this version-mismatch failure can recur**. When it does,
the fix is to bump both halves by hand in one commit. This is a deliberate trade-off,
not an oversight.
