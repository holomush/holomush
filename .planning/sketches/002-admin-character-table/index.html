Characters

Every character in the game, across all players.

This table now sorts on more than SPEC §11.3 permits — three amendments are required before Phase 6 builds it.
A1 · last_active_at does not exist. It cannot be derived: sessions rows are reaped and session_connections.last_seen_at is a gateway lease, so both answer "online now", not "last active". Needs a durable column on characters, a write path at session start, and a §11.3 row.
A2 · sorting by player. §11.3 says characters.player_id is "equality filter only … never an ordering". What this column actually sorts is players.username, a joined column §11.3 never enumerates — so it is excluded by default rather than by that row. Ordering by it discloses nothing to an audience that already sees it, which is §11.3's own stated safety test.
A3 · AdminSearchCharacters "searches names" (§9.2) — meaning character names. Searching player usernames extends it.
Unchanged and honored: description, location_id and every profile.* row stay excluded, and there is deliberately no sort dropdown and no facet panel — §11.3 names a sort control drawn from the §7.2 field list as "the specific warning sign".
