<objective>
Land the character lifecycle vocabulary as a usable domain concept and bind the two
invariants 01-SPEC.md §13 assigns to Phase 2: INV-WORLD-5 (exhaustive lifecycle
reads) and INV-WORLD-6 (retire preserves the name reservation).

Migration `000054` (plan `02-01`) added the columns. This plan makes them mean
something: a closed Go vocabulary, one selection predicate every read routes
through, and the two tests that prove the unreachable `idle` value is covered
non-vacuously and that retirement does not free a name.

Purpose: §4.3 is explicit that shipping a value nothing can reach is safe **only**
when paired with the exhaustive-read rule. An unreachable enum value plus a
non-exhaustive check reads correct for exactly as long as the value stays
unreachable, and fails open on the day a later milestone makes it reachable — a
change made by someone with no reason to audit every lifecycle read.
Output: `internal/world/lifecycle.go`, an exhaustive `Selectable` decision, and two
bound registry invariants.

**Requirement mapping note.** This plan's ROADMAP obligation is the phase-goal item
"the character **lifecycle column**". Of the six requirement IDs allocated to
Phase 2, IDENT-09 is the one it advances: INV-WORLD-6's guarantee — that a name
stays reserved through retirement and is released only by a sanctioned hard-delete
path — is a statement about exactly the name-reservation surface IDENT-09's unique
index enforces, and the two are asserted against the same column.

**INV-WORLD-6 is amended before it is bound (cross-AI review HIGH #5, confirmed
against the tree).** The shipped registry entry
(`docs/architecture/invariants.yaml:5074-5081`) says `world.Service.DeleteCharacter`
is *"the **ONLY** path by which a character name becomes claimable again"*. That is
already false: `internal/auth/character_reaping.go:90-97` documents
`CharacterReapingService` as *"the SECOND sanctioned out-of-world writer under
INV-WORLD-4"*, and `reapCharacter` deletes the character row via
`s.deleter.Delete(txCtx, char.ID, char.Version)` (`character_reaping.go:263`) —
releasing the name by exactly the same mechanism. Binding the entry as written would
put a **fabricated guarantee** in the registry, which `.claude/rules/invariants.md`
forbids outright and which `TestBoundInvariantsAreGenuinelyAsserted` cannot catch
because the test would genuinely assert the *retire* half while the exclusivity half
is simply untrue.

Task 3 therefore **edits the entry's summary in the same change that binds it** —
which the rule explicitly requires ("MUST update on change") — to enumerate both
sanctioned deleters, and Task 2 adds a guest-reaping release proof so the
enumeration is asserted rather than asserted-by-omission. The corresponding
`01-SPEC.md` §13 text is amended in plan `02-11` (Amendment E) so the spec and the
registry do not disagree.
</objective>
