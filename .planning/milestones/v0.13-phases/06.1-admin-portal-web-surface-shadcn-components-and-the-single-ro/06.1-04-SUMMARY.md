## What the browser found that jsdom could not

Three defects, all of which compiled, type-checked and passed every unit test.

### 1. A settled search silently discarded the operator's draft

`row` is a prop, and `characters/+page.svelte` hands down a **fresh object** every time the list is re-read — a debounced search settling, a sort, a page turn. The detail fetch was keyed on reading `row.id` inside an `$effect`, which subscribes to the **prop**, not to the string. Every re-read therefore:

1. re-ran `AdminGetCharacter`,
2. set `detailState = 'loading'` → `Save changes` went disabled mid-edit,
3. and on resolve reseeded `working` from the server, **discarding whatever had been typed**.

It surfaced in Playwright as a permanently disabled submit with a draft still on screen, in three different tests, for what looked like three different reasons. The fix keys the fetch on the character:

```
let fetchedFor = $state('');
$effect(() => {
  const id = row.id;
  if (untrack(() => fetchedFor) === id) return;
  untrack(() => { fetchedFor = id; void loadDetail(id); });
});
```

This is `ProfileSection.svelte:70-83`'s hazard one level up, and it is answered the same way. A regression case was added; deleting the guard line fails it:

```
AssertionError: expected 2 to be 1
```

### 2. The 16px phone-band input rule lost to Svelte's own scoping

`:global(.editsheet input)` is specificity **(0,1,1)**. Svelte compiles this component's own `.control { font-size: 14px }` into `.control.svelte-xxxx` — **(0,2,0)** — which wins. Chromium reported `14px` where the contract says 16, which is precisely the iOS zoom-on-focus footgun the rule exists to prevent. Both rules in the block now carry a **doubled class**, and the comment says the doubling is load-bearing on each for a *different* reason (the height beats a generated Tailwind utility at equal specificity; the font beats Svelte's scoping).

### 3. Initial focus on `Cancel` was set by an effect the primitive then overrode

A mount `$effect` calling `cancelEl.focus()` passes in jsdom and loses in Chromium: bits-ui focuses the content element on open, **after** mount effects run. `toBeFocused()` read `inactive`. It now goes through the primitive's own `onOpenAutoFocus` hook, which is the ordered seam.

## Decisions worth carrying

### The lifecycle picker is a native `<select>`

The plan requires a Vitest case that **selects** `Retired` and asserts zero RPCs. bits-ui's `Select` is popover-driven and cannot be driven in jsdom — which is exactly why 06.1-03 asserted the filter bar's option list from `ADMIN_STATUS_FILTERS` rather than from the control. A native `<select name="lifecycle">` makes the selection drivable, and a native `<option disabled>` is **browser-enforced unselectability** rather than a click handler that declines, which is the stronger reading of §10.6's `idle` rule.

The cost is real and stated: the admin surface now has one bits-ui select (the status filter) and one native select (the Sheet's lifecycle). Nothing in the UI contract mandates bits-ui here; the `select` primitive was added for the filter bar.

Selecting a transition **snaps the control back** to the character's current lifecycle immediately, because selecting is not applying and a control left showing the new value would claim it had.

### The confirm's action is a plain button

`AlertDialog.Action` closes the dialog on click. That would dismiss the confirmation before the RPC answered, leaving a failure with nowhere to land except a toast — and a toast is the receipt for something that **finished**. Closing is the page's decision, taken when the RPC resolves. `AlertDialog.Cancel` is kept as-is, because cancelling *should* close.

### The Sheet's footer is sticky

Thirteen fields — five of them textareas — are taller than any viewport. Playwright reported the submit `outside of the viewport` after scrolling. A submit that scrolls off the bottom of its own form is unreachable exactly when the operator is done, so the footer sticks to the bottom of the Sheet's scroll container.

### `adminWireField` is one rule, not a second table

The flat request field for a mask path is the path minus its `profile.` prefix — the server's own naming rule. It is exported from `client.ts` and imported by the Sheet's module block, so the `name` attributes on the form and the keys on the request come from the same function rather than from two spellings of one rule.
