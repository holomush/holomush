# Phase 06.1 Plan 08: Breakpoint census reach and proof stability (G-06.1-5) Summary

The census that ROADMAP criterion 4's "by construction" rests on now measures its own reach
against its own checked-in claims, counts occurrences instead of testing containment, fails
loudly on a file type nobody classified, and sees two band shapes it was blind to — and the
two adjacent proofs in its family no longer fail for reasons unrelated to what they guard.

## What was built

**Task 1 — the census (`9f301d043`).** Six changes in
`test/meta/web_phone_band_breakpoint_census_test.go`:

1. `bandedViewportRule` gained `count int`; the two duplicated `TopBar.svelte` entries
   collapsed into one with `count: 2`; the per-rule assertion became
   `require.Equal(r.count, strings.Count(src, r.rule))`. A zero-count entry is rejected
   outright — it would otherwise assert `Count == 0`, which every file that does not carry
   the rule satisfies.
2. `require.Greater(t, scanned, 15)` is gone (not adjusted). A second tally, `bandRelevant`,
   counts viewport-deciding lines carrying a forbidden width **or** `theme(--breakpoint-`,
   and is asserted `>=` the sum of the census's own counts. `scanned` survives only as
   context inside the failure message.
3. `scannedExtensions` is now paired with `skippedExtensions`; an extension in neither set
   appends to an `unclassified` list that is asserted empty **before** the floor, because an
   unclassified file means the corpus measurement is incomplete. Extensionless files are
   skipped.
4. `isViewportDecidingLine` gained `min-[`/`max-[` and `window.innerWidth`/`window.outerWidth`.
5. `referenceDirectiveFor` handles `dir == "."` as depth 0.
6. The whole meta package was re-run each time, not only the two breakpoint tests.

**Task 2 — the band sweep's settle (`d14c4df42`).** `BAND_SETTLE_MS = 300` and the
`waitForTimeout` are gone. `columnsAt` sets the viewport, then polls a **single** evaluate
returning both widths until two consecutive samples are identical, then takes one final
paired sample. One evaluate, not two, because every assertion in the block compares the two
columns to each other; two reads can land in two frames and turn a passing layout into a
divergence. The poll decides only *when* to measure — every existing expectation still does
the judging, so a slower transition costs time rather than correctness. The
one-expect-per-column shape, the `:not(.is-drawer)` qualifier and every width and Sheet
`data-side` assertion are unchanged.

**Task 3 — the CharacterTable anchor (`e8857775a`).** Two CSS comment markers,
`phone-band-overlay:start` / `:end`, bracket the phone-band rules. The test asserts both
markers **and their order** before slicing, then slices between the marker *comments* so
their prose cannot be captured as part of a selector. The verbatim media-condition copy is
gone from the test file entirely.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 — Bug] The plan's prescribed comment for the `window.innerWidth` clause is factually false**
- **Found during:** Task 1, before writing the clause
- **Issue:** the plan says to "note in the comment that neither shape exists in the tree
  today, so these clauses are prospective coverage". `min-[`/`max-[` genuinely has zero
  occurrences, but `window.innerWidth` appears on **four** lines today —
  `lib/components/terminal/Composer.svelte:49,102,123` and `lib/sentry.ts:87`. Writing the
  plan's sentence verbatim would have put a **fourth false claim** into the very file plan
  06.1-07 spent a commit removing three from.
- **Fix:** the comment states the truth, names the four sites, and explains that all four are
  positioning/telemetry arithmetic carrying no band width — so they widen the screened tally
  and reach no offender list. It adds the general principle: this predicate is a SCREEN,
  deliberately wider than the property, and narrowing a clause to exclude arithmetic is how a
  shape escapes.
- **Files modified:** `test/meta/web_phone_band_breakpoint_census_test.go`
- **Commit:** `9f301d043`

**2. [Rule 1 — Bug] The marker comments cross-referenced each other's tokens, inverting the slice**
- **Found during:** Task 3, first `task web:test` run
- **Issue:** the opening marker's prose contained the literal string `phone-band-overlay:end`
  ("slices the source between this marker and phone-band-overlay:end"). The test finds each
  marker by **first occurrence**, so `indexOf(endMarker)` matched the mention inside the
  *opening* comment, which sits before the real closing marker. The slice inverted.
- **Fix:** neither marker comment now spells the other's token; they refer to "its closing
  counterpart" / "the opening marker at the top of this block". The constraint and its reason
  are written into the opening marker comment so a future editor meets it.
- **Notable:** this was caught by the **new order precondition** this very task added
  (`expect(to).toBeGreaterThan(from)`), which is the property it exists to enforce. Under the
  pre-task `indexOf` bind the same mistake would have been impossible to make and equally
  impossible to detect.
- **Files modified:** `web/src/lib/components/admin/CharacterTable.svelte`
- **Commit:** `e8857775a`

**3. [Rule 3 — Blocking] Marker placement widened from the plan's literal wording, to avoid narrowing an assertion**
- **Found during:** Task 3
- **Issue:** the plan says to place the markers "immediately around the row/cell containing-block
  declarations". Read literally — bracketing only `:global(.charrow) { position: relative }` —
  the slice would exclude the `cell-created`/`cell-ver` rules that the surviving assertion
  `expect(selector).not.toMatch(/\btd\b|cell/)` scans. That is a **reduction** in the
  assertion's reach, which `prohibitions[0]` forbids.
- **Fix:** the markers bracket the whole media-block interior — the exact span the pre-task
  brace walk captured — so the scan's reach is byte-for-byte preserved and only the *binding
  mechanism* changed. The closing marker's comment says that a rule added below it is outside
  the slice.
- **Files modified:** `web/src/lib/components/admin/CharacterTable.svelte`, `…/CharacterTable.svelte.test.ts`
- **Commit:** `e8857775a`

**4. [Rule 3 — Blocking] Slice taken between the marker COMMENTS, not the marker STRINGS**
- **Found during:** Task 3
- **Issue:** slicing from the marker string leaves the marker's own prose inside the scanned
  text (its opening `/*` is before the slice start, so the comment-stripping pass cannot
  remove it). The `relativeRules` regex captures whatever precedes a `{`, so a future edit
  adding the word "cell" to a marker comment could be captured as part of a selector and fail
  the assertion for a reason having nothing to do with CSS.
- **Fix:** the slice runs from the opening comment's `*/` to the closing comment's `/*`, with
  both offsets asserted. The scanned text is now CSS only.
- **Files modified:** `web/src/lib/components/admin/CharacterTable.svelte.test.ts`
- **Commit:** `e8857775a`

**5. [Process] A `git checkout --` during a RED proof reverted an entire in-progress file**
- **Found during:** Task 1, reverting the depth-0 mutation
- **Issue:** `git checkout -- test/meta/web_phone_band_breakpoint_census_test.go` reverts to
  HEAD, not to the pre-mutation state, so it discarded all uncommitted Task 1 work along with
  the two-line mutation. No committed work was lost and the RED proof itself had already
  completed successfully (exit 201).
- **Fix:** the edits were re-applied identically and re-verified (203 tests, exit 0). Every
  subsequent mutation/revert used a targeted `python3` replace or a `cp` from a saved copy.
- **Recorded here** because the same reflex is a genuine hazard for any future guard-hardening
  round, where the file under mutation *is* the file being written.

No architectural deviation (Rule 4) arose. No guard was weakened, narrowed or deleted to make
anything pass; where the plan's literal wording would have narrowed one, the deviation is
documented above.
