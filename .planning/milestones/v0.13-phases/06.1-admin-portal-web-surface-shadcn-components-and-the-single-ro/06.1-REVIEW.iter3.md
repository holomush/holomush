## Warnings

### WR-01: The completeness equality preempts the offender assertion, so a hand-written breakpoint now reports as a missing census entry and instructs the reader to enumerate it *(NEW — introduced by fix `ae6cf171b`)*

**File:** `test/meta/web_phone_band_breakpoint_census_test.go:539` (equality), `:554` (offenders)

**Issue:** The WR-07 repair converted the anti-vacuity floor into
`require.Equal(ruleCensusOccurrences+allowlistLines, bandRelevant)` and placed it **before**
`require.Empty(t, offenders, …)`. But a hand-written breakpoint line increments
`bandRelevant` too (`:402-405`: `forbidden || carries the token` → `bandRelevant++`), so it
breaks the equality as well as populating `offenders` — and the equality fires first.

Measured. Injecting `@media (max-width: 767px)` into `AdminNav.svelte` — the exact defect
this test is *named* for (`TestNoAuthoredViewportRuleCarriesAHandWrittenBreakpointLiteral`)
— fails at `:539` with:

```
expected: 18   actual: 19
MORE reached than claimed: a banded rule exists that is NOT enumerated in
bandedViewportRules … Enumerate it.
```

The offender message at `:554`, which carries the correct instruction — *"A viewport width
written by hand is a copy of a Tailwind default that nothing keeps in step. Derive it:
`@media (width < theme(--breakpoint-md))` …"* — is never reached. The instruction the
operator actually receives is the opposite of the fix: a reader who obeys it adds
`{"…/AdminNav.svelte", "@media (max-width: 767px)", 1}` to the census, which satisfies the
equality *and* the sibling's occurrence count, and only then surfaces the real cause. The
census has just told them to enumerate the thing it exists to forbid.

This is a strict regression in diagnosis introduced by the repair: under the previous floor
(`19 >= 16`) the equality did not fire at all and `offenders` reported first, correctly.
The fixer reasoned about ordering relative to the allowlist staleness loop and got that
right; ordering relative to the offender list was not considered.

**Fix:** make the two comparisons orthogonal so each reports its own cause. Either report
offenders first —

```go
require.Empty(t, offenders, /* unchanged message */)

// …then the completeness equality, which is now a statement about a corpus with
// no hand-written lines in it.
require.Equal(t, ruleCensusOccurrences+allowlistLines, bandRelevant, …)
```

— or, keeping the current order, exclude offenders from the measured side and say so:

```go
// An OFFENDER line is band-relevant but is not a census rule and not an
// allowlist hit; it has its own assertion below, so it is excluded here rather
// than reported as a missing census entry.
require.Equal(t, ruleCensusOccurrences+allowlistLines, bandRelevant-len(offenders), …)
```

Whichever is chosen, add a mutation to the file's own RED-proof list: inject
`@media (max-width: 767px)` and confirm the failure names the hand-written width, not the
census.
