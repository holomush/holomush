## What the table actually does

### Sorting, and the shape that is not there

Five headers carry a real `<button>` under a `<th aria-sort>`; the sorted one shows `▲`/`▼` as well as the accent. `Ver` has neither. There is **no sort dropdown and no facet panel** — §11.3 names a control whose options are drawn from the field list as *the* warning sign, because the field list is the privacy-bearing set. The one `select` on the surface filters `status`, and it is the only control on the page that opens a list at all (`rg '[aria-haspopup]'` over the filter bar → exactly 1).

### The client renders the server's order, index for index

`{#each rows as row (row.id)}` and nothing else. The row-order case feeds a deliberately unsorted array containing **two rows with an equal sort key** (both never-active), so the three-clause server ordering's tiebreak is exercised rather than assumed. Adding `[...rows].sort((a, b) => a.name.localeCompare(b.name))` inverts it:

```
AssertionError: expected [ 'c2', 'c1', 'c3' ] to deeply equal [ 'c3', 'c1', 'c2' ]
```

`rg '\.sort\(|toSorted|localeCompare'` over the component returns **0**.

### The phone-band row target, and the proof that can exist

A `<tr>` cannot become a `<button>` and a `<button>` cannot contain `<td>`s, so the row target is a **primary-cell button with a row-spanning `::after`**: the `Name` cell holds a real `<button type="button">` carrying the row's full accessible name, and inside `@media (max-width: 767px)` its `::after { position: absolute; inset: 0 }` extends the hit area across the row. The `<tr>` takes no handler, no `role` and no `tabindex` — all three asserted.

**The containing block is the `<tr>`, asserted on the stylesheet.** The computed-style assertion that cycle 2 asked for is deliberately absent and must not be reintroduced: the rule lives inside a `max-width: 767px` media query, both Vitest projects run jsdom (`web/vite.config.ts:9`), and `getComputedStyle(tr).position` reads `static` whether the CSS is right or wrong — the mandated "move it onto the `<td>` → FAIL" demonstration fails *identically before and after*. The test instead parses the media block by brace balance, strips comments, and requires every `position: relative` selector inside it to be a row selector and none to be a cell selector. Moving it back onto the cell:

```
AssertionError: expected ':global(.charrow .cell-name)' not to match /\btd\b|cell/
```

The genuine span proof is browser-level and is 06.1-04's 375px tap on a **non-Name** cell.

**Why the test asserts `onedit` and not "the Sheet opened":** this component owns presentation only, and `EditCharacterSheet.svelte` is 06.1-04's artifact — it does not exist yet. A mock of it would prove nothing.

**On keyboard activation.** jsdom implements no keyboard-activation default for `<button>`, so dispatching `keydown{Enter}` fires no click there. The test asserts the two things that *are* observable and that *are* the property: the control is a real `<button type="button">` (which is exactly what grants Enter/Space in a browser), it takes focus, and activating it calls `onedit` with the row id.

### The two vocabularies stay apart

`status` is muted text carrying the word. No session badge, no presence dot, no colour-coded status, no `--color-status-online`. Asserted both as a scoped `rg` (0) and as a negative match over the rendered output for a mixed active/retired pair.

## `Last active`, and why a second formatter is correct

**Prior art was searched and two helpers were found**, both rejected on the merits rather than overlooked:

| Existing | Why it cannot serve |
|---|---|
| `SceneContextRail.svelte:34-43` `formatRelativeTime` | private to the component; takes epoch **milliseconds**; buckets are `just now` / `{n}m ago` / `{n}h ago` / `{n}d ago` — minute granularity, no month or year band; `0` renders the empty string, not `never`; no injectable clock |
| `SceneBoardRow.svelte:22-31` `relativeTime` | the same shape again, with a different `just now` threshold — already two drifting copies before this plan |

This column is epoch **nanoseconds** (INV-STORE-1), its `0` is a **sentinel meaning absence** rather than a falsy age, and its six buckets are fixed by the UI contract. Reusing either would have changed the rendered vocabulary and silently dropped `never`. The new formatter is the first with an injectable clock and the first with a boundary-tested bucket table.

**The absolute instant is unreachable at the call site.** `formatLastActive` returns a `string` and nothing else — no second return value, no companion export, no field a caller could put in a `title`. That is what enforces AR-03-03's "coarse because the value lags", rather than trusting every caller to decline a precise stamp they were handed.

## The search wire, and what the client does not claim

The box sends **the raw typed string**, after 250ms of quiet, with **no minimum-length gate**. A fullwidth-plus-whitespace term (`  Ｍｉrén  `) arrives byte-identical at the RPC. The client therefore makes **no claim about which strings are equal** — not case, not width, not composition — and renders no copy asserting one. Emptying the box returns to the list RPC rather than searching for `''`.

## The four list states

| State | Discriminator | Copy | Action |
|---|---|---|---|
| loading | `loading` | skeleton rows at the full column count inside `role="status"` labelled `Loading characters…` | — |
| load failure | `failure === 'load'` | `Couldn't load characters. Try again.` | `Try again` |
| search failure | `failure === 'search'` | `Couldn't run that search. Try again.` | `Try again` |
| no results | zero rows **and a filter applied** | `No characters match those filters.` / `Try a different search or clear the status filter.` | `Clear filters` |
| zero characters | zero rows **and no filter** | `No characters yet.` / `Characters appear here once players create them.` | **none** |

**The discriminator is whether a filter is applied, not the row count**, which is `0` in both. Forcing the no-results branch off fails **four** cases at once, which is the pair of states showing up in the test output rather than being argued:

```
× renders the no-results state with a Clear filters action
× discriminates the two empty states on whether a filter is applied, not the count
× makes no existence claim in the no-results copy
× clears the filters back to the unfiltered page
```

**The no-results copy makes no existence claim, and that hedge is grounded rather than stylistic.** **#4972 is open**: `AdminSearchCharacters` binds a charname-normalized term against the **verbatim** `players.username` column, so a non-ASCII username silently returns an **empty 200** with no error. **This state is currently reachable BY DEFECT as well as by data**, and the client cannot distinguish the two — so it must not, and does not, upgrade the render into a claim it has no grounds for. A verifier reading a green empty-state test must not read it as evidence that the search works. The server fix is out of this phase's scope and was not attempted.

**No server-supplied string reaches the screen.** The `catch` block **does not bind the caught value at all** — there is nothing the page may learn from it and nothing it may show. A thrown error carrying `DENY_ADMIN_SECTION: pg_trgm index missing on characters.normalized_name` renders neither token.

## Pagination

Page size **50**, and it is a **request**: the core clamps it (`adminportal.proto:282-286`, `:321-322`), so the rendered range is computed from what came back. `total_count` is the server's own scalar COUNT over the filter (`:294-302`, `:341-344`) and the client derives nothing — a case renders `1–50 of 412` from a 50-row page, which a client-side count could not produce.

| `totalCount` | Control |
|---|---|
| 0 | **not rendered** |
| 50 | **not rendered** (a single-page pager is chrome with no function) |
| 51 | rendered, with `1–50 of 51` |
| 51, page 2 | `51–51 of 51` — the end clamped to the total, not to `start + pageSize - 1` |

Relaxing the predicate from `>` to `>=` fails the 50 case alone — the boundary, at the value and one step either side, rather than a band assertion.

The non-precedent note travels with the type: `CharacterPage.totalCount`'s doc block states that a total is safe on this surface **and only here**, and MUST NOT be cited as precedent for a count on the public character directory.
