# Phase 06.1 Plan 07: Phone-band unit repair (G-06.1-2) Summary

Both halves of the phone band now resolve against one reference — the CSS rules were
already `rem` via `theme(--breakpoint-md)` and `DESKTOP_MEDIA_QUERY` is now `48rem` too —
and a Playwright project running Chromium at a 20px root font size proves it in a real
browser against the token read off `:root`, which is the one axis every earlier proof in
this phase was blind to.

## What was built

**Task 1 — the census, repaired before the constant moved (`aba47f31e`).**
`test/meta/web_phone_band_breakpoint_census_test.go` gained `48rem`/`64rem` in
`forbiddenViewportWidths`; its allowlist values became a `breakpointExemption{symbol,
reason}` so a forbidden width on a line NOT carrying `DESKTOP_MEDIA_QUERY` is an ordinary
offender even inside an allowlisted file; and its staleness assertion now checks the file
still declares the exempted symbol and counts only symbol-carrying hits. The false
exemption rationale — that Tailwind "compiles the token away" and the JS side "provably
cannot read" it — was deleted and replaced with the true one (SSR and jsdom have no
stylesheet to read; the literal is pinned by the browser proof). The order matters: the
census had to be correct *before* the constant changed, and this split leaves both commits
green.

**Task 2 — the tracer: one unit, proved end to end (`85d6c89d2`).**
`DESKTOP_MEDIA_QUERY` became `'(min-width: 48rem)'`. A new `chromium-large-font` Playwright
project launches with `--blink-settings=defaultFontSize=20`, scoped by `testMatch`, with the
existing `chromium` project taking the matching `testIgnore`. Neither project carries a
project-level `grep`/`grepInvert`, so the config-level quarantine filter is not shadowed.
`web/e2e/admin-band-root-font.spec.ts` asserts the 20px root font in page FIRST, then that
`matchMedia(DESKTOP_MEDIA_QUERY)` equals the token form at eight widths and equals the
negation of `(width < token)`, then that the admin rail, the `.adminnav-col` and the Sheet's
`data-side` all take the phone branch at 900px and all flip together at 1000px.
`signInAsAdmin`, `gotoAdminCharacters`, `rowFor` and `sheet` moved verbatim into
`web/e2e/helpers/admin.ts`.

**Task 3 — the false claims retired (`d2fc73224`).**
`EditCharacterSheet.svelte`'s "exact complement … at EVERY width" paragraph was rewritten to
state what is true and why, naming the browser proof. `ScenesShell.svelte` records that its
`md:` utilities and `isDesktop()` now share a reference and that the pairing was a live
px/rem split until this plan. `06.1-05-SUMMARY.md` received an append-only `## Erratum`.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 3 — Blocking] `//nolint:gosec` on the new `os.ReadFile` was rejected by nolintlint**
- **Found during:** Task 1, `task lint`
- **Issue:** the staleness assertion's new `os.ReadFile(abs)` copied the walk body's
  `//nolint:gosec` directive, but gosec does not flag an allowlist-derived path, so
  nolintlint failed the build with "directive is unused for linter gosec".
- **Fix:** removed the directive rather than widening `.golangci.yaml`.
- **Files modified:** `test/meta/web_phone_band_breakpoint_census_test.go`
- **Commit:** `aba47f31e`

**2. [Rule 1 — Bug] A fourth false claim, in the census's own doc comment**
- **Found during:** Task 1
- **Issue:** the plan named three sites of the "Tailwind compiles the token away" fiction.
  A fourth sat in `TestNoAuthoredViewportRuleCarriesAHandWrittenBreakpointLiteral`'s
  "What this census does NOT cover" paragraph: "it cannot tie … DESKTOP_MEDIA_QUERY to a
  token the build compiles away". Leaving it would have preserved the exact sentence the
  gap says will be re-cited and the defect re-derived.
- **Fix:** rewritten to say the tie is the browser proof's job, naming
  `web/e2e/admin-band-root-font.spec.ts`.
- **Files modified:** `test/meta/web_phone_band_breakpoint_census_test.go`
- **Commit:** `aba47f31e`

**3. [Rule 3 — Blocking] `web/e2e/helpers/admin.ts` re-exports the fixture `test`**
- **Found during:** Task 2
- **Issue:** the plan specified moving four symbols. A spec importing only those four would
  still have to import `test`/`expect` from `./helpers/fixtures` separately, and importing
  the bare `test` from `@playwright/test` instead is a silent way to lose the database
  fixtures `signInAsAdmin` depends on.
- **Fix:** the helper module re-exports `test`, `expect`, `db`, `registerPlayer`,
  `createCharacter` from `./fixtures`, with a comment saying why. `db` was also dropped from
  `admin-portal.spec.ts`'s import list, where it became unused after the move.
- **Files modified:** `web/e2e/helpers/admin.ts`, `web/e2e/admin-portal.spec.ts`
- **Commit:** `85d6c89d2`

**4. [Rule 3 — Blocking] Two acceptance greps were unsatisfiable as first written**
- **Found during:** Task 2
- **Issue:** the plan requires `rg -c 'expect.poll'` ≥ 1 and `rg -c 'waitForTimeout'` = 0.
  The first draft split each poll across lines as `await expect\n  .poll(...)`, so the
  line-scoped grep counted 0; and the helper's doc comment used the word `waitForTimeout`
  in prose, so the second counted 1. Both greps are line-scoped, and both were measuring
  the property the plan intended.
- **Fix:** each poll was collapsed onto one line (message strings hoisted to named consts,
  which also gives a failure the column it names), and the prose says "a fixed wall-clock
  sleep". The web tree has no prettier — `dprint.json` covers only JSON and TOML — so the
  one-line form is stable under `task fmt`.
- **Files modified:** `web/e2e/admin-band-root-font.spec.ts`
- **Commit:** `85d6c89d2`

**5. [Rule 3 — Blocking] Module-scope `expect()` replaced with a plain throw**
- **Found during:** Task 2
- **Issue:** the plan says to assert the `DESKTOP_MEDIA_QUERY` parse succeeded before using
  it. That parse runs at module load, where no test exists to attribute a Playwright
  assertion to.
- **Fix:** `readDesktopMediaQuery` throws with the same message. A thrown error at module
  load fails the file loudly, which is the property the plan wanted.
- **Files modified:** `web/e2e/admin-band-root-font.spec.ts`
- **Commit:** `85d6c89d2`
