# Phase 02.1: World Caller Model - Context

**Gathered:** 2026-08-08
**Status:** Ready for planning (research pre-approved — see Open Questions)

<domain>
## Phase Boundary

`world.Service`'s 21 public commands take a **typed caller value** instead of a bare
`subjectID string`, so caller identity and the execution context it acts under travel together and
cannot be supplied half-way. `checkAccess` forwards that context to `types.NewAccessRequest`,
deleting the hardcoded `nil` at `internal/world/service.go:214`. The 47 production call sites and
347 test call sites migrate with **identical authorization outcomes** (existing suites pass without
assertion changes), and `internal/grpc/location_follow.go:197` — the single production
`access.WithSystemSubject` site — becomes an explicit `SystemCaller`.

**In scope:** the caller type + constructors (`HumanCaller`, `SystemCaller`), the 21-signature
flip, the 3 lockstep interfaces (`internal/world/mutator.go`, `internal/command/types.go`,
`internal/grpc/server.go`) + mockery regeneration, the `checkAccess` seam, the criterion-2 proof
that a world write can reach the DSL as `action.*`, and the registry invariant pinning the
guarantee (D-65).

**Out of scope:** `JobCaller` and all job vocabulary (Phase 02.2, per D-62 below); registering the
`action` namespace in the schema registry (02.2's D-59, which requires the repo-wide `action.*`
audit first — 02.1 MUST NOT flip that switch); retiring `access.WithSystemSubject` (deferred
cleanup, no phase); the job registry/provider/seeds (02.2).

</domain>

### JobCaller scope

- **D-62:** **`JobCaller` is deferred to Phase 02.2.** 02.1 ships `HumanCaller(subjectID)` and
  `SystemCaller()` only. The caller type carries its **internal attribute channel from day one**
  (checkAccess consumes it in 02.1), designed so 02.2 adds `JobCaller` as a **purely additive
  constructor** — no change to the 21 signatures, the interfaces, or the `checkAccess` seam.
  Rationale: `JobCaller(name, provenance)`'s provenance parameter is exactly the vocabulary 02.2
  has NOT settled (its open question 1: timer-driven jobs have no triggering event, so the D-54
  triple cannot be universal), and that question is marked "do not let a planner pick one
  silently." Shipping a provisional shape would either be stringly-typed (the shape D-57 rejected)
  or would force 02.2's decision in the wrong phase. ROADMAP §02.1 Shape line amended accordingly.
  **Planner constraint:** no production-reachable path may construct a caller with arbitrary
  attributes in 02.1 — constructors are the only public construction path; the criterion-2 proof
  test populates attributes via package-internal construction (exact mechanism is Claude's
  discretion).

### Landing & review strategy

- **D-63:** The 347-site test migration is executed by an **ast-grep codemod whose rule is
  committed as a repo artifact** (under `scripts/`, with a documented re-run command). The
  reviewer verifies the bulk diff mechanically — re-running the rule against the pre-flip tree
  reproduces the committed diff (re-run → empty diff) — instead of reading 347 hunks; the rule is
  reusable if new call sites appear on rebase.
- **D-64:** **Single PR** through the normal `/gsd-ship` flow. Branch commit sequence keeps every
  commit green (`task lint` + `task test` per commit): **(1)** additive caller type + constructors
  (no consumers), **(2)** the atomic flip — 21 signatures + 3 interfaces + 47 prod sites
  (including `location_follow.go:197` → `SystemCaller`) + 347-site codemod + mockery regen in one
  commit, **(3)** criterion-2 proof test, invariant binding, cleanups. The flip commit is
  irreducibly large because criterion 1 forbids any overload/variadic escape hatch that would
  allow an incremental migration; the review story is the commit structure + D-63's mechanical
  verification, not diff size.

### Invariant registry

- **D-65:** **Mint and bind a registry invariant in-phase** — `INV-WORLD-<next free N>`: every
  public `world.Service` command takes the typed caller value (no bare subject-string parameter),
  and `checkAccess` forwards the caller's execution context (never a hardcoded-`nil` attribute
  channel). Bound (`binding: bound`, not pending) by a **census-style go/ast test** in the mold of
  `internal/world/world_envelope_census_test.go:187-207`, asserting every public `Service` method's
  caller slot is the caller type — this is what catches a future 22nd method regressing to
  `subjectID string`, which the compiler would happily accept. The summary MUST NOT claim more
  than the binding proves (the INV-WORLD-6 lesson). Because a GSD phase doc is outside the
  registry's orphan-check walk root, the id MUST be **hand-registered** in
  `docs/architecture/invariants.yaml` + `go run ./cmd/inv-render` in the same change.

## Open Questions — for the researcher; MUST NOT be invented by a planner

1. **`SystemCaller()` vs the S1 defense (the phase's flagged unknown).** `engine.go:92-101`
   requires **both** `req.Subject == "system"` (bare literal) **and** `access.IsSystemContext(ctx)`;
   a bare `"system"` subject without the marker is a hard `SYSTEM_SUBJECT_REJECTED`. So a caller
   *value* must influence the *context* — candidate shapes: `checkAccess` (or the caller's
   accessor) derives/stamps the context internally when the caller is system-kind, vs. call sites
   continuing to wrap ctx themselves (which would defeat criterion 4's point). Researcher verifies
   the mechanism and its interaction with `WithSystemSubject`'s total-bypass semantics
   (`context.go:10-18` — behavior must stay identical per criterion 3).

   > **✅ RESOLVED 2026-08-16 by the phase's own execution.** The mechanism is
   > `checkAccess` deriving the context internally: `service.go:234` calls
   > `s.engine.Evaluate(caller.evalContext(ctx), req)`, and `evalContext`
   > (`caller.go:100-105`) returns the input unchanged for a non-system caller and a
   > system-marked derivation otherwise — so the caller *value* influences the
   > *context* without any call site wrapping ctx itself, which is what criterion 4
   > required. Adjudicated in `02.1-VERIFICATION.md` rows **R4**, **P1**, **P3** (all
   > ✓ VERIFIED). Behavioural proof:
   > `TestWorldServiceSystemCallerSatisfiesTheS1GateWithoutAmbientContext` — the
   > positive half passes with a plain `context.Background()`, the negative half
   > asserts `HumanCaller("system")` is rejected with `SYSTEM_SUBJECT_REJECTED`.
   > Non-mutation is separately pinned by
   > `TestSystemCallerStampsTheSystemMarkerOnlyOnTheDerivedContext`.
2. **Subject string formats at the 47 production sites.** What exactly flows as `subjectID` today
   (bare ULID vs `character:<id>`-prefixed, per site)? `HumanCaller` must preserve each site's
   string byte-identically for criterion 3.

   > **✅ RESOLVED 2026-08-16 by the phase's own execution.** Byte-identity holds and is
   > mechanically detected, not reviewed by eye: `02.1-VERIFICATION.md` row **P6**
   > (✓ VERIFIED, behavioural) records that `buildIntent` receives the subject verbatim
   > at all 10 mutation sites, with
   > `TestWorldCallerSubjectReachesTheOutboxActorByteForByte`
   > (`internal/world/outbox_actor_test.go`) asserting `require.Equal` on raw Go strings
   > across four subject shapes — `character:…`, `plugin:core-scenes`,
   > `system:bootstrap`, and bare `system` — against both `intent.Actor` and
   > `moveIntent.Actor`.
3. **Where `action.dispatch_location` attributes are supplied today** (`seed.go:332` references it;
   some engine caller outside `world.Service` passes it) — confirm 02.1's flip changes nothing on
   that path.

   > **✅ RESOLVED 2026-08-09 by Phase 02.2's D-59 audit.**
   > `02.2-ACTION-AUDIT.md` row 2 maps the key end to end: shipped seed
   > `internal/access/policy/seed.go:332` (`seed:plugin-world-mutation-own-location`,
   > INV-PLUGIN-50/52); producer `internal/plugin/hostcap/interceptor.go:294` →
   > `internal/plugin/pluginauthz/capability.go:50`; tests at
   > `seed_smoke_test.go:976,998`, `interceptor_test.go:120`, and both
   > `dispatch_propagation_test.go` sites. The supplier is the plugin host interceptor,
   > **not** `world.Service`, so 02.1's flip does not touch that path. Verdict: DECLARE.
