## Deviations from Plan

### 1. [Rule 1 - Bug] The committed decl rules and the census probe were position-blind; the flip made it destructive

**Found during:** Task 3, the D-63 re-run gate.

**Issue.** Re-running `world-caller-decl.yml` against the migrated tree produced
**8 hunks**, each rewriting `_ string` → `_ world.Caller` on the **`name` parameter**
of `FindLocationByName` — a **build-breaking** rewrite, and a direct violation of the
D-63 review contract. The census probe had the same defect, reporting **16** instead
of the pinned **8**.

**Root cause.** All three rules constrain the parameter name to `^(subjectID|subject|_)$`,
which admits the blank identifier, and none constrained the parameter *position*. They
therefore matched a blank-named `string` parameter **anywhere** in a world command's
signature. Pre-flip this was **masked**, which is why no Plan 01 measurement could have
caught it: `FindLocationByName(ctx, _, _ string)` is a *single* grouped
`parameter_declaration` excluded by `not: {regex: ','}`. Migrating the grouped form
necessarily **splits** it into `_ world.Caller, _ string`, and the surviving trailing
parameter is newly visible.

**Why the probe's 16 was not an unmigrated site.** The arithmetic reconciles exactly:
16 = 8 façades + 8 residuals, and those 8 residuals are precisely the 8 in-scope grouped
`FindLocationByName` declarations migrated in this plan (7 `_, _ string` + `hostcap/world_test.go:84`'s
`subjectID, _ string`). All 8 were confirmed by inspection to be the `name` parameter,
which is legitimately a string. The underlying invariant was proven independently with an
ad-hoc positional probe before any rule was touched: **8 matches, all façades**.

**Fix.** Added a one-line `nthChild: 2` positional fence to `world-caller-decl.yml`,
`world-caller-decl-internal.yml`, and `probe-subject-param.yml`, with the rationale
recorded in each rule header and in a new README § 3. This is the remedy Task 3's action
mandates — *"fix the rule's constraints rather than the file, because the rule is the
committed review artifact"* — rather than the README's older `ignores:`-first advice,
which would have blinded the rules to real targets in the same files. The README's
standing-remedy section was reordered accordingly.

**Verified against a two-direction fixture** before adoption: all three pre-flip
subject-at-position-2 shapes (`subjectID string`, `subject string`, `_ string`) are still
rewritten; no position-3 parameter is touched. Post-fix, all four rewrite rules re-run to
**0 hunks** and the probe reads exactly **8**.

**Files:** the three rule files + `scripts/codemod/README.md`. **Commit:** `1a25bd6c2`.

### 2. [Rule 3 - Blocking] Eight more assertions hit the D-62 collision Wave 1 resolved

**Found during:** Tasks 1 and 3, successive compiles.

**Issue.** Test doubles that captured a subject **string** from a parameter that is now an
opaque `Caller` cannot compile, and — because D-62 forbids an exported accessor — cannot
render the subject back out. This is the genuine collision between two plan prohibitions
that Wave 1 recorded as its deviation 3.

**Fix.** Followed Wave 1's precedent exactly, resolving in favour of the security
prohibition: capture a `world.Caller` and compare against `world.HumanCaller("<same
literal>")` — same expected subject, same behaviour under test, expressed at the new type.
No accessor was minted. Sites:

- `hostfunc/adapter_test.go` — the three assertions Wave 1 explicitly deferred (`:175`,
  `:234`, `:302`). `capturedSubjectID` is now retired entirely; all four methods record
  into the `capturedCaller` field Wave 1 introduced.
- `hostcap/world_test.go` — four `fakeMutator` capture fields (`lastFindSubject`,
  `lastCreateLocSubject`, `lastCreateExitSubject`, `lastCreateObjSubject`) and their four
  assertions.
- `hostfunc/world_write_test.go` — one local `capturedSubjectID` and its assertion.

`internal/plugin/objects_integration_test.go`'s `lastSubjectID` needed **no** assertion
change: the field is write-only, so only its type moved.

**Assertion-immutability measurement (against `BASE=89eb4330c`).** The plan's criterion
command returns **28** lines (14 pairs), which splits into two classes:

| Class | Pairs | What moved |
|---|---|---|
| call-shape only, inside `require.NoError(t, <call>)` | 6 | the *call expression* nested in the assertion — `MoveCharacter`, `SetName`, `SetDescription`. The assertion itself is unchanged; the criterion's regex catches these because the call is inline. These are exactly the rewrites the plan mandates. |
| genuine assertion-expression changes | 8 | the D-62 resolution above — `assert.Equal(t, "plugin:X", …)` → `assert.Equal(t, world.HumanCaller("plugin:X"), …)` |

Excluding the `NoError` class, the count is **16** lines = the 8 genuine pairs. No
assertion's *meaning* changed, no test case was renamed, and
`TestWorldService_MalformedAccessParams` retains all nine subtests with names untouched.

## Criterion-wording defects found (no migration impact)

Recording them so Plan 03 does not read them as failures.

1. **`rg -n 'subjectID' <the ten Task-1 files> | wc -l` returns 0.** Unsatisfiable. The
   committed declaration rules deliberately **keep the parameter name** (`fix: '$NAME
   world.Caller'`), which the README documents as intentional. Measured: pre-flip 56 →
   post-flip **54**, the delta being exactly the two prose doc-comment lines the plan
   names — both restated in terms of the caller value, not merely deleted. Of the surviving
   54, **0** is typed `string` and **0** is prose. The plan says elsewhere, correctly,
   *"the identifier is not the invariant; the parameter type is."*

   **2** on a correct tree: the regex cannot distinguish position 4 from position 5, and
   both hits are `_ world.Caller, _ string` where the `_ string` is `entityType`. Direct
   positional check: all **4** `Definition.Set` declarations carry `Caller` at position 4.

3. **`rg -n 'SystemCaller\(\)' --glob '!*_test.go' internal/ cmd/` returns exactly the two
   `location_follow.go` lines.** Returns 4: the two call sites plus a doc comment at
   `location_follow.go:189` and the constructor's own declaration at `caller.go:88`. The
   substance — exactly two production system-caller *call sites* — holds.
