## Deviations from Plan

### 1. [Rule 3 - Blocking] `caller_test.go` is `package world_test`, not `package world`

**Found during:** Task 1, writing the criterion-2 proof.

**Issue:** the plan requires the criterion-2/4 proofs to sit in `internal/world/caller_test.go`
declared `package world`, so the attribute-carrying caller can be built by same-package
composite literal. That is **unsatisfiable**. The proofs must drive a real `policy.Engine`;
`policy.NewEngine`'s first parameter is a concrete `*attribute.Resolver`; and
`internal/access/policy/attribute` imports `internal/world`
(`attribute/character.go:12`, `attribute/property.go:13`). Go rejects it:
`import cycle not allowed in test`. Verified with
`go list -deps .../policy/attribute | rg -x '.../internal/world'`.

**Fix:** the whole file became `package world_test` (external test packages are exempt from the
cycle — which is why `service_test.go` is already `package world_test`), plus a new
`internal/world/export_test.go` (`package world`) bridging `Caller`'s unexported state.

**Why this does not weaken D-62:** symbols in a `_test.go` file compile only into package
world's own test binary. No production code and no other package's non-test build can reach
`NewCallerWithAttrsForTest`. `world.Caller` still has unexported fields, exactly two exported
constructors (neither populating `attrs`), and zero exported accessors in `caller.go`. Keeping
all eight tests in the single referenced path preserves Plan 03's `INV-WORLD-8` `asserted_by`.

**Files:** `internal/world/caller_test.go`, `internal/world/export_test.go`. **Commit:** `8fd2916f5`.

### 2. [Rule 3 - Blocking] `internal/world/service_helpers_test.go` drives `checkAccess` directly

**Found during:** Task 1, first compile after the `checkAccess` signature change.

**Issue:** the plan's `read_first` states this file holds no tracer call site or declaration —
true — and it is absent from `files_modified`. But it calls the package-private
`svc.checkAccess(ctx, subject, …)` **12 times**, so the signature change breaks it.

**Fix:** wrapped all 12 in `HumanCaller(...)`. Call shapes only; zero assertions touched.

**Commit:** `8fd2916f5`.

### 3. [Rule 3 - Blocking] `adapter_test.go` cannot capture a subject string from a `Caller`

**Found during:** Task 1, second compile.

**Issue:** `mockWorldService.capturedSubjectID string` is assigned from the method's second
parameter. Once `GetLocation` takes a `world.Caller`, that assignment cannot compile, and the
external test package cannot render the subject back out — precisely because D-62 forbids an
exported accessor. This is a genuine collision between two plan prohibitions ("no exported
accessor" vs "MUST NOT change any existing test assertion").

**Fix:** resolved in favour of the security prohibition. Added a sibling
`capturedCaller world.Caller` field; `GetLocation` records into it; the single affected
assertion became
`assert.Equal(t, world.HumanCaller("plugin:test-plugin"), svc.capturedCaller)` — the same
expected subject literal, same behaviour under test, expressed at the new type. The other three
`capturedSubjectID` assertions (`:175`, `:234`, `:302`) are untouched because those methods have
not migrated yet.

**Commit:** `8fd2916f5`.

### 4. [Rule 3 - Blocking] ast-grep does not manage imports

**Issue:** `test/integration/resilience/restart_reconnect_test.go:79` was rewritten to

**Fix:** added the import. **Plan-02 relevance:** the committed rules will hit this again across
the bulk flip; it is now recorded in the codemod README's known-limitations framing via this

**Commit:** `8fd2916f5`.

### 5. [Rule 1 - Correctness] S1 negative assertion pins the inner oops code

**Found during:** Task 1, running the criterion-4 proof.

**Issue:** the negative half asserted `LOCATION_ACCESS_EVALUATION_FAILED`.
`errutil.AssertErrorCode` chain-walks, and the chain carries the engine's own
`SYSTEM_SUBJECT_REJECTED` inside that wrapper.

**Fix:** assert `SYSTEM_SUBJECT_REJECTED` — strictly more precise, and it names the S1 rejection
rather than the generic classification around it. New test, so no frozen assertion was altered.

### 6. [Rule 2 - Correctness] codemod `ignores:` corrected for the package change

**Found during:** post-flip verification.

**Issue:** the plan's per-rule ignore table places `internal/world/caller_test.go` on
`world-caller-arg2-internal.yml` *because it is `package world`*. Per deviation 1 it is
`package world_test`, so that ignore is inert and the **external** rule is the one that scans
the file.

**Fix:** added the live ignore to `world-caller-arg2.yml`, retained the internal one as
belt-and-braces (so moving the file back into `package world` cannot silently reintroduce the
double-wrap), and documented the reasoning in both rule headers and the README. Verified all
four committed rules emit zero hunks in that file either way. Basis-B emission is unaffected
(the file contributed zero matching hunks).

**Commit:** `8fd2916f5`.

## Measurement refinement (not a deviation)

The plan presents the `RECV` false-positive blocklist as load-bearing, with deltas
375 → 370 → 355. Those deltas reproduce **only with the `SUBJ` guard removed**. With the
three-clause `SUBJ` allowlist present, all three stages read 355: argument 2 at every one of the
20 excluded sites is spelled `charID` / `locID` / `characterID`, none of which is `subj`-ish, so
the allowlist already excludes them.

Both guards are retained as defence in depth and this is recorded in the README —
the `SUBJ` allowlist is the one whose complement may grow over time, and the `RECV` blocklist is
the one that stays true if the allowlist is ever widened. Neither is redundant against future
drift; they are merely redundant against *this* tree.
