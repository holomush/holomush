<objective>
Prove the phase's three user journeys against the real Docker stack through a real browser: a
logged-out visitor reading a public profile, a player creating a character through the
structured card, and a player managing their roster including which character is default.

Purpose: every other test in this phase runs in-process. The one property that cannot be proven
in-process is that a browser with **no cookie at all** reaches `/c/[id]` — the app has never
served an application path outside `(authed)`, and `landing.spec.ts` only visits `/`. The
combination this phase needs — create while signed in, then read from a fresh cookie-less
context — has no in-tree precedent, and it is exactly the combination PROFILE-01 promises.

Output: three Playwright specs built on the shipped fixtures and database helpers, adding no
new helper.
</objective>

text, and assert the two are equal. Build the unreachable case from the seeded corpus rather
than by mutating policy from a browser test. Assert also that the not-found text contains
neither the requested identifier nor any reason.
