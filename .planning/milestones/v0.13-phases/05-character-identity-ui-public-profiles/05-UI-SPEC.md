# Phase 5 — UI Design Contract

> Visual and interaction contract for the character identity surface: structured creation,
> multi-alt roster, owner authoring, and the public profile a logged-out visitor can read.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Upstream authority.** `05-CONTEXT.md` (D-84…D-98) and `01-SPEC.md` §7–§9 are normative and
already settle most of this phase. This document adds only the *visual and interaction*
contract on top of them. Where this document and CONTEXT/SPEC appear to disagree,
CONTEXT/SPEC wins and this document is the bug.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn-svelte (already initialized — `web/components.json`) |
| Preset | style `nova`, baseColor `slate`, aliases `$lib/components/ui` |
| Component library | `bits-ui` 2.x headless primitives (the Svelte analogue of radix) |
| Icon library | `@lucide/svelte` |
| Font | App chrome: `-apple-system, 'Inter', system-ui, sans-serif` (`app.css` `@layer base`). No new face. |
| Styling | Tailwind v4 utilities for layout/spacing + `var(--color-*)` custom properties for all color |

**Tailwind v4 gotcha (binding).** `@theme` compiles `var()` at **build time**. Never put a
`var()` reference inside `@theme` for a value that changes at runtime. All new color use
reads `var(--color-*)` in scoped CSS or the matching Tailwind utility (`bg-card`,
`text-muted-foreground`) — never a hardcoded hex. (`web/CLAUDE.md`.)

### Component inventory — **zero new shadcn components**

Already installed and sufficient: `badge`, `button`, `card`, `checkbox`, `input`, `label`,
`separator`, `textarea`, `tooltip` (plus `command`, `dialog`, `dropdown-menu`,
`input-group`, `popover`, `resizable`, `scroll-area`, `sheet` unused by this phase).

Explicitly **declined**, with reasons — the planner MUST NOT add these:

| Declined | Reason |
|----------|--------|
| `avatar` | The portrait is an initial letter rendered in pure CSS (007-C). In v0.13 no media row can exist, so it is *never* an image. An avatar primitive would exist only to render one styled letter. |
| `skeleton` | A field-shaped skeleton pre-announces a response shape the response may not have — on a surface whose whole constraint is that it may not signal how much it is withholding. Loading is one `role="status"` line (see Copywriting). |
| `sonner` / any toast library | The app ships **no toast infrastructure today** (verified: zero `toast`/`sonner` references under `web/src/` and `web/package.json`). See "Deliberate refinement of D-88" below. |
| `select` | Every one of the twelve `profile.*` fields is free text (§7.2). Nothing in this phase is an enumeration. |
| `field` | `label` + `input`/`textarea` + a scoped `<p>` error is what the shipped forms already do. A second form-composition idiom in the same codebase is the cost. |

**Deliberate refinement of D-88.** D-88 names "the toast and the new roster card" as the
post-submit echo sites. This contract keeps the *substance* (the created display name is
echoed in the success path) and changes the *vehicle*: a persistent inline `role="status"`
confirmation region on the roster, not a toast. Three reasons: (1) no toast infrastructure
exists, so a toast is a new runtime dependency for one string; (2) a toast that vanishes in
four seconds is a poor carrier for teaching that the server rewrote the player's name — the
one thing the echo exists to teach; (3) a persistent region is directly assertable by
Playwright and is announced by screen readers without a live-region race. The roster card
echo (D-88's second site) is unchanged.

## Spacing Scale

Declared values — all multiples of 4:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Fact-pill inner gap, badge inner gap |
| sm | 8px | Label-to-control gap, pill row gap, badge margin |
| md | 12px | Card grid gap, intra-card element gap (matches shipped `gap-3`) |
| lg | 16px | Card padding, section body padding, form-field vertical rhythm |
| xl | 24px | Between long-form profile sections; between authoring sections |
| 2xl | 32px | Page top padding; roster section-header top margin |
| 3xl | 48px | Page horizontal gutter at ≥768px |

**Exceptions (each justified, each a multiple of 4):**

| Exception | Value | Why |
|-----------|-------|-----|
| Profile portrait | 80×80px | The sketch's 78px rounded to the scale. Large enough that a single letter reads as deliberate identity rather than a favicon. |
| Roster card avatar | 44px | The shipped value (`w-11`), and the minimum comfortable touch target. Unchanged. |
| Interactive target floor | 44×44px | Every button, link-card and collapse chip has ≥44px of hit area, padding included, at every band. |
| Fact-pill vertical padding | 4px | `xs`. Pills are inline chrome, not blocks. |

**Rounded from the sketch corpus.** Sketch 007/008 CSS uses 18/13/11/9/6px. Those are
sketch values, not tokens. Every one is rounded to the nearest scale step above
(18→16 or 24 by context, 13→12, 11→12, 9→8, 6→4/8). The sketch CSS is a *shape* reference,
not a spacing reference.

## Typography

Exactly **4 sizes, 2 weights**.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 12px | 600 | 1.4 | Section headings (uppercase, `.06em` tracking), fact-pill labels, badges, meta lines, the byte counter |
| Body | 14px | 400 | 1.5 | All prose: description, the five long-form sections, form inputs, error and status copy, fact-pill values |
| Heading | 20px | 600 | 1.2 | The character name in the profile card; the `<h1>` on each page (matches the shipped roster `text-xl`) |
| Display | 32px | 600 | 1 | **The portrait initial letter only.** Nothing else in this phase uses it. |

Rules:

- **Two weights, full stop:** 400 and 600. The sketch's `font-weight: 700` on the portrait is
  pinned down to 600 — a lone 700 for one glyph is not worth a third weight.
- **No 11px, no 11.5px, no 10.5px.** The sketch's sub-12px sizes collapse into the 12px Label
  role. 12px at the declared contrast ratios (below) is the floor.
- Monospace (`JetBrains Mono`) is **terminal-only** and appears nowhere in this phase.
- The portrait letter is uppercased in CSS (`text-transform: uppercase`), never by mutating
  the name string — §8.8 guarantees a letter exists, not that it is uppercase.

**Accent reserved for — the complete list. Anything not on it is not accent:**

1. The portrait initial letter and its tinted plate
   (`color-mix(in srgb, var(--color-primary) 16%, transparent)` fill,
   `color-mix(… 32% …)` border, letter in `--color-primary`).
2. The focus ring on any input, button or link-card (`--color-ring`, same hex).
3. The primary submit button of each form section (`Create character`, and each section's own
   `Save …` button) — solid `--color-primary` on `--color-primary-foreground`.
4. The hover border on a clickable roster card (`border-color: var(--color-primary)`).
5. The `View public profile →` link on `/characters/[id]` and `View profile →` on a
   not-playable roster card.
6. The `Default` badge outline on the roster — the one once-per-roster marker.

**Not accent, explicitly:** section headings, fact pills, the session badge, the `Retired`
badge, the `Not playable` collapse chip, the sheet's empty section, the web-DM slot, the
not-found page, body prose.

**Portrait treatment is unified.** The shipped roster avatar uses a solid `bg-primary`
plate; 007-C's profile portrait uses the 16% tint. Phase 5 adopts the **tint everywhere**,
including on the shipped roster card. One treatment, and it lowers the total accent area.

**Amber is forbidden.** `--color-cursor` `#ffb300` is the **cursor only**
(`branding.md` INV-1). It MUST NOT appear as an accent, link, button, badge, status color,
warning color, or highlight anywhere in this phase. The not-retroactive notice in particular
is **not** a warning and takes muted text, not amber.

**No hardcoded brand string.** `HoloMUSH` MUST NOT appear in any copy written by this phase
(INV-6). `/c/[id]` is the first public, shareable, indexable page the platform ships; the
game's own display name is server-side-only (#4905, deferred). The one permitted "back"
target is the word `Home`.

**Contrast, computed against `--color-card` `#101418`:**

| Pair | Ratio | Verdict |
|------|-------|---------|
| `--color-foreground` `#e8edf2` | 15.0:1 | AAA |
| `--color-status-text` `#9aa7b2` | 7.5:1 | AAA for body, AA at 12px |
| `--color-primary` `#3dd6f7` | 10.7:1 | AAA |
| `--color-destructive` `#fc7f7f` | 7.5:1 | AAA |

Every text/background pair in this phase MUST come from that table or exceed 4.5:1. Color is
never the sole carrier of meaning: the `Retired` badge carries the word, the error region
carries an icon-free `role="alert"` and text, the `Default` badge carries the word.

## The Absence Contract (binding — this is the phase's hardest rule)

Apply D-94's discriminating test to every element before drawing it:

> **Does this element's presence or absence vary with who is looking?**
> **Yes** → absence rule: render nothing.
> **No** → named-slot rule: name the reserved capacity.

| Governed by | Rule |
|-------------|------|
| The twelve `profile.*` fields, the in-world description, the media rows | **Absent ⇒ render nothing.** No count, no lock icon, no greyed section, no dashed placeholder, no progress indicator, no "N hidden", no heading-without-body, no copy that varies with how much was withheld. |
| The empty sheet (PROFILE-02), the named web-DM slot (EXT-08) | **Name the reserved capacity.** Identical for every viewer at every tier; discloses only "the platform has not built this yet", which is public. |
| The owner-only `Edit` / `View public profile` affordance | Varies by viewer, but tells the owner they are the owner. Leaks nothing. Permitted. |

Hard consequences the executor must hold:

- **A profile carrying only name + pronouns is the native, complete rendering** — not a
  degraded one, and it carries **no empty-state copy of any kind**. It is reachable in a real
  configuration (the players-only posture) and MUST look deliberate there.
- **The gallery never renders in v0.13.** §7.3 ships the media model with zero upload
  behavior, so no media row can exist. Build the renderer; ship **no** "coming soon" slots.
- **No tier preview ships in this phase.** If one is ever built it MUST derive distinct
  outcomes from the live floor set — under seeded defaults `guest` and `player` render
  **identically** (no §8.6 row seeds `player`), so a hardcoded three-way toggle shows two
  identical panels.
- **Absence is a wire property, never a client filter** (§8.9). The client renders what
  arrived. It MUST NOT hold a list of expected fields and diff against it.

## Layout

### Responsive

**One breakpoint: 768px, expressed as a `@media` query.** Below it, single column and full
gutters collapse to `lg` (16px); at and above it, the content column is centered at
`max-width: 720px` (the shipped roster's value) with `3xl` (48px) gutters.

*Deviation from the sketch corpus, recorded.* Sketches 001/006/008 use container queries
(`@container vp`) because the admin portal is a three-column shell whose content column
resizes independently of the viewport. Phase 5 ships **no shell** — these are full-width
single-column pages under the root layout, where the content box and the viewport are the
same thing. Media queries are what ships today (`TopBar.svelte:200`,
`characters/+page.svelte`). Introducing a `vp` container solely to satisfy an idiom borrowed
from a surface that does not exist yet is inventing infrastructure. Phase 6 owns the
container-query frame.

### `/c/[id]` — the identity card (007-C)

```
[ card ]                        ← bordered, radius 12px, --color-card, lg padding
   [portrait 80px] [ name (Heading 20/600)          ]
                   [ pronouns (Body, muted)          ]   ← hard floor, §8.8
                   [ concept (Body)          if present]
   [ description (Body, pre-wrap)            if present]
   [ fact pills: species · age · faction · currently · timezone   each if present ]

[ section: Appearance    ]      ← xl (24px) below the card; heading ONLY if body present
[ section: Personality   ]
[ section: Biography     ]
[ section: Rumours & hooks ]    ← profile.rumors
[ section: Out of character ]   ← profile.rp_preferences (OOC — labelled so, last)

[ gallery ]                     ← renders only if media rows exist. In v0.13: never.

[ action bar ]                  ← the named web-DM slot (EXT-08)
[ section: Sheet ]              ← named empty section (PROFILE-02)
```

- The page body is **unpadded**; the card and each section carry their own margin, so
  sections *grow below* the card rather than sharing a document flow with it. That is the
  structural mechanism by which the sparse view reads as complete.
- Field → slot mapping is fixed: short single-line fields (`species`, `age`, `faction`,
  `currently`, `timezone`) are **fact pills**; `pronouns` and `concept` live in the card
  head; long multi-paragraph fields (`appearance`, `personality`, `biography`, `rumors`,
  `rp_preferences`) are **sections below the card**. This matches §7.2's short/long column.
- `profile.rp_preferences` is **out-of-character** text about the player. Its section heading
  says so (`Out of character`) and it renders **last**, after all in-character sections. It
  MUST NOT be written to `characters.preferences` (§7.2 naming collision).
- The primary image, if one ever exists, replaces the initial letter in the portrait slot;
  `alt_text` becomes `alt`; a non-empty `content_warning` renders the image blurred behind a
  reveal control whose label is the warning text. Unexercised in v0.13 — see the backstop row.

### `/characters` — the sectioned roster (008-B)

```
Playable  ─────────────────────────────
[ card ] [ card ] [ card ] [ + create card (dashed) ]

Not playable  ─────────────────────  [3 ▾]     ← chip is the COLLAPSE control
[ locked card ] [ locked card ] [ locked card ]
```

- `Playable` grid **first**, carrying the dashed create card. **Every card in the top grid is
  uniformly clickable** — that is the decisive property of 008-B; there is no
  mixed-affordance grid.
- The create card is a **link to `/characters/new`** (D-87), not an inline input. The shipped
  inline-input branch (`characters/+page.svelte:154-193`) is deleted.
- `Not playable` renders **expanded**; the count chip is a collapse control with
  `aria-expanded` (D-96). Its label MUST NOT say "hidden" — that presumes the opposite
  default. The section is **omitted entirely** when the set is empty.
- **`idle` is unreachable in v0.13** (nothing transitions into it, §4.2). Write no copy that
  assumes a player will ever see it. The exhaustive switch still needs a branch; the branch
  needs no bespoke prose.
- **Badge rules, binding:**

| Card state | Badges |
|------------|--------|
| lifecycle `active`, is default | `Default` (accent outline) + session `Active` \| `Offline` |
| lifecycle `active`, not default | session `Active` \| `Offline` |
| lifecycle **not** `active` | `Retired` **only — the session badge is suppressed entirely** |

  `Retired · Offline` is meaningless, and the two vocabularies collide on the token `active`
  (008 Finding). Suppression happens in the template, not in the data.

- Grid: `repeat(auto-fill, minmax(200px, 1fr))`, `md` (12px) gap; single column below 768px.
- Ordering within `Playable` — see the unresolved row in UI Considerations.

### `/characters/[id]` — the sectioned authoring surface (D-92, D-93)

**Five sections, each with its own Save, its own mask, and its own error region.**

| # | Section heading | Fields | RPC | Mask paths |
|---|-----------------|--------|-----|------------|
| 1 | Identity | pronouns, concept, species, age, faction | `UpdateCharacterProfile` | `profile.pronouns`, `profile.concept`, `profile.species`, `profile.age`, `profile.faction` |
| 2 | In-world description | description | **`UpdateCharacterDescription`** | — (no mask) |
| 3 | Appearance & history | appearance, personality, biography | `UpdateCharacterProfile` | `profile.appearance`, `profile.personality`, `profile.biography` |
| 4 | Hooks & current | rumors, currently | `UpdateCharacterProfile` | `profile.rumors`, `profile.currently` |
| 5 | Out of character | rp_preferences, timezone | `UpdateCharacterProfile` | `profile.rp_preferences`, `profile.timezone` |

- **Section 2 is its own section precisely because it is its own RPC.** The two-RPC split
  surfaces as a **visible section boundary** rather than hiding behind one button that
  silently makes two writes — the system's shape and the interface's shape agree, and the
  partial-failure state stops existing (D-93).
- Each Save sends **only the paths its own section owns** — never the full twelve. An empty
  mask is a no-op success, never "apply every field"; an unlisted path is rejected
  (§9.5). A section with no dirty field has its Save **disabled**.
- Each response returns the post-write `OwnCharacter` carrying the fresh `version`. That
  version is stored in **exactly one place** on the page and is what the next Save of *any*
  section sends. One `GetMyCharacter` call feeds the whole page.
- A conflict scopes to **one section**: that section shows its error and keeps its text; the
  other four are untouched.
- Edit in place. **No view/edit split** — §8.12 ships no visibility controls, so an owner's
  read view and edit view would render the identical dataset from two loads with two places
  `version` can go stale.
- `View public profile →` links to `/c/[id]`.
- The PROFILE-12 notice sits **once, at the top of the page**, above section 1 — muted Body
  text, no icon, no border, not a callout. It is a standing fact, not an alert. It attaches
  **only** here: there is no player-facing retirement flow in v0.13, so the retirement half
  of PROFILE-12 is Phase 6's (D-91).

### `/characters/new` — the creation card (009-A, D-87, D-88)

Six fields in one section with one Save: `name` (required), `pronouns`, `concept`,
`species`, `age`, `faction`. Under the name field sits **one static line** stating the class
of rewrite and the syntactic rule. **Submit and report** — there is **no live availability
check, no debounced lookup, no client-side normalization mirror.** A client-side TypeScript
mirror of `charname.Normalize` is forbidden: it duplicates a security-adjacent normalizer
(NFKC → `Cf` strip → whitespace collapse → case-fold) in a second language and creates two
sources of truth for the value the unique index depends on (D-88).

On success: navigate to `/characters` and render the persistent confirmation region with
the **server-returned display name** (already on the wire via `OwnCharacter.name`), and the
new roster card shows the same name. That is the honest half of the echo; the availability
half stays rejected.

## Copywriting Contract

Terminology is binding (`.claude/rules/terminology.md`): **character**, **player**,
**session**, **location**. Never "room", "user", "avatar", "profile owner".

### Primary CTAs

| Surface | Copy |
|---------|------|
| `/characters` create card | `+ Create a character` |
| `/characters` playable card, not default | `Make default` |
| `/characters` roster card, any lifecycle | `Edit profile →` |
| `/characters/new` submit | `Create character` |
| `/characters/[id]` section 1 | `Save identity` |
| `/characters/[id]` section 2 | `Save in-world description` |
| `/characters/[id]` section 3 | `Save appearance & history` |
| `/characters/[id]` section 4 | `Save hooks & current` |
| `/characters/[id]` section 5 | `Save out of character` |
| `/characters/[id]` → public view | `View public profile →` |
| Not-playable roster card | `View profile →` |
| Not-found page | `Home` |

**The five Saves carry distinct visible labels — verb + that section's own noun — because
`/characters/[id]` renders all five at once.** Each label is the section heading it belongs
to, so a sighted player scanning the page can tell the five buttons apart without reaching
for context. There is **no `aria-label` override** on any of them: once the visible text is
distinct the override is duplication, and a duplicated string is a string that drifts out of
sync with the heading it is supposed to mirror. The accessible name is the visible name.

### Static explanatory copy

| Element | Copy |
|---------|------|
| Create-form name rule (static, always shown) | `Letters and single spaces, 2–32 characters. Full-width characters, invisible marks and extra spaces are folded, so the name you get may differ slightly from what you type.` |

| PROFILE-12 notice, `/characters/[id]` only | `Privacy here is not retroactive. Editing or clearing a field changes what this profile shows from now on — it cannot recall what visitors have already read.` |

**"Names are permanent" is FALSE and MUST NOT be written.** The property that holds is
**reserved** (§4.4, §4.5). Note the corpus drift: sketch 008/009 justify "reserved" by
pointing at rename shipping in v0.13; rename **left v0.13 on 2026-08-06** (Phase 3 D-44 →
backlog 999.20). "Reserved" is still the correct word — a retired character keeps its name —
but no copy may imply a player can change a name in this release.

| Element | Copy |
|---------|------|

### Error states

**Branch rule for `/c/[id]`, binding.** The client branches on **exactly one** condition:
gRPC status `NotFound` (oops code `CHARACTER_PROFILE_NOT_FOUND`) → the not-found render.
**Every other failure** → the generic error render. It MUST NOT branch on any distinction
between "no such character" and "below the reachability floor" — §9.6 returns one code for
both deliberately, and inventing a second branch client-side would reconstruct the exact
disclosure the uniform code exists to prevent.

| Element | Copy |
|---------|------|
| `/c/[id]` not-found (inline, no error boundary — D-95) | Heading `Not found` · body `We couldn't find that page.` · link `Home`. **No path echo** (echoing the requested string confirms it was routed). **No reason.** **Never** "this profile is private", never "access denied". |
| `/c/[id]` any other failure | `Something went wrong. Try again.` + a `Try again` control. |
| Create — `CHARACTER_NAME_TAKEN` | `That name is taken. Try another.` |
| Create — `CHARACTER_NAME_INVALID` | Render the **server-supplied message verbatim** — these are authored player-facing strings from the `charname` pipeline, including the two distinct messages for the empty-normal-form case (`pipeline.go:110-128`), one of which explains the invisible-codepoint case. Fallback if the message is empty: `That name can't be used here.` **The confusable message MUST NOT name the colliding character** (server-side constraint, restated here so no client-side "helpful" enrichment reintroduces it). |
| Create — any other failure | `Couldn't create the character. Try again.` |
| Save — `WORLD_CONCURRENT_EDIT` | `This character changed somewhere else. Reload to get the latest, then re-apply your edits.` + a `Reload` control. **Scoped to the one section that failed.** |
| Save — `CHARACTER_MASK_PATH_UNSUPPORTED` / `CHARACTER_VERSION_REQUIRED` | `Couldn't save. Try again.` (These are client bugs, not player errors. Never surface the code.) |
| Save — any other failure | `Couldn't save. Try again.` |
| Roster load failure | `Couldn't load your characters. Try again.` |

**No internal code, message or wrapped error text is ever rendered** — except the
`CHARACTER_NAME_INVALID` messages above, which are deliberately authored for players
(`.claude/rules/grpc-errors.md`).

### Success states

| Element | Copy |
|---------|------|
| Create success (roster, persistent `role="status"` region) | `Created {name}.` — `{name}` is the **server-returned display name**, which is the D-88 echo. |
| Section save success | `Saved.` in the section's own `role="status"` region, cleared on the next edit to that section. |
| Default changed | `{name} is now your default character.` in the roster's `role="status"` region; the `Default` badge moves in the same render. |

### Destructive confirmation

**No destructive action ships in Phase 5.** Retire / unretire are Phase 6 admin operations
(ADMIN-05); player self-retire is deferred beyond v0.13 (IDENT-04); rename is out of the
milestone (999.20); there is no `AdminDeleteCharacter` and no delete anywhere in the portal.
`SetDefaultCharacter` is reassignment, not destruction, and takes **no confirmation dialog** —
it is one click, immediately reflected, and immediately reversible by clicking another card.

The roster copy MUST NOT imply a player can retire, delete or rename a character.

## Accessibility & Interaction

| Requirement | Rule |
|-------------|------|
| Form `name` attributes | Every input carries `name` (Playwright, `web/CLAUDE.md`). Submit buttons carry `type="submit"`. |
| Status regions | Create/save/default confirmations use `role="status"` (polite). Error regions use `role="alert"`. |
| Portrait | `aria-hidden="true"` — the name is adjacent; the letter is decorative. |
| Collapse chip | `aria-expanded`, `aria-controls` pointing at the not-playable grid; label carries the count and the action, not the word "hidden". |
| Focus | Visible ring on every interactive element (`--color-ring`); never `outline: none` without a replacement. Focus moves to the first field of a section that fails to save. |
| Long-form fields | `<textarea>` with `white-space: pre-wrap` rendering on the public side; the profile never truncates prose — the prose is the content. |
| Motion | Card hover is a `border-color` transition ≤150ms. No new keyframes. Any animation added MUST sit inside a `@media (prefers-reduced-motion: no-preference)` guard. **Amended 2026-08-13:** this row previously said "the **existing**" block. No such block existed anywhere in `web/src` — the phase shipped no CSS transitions at all — so the guard was introduced with the card hover in `RosterCard.svelte`. New animations join that guard; they do not add their own. Transition named properties, never `all`, so the guard cannot silently stop covering a property added later. |
| Color independence | No state is signalled by color alone (see Color). |
| Byte counters | Shown on a field **only** within 20% of its cap, computed as `new TextEncoder().encode(v).length` so it matches the server exactly. Caps are **bytes**: 100 for short fields (`world.MaxNameLength`), 4000 for long fields and the description (`world.MaxDescriptionLength`) — see `internal/grpc/characteraccess_write.go:119-153`. |

## Anti-Pattern Guard (executor checklist)

Each of these was made or nearly made in the sketch corpus. Reintroducing any is a bug.

- [ ] No count, lock icon, greyed section, progress indicator or "N hidden" on a profile.
- [ ] No conditional sign-in invitation. No profile-local sign-in notice **at all**.
- [ ] No empty "coming soon" gallery slots.
- [ ] No "this profile is private" page — §8.7 requires the ordinary not-found.
- [ ] No path echo, no reason, on the not-found render.
- [ ] No session badge on a non-`active` lifecycle.
- [ ] No copy saying names are "permanent"; no copy implying a player can rename.
- [ ] No `/c/{name}` link — the key is the id (§9.2). Sketch 008's HTML is stale here.
- [ ] No live availability check, no debounced name lookup, no client-side normalizer mirror.
- [ ] No cleared create form on a rejected submit — every entered value survives the round trip.
      Submit-and-report (009-A) is only defensible if the round trip is cheap; discarding five
      typed fields to report one name collision makes it the hostile option.
- [ ] No client-side field allowlist diffed against the response (absence is a wire property).
- [ ] No amber outside the cursor.
- [ ] No hardcoded `HoloMUSH` in player-facing copy.
- [ ] No dense table for the player's own roster — Cards is the player idiom.
- [ ] No ordinal tier comparison anywhere the client touches tiers (set membership, §8.2.1).
- [ ] No `+error.svelte` added in this phase — `/c/[id]` renders not-found **inline** (D-95),
      and Phase 6 owns the single root boundary (#4903). When it lands, `/c/[id]` MUST adopt it.
- [ ] No claim in copy or acceptance text that a configuration change is visible on the
      **next load** or **immediately** — the policy cache is poller-refreshed on a 10s default
      interval (`internal/access/policy/poller.go:35`), D-97.
