## Job identity shape

### Q1 — Namespace for a background-job principal

| Option | Description | Selected |
|--------|-------------|----------|
| New `job:` namespace | Disjoint from `system:` at `parseEntityType`, so a job permit cannot grant `system:bootstrap`. Costs a provider + schema + seed. | ✓ |
| Reuse `system:` with per-job guards | Zero new substrate, but it is D-45's rejected shape with a `when { principal.id == … }` guard bolted on. | |
| Per-job namespace | Maximum isolation; N providers, N schemas, N seeds — bespoke wiring rather than a model. | |

### Q2 — How the resolver decides a job ref is real

| Option | Description | Selected |
|--------|-------------|----------|
| Registry of running jobs | Mirrors `PluginProvider`/`IsPluginLoaded`; a non-running job resolves to `nil, nil` and fails closed. Ties authority to liveness. | ✓ |
| Static compile-time list | Simpler, no lifecycle coupling, but registered-but-not-running still resolves. | |
| No registry | Cheapest; drops the fail-closed property and makes any job name a valid principal. | |

### Q3 — Subject attributes the provider stamps

| Option | Description | Selected |
|--------|-------------|----------|
| name + declared capability class | Lets policy express "a job may only touch resource kinds it declared". | ✓ |
| name only | Matches `PluginProvider` exactly; nothing about declared scope is expressible in policy. | |
| You decide | Defer to researcher using the two in-tree consumers as forcing cases. | |

### Q4 — Where the capability class is authored

| Option | Description | Selected |
|--------|-------------|----------|
| Go, at registration | Jobs are compiled-in host subsystems; declaration narrows, seed grants — both gates apply. | ✓ |
| In the seed policy only | Single source, but reintroduces the identity-string condition D-47 objected to. | |
| Manifest-style YAML | Mirrors `plugin.yaml` least-privilege, but jobs are not loadable units — no discovery step to parse from. | |

### Q5 — Which job satisfies criterion 2's DENY test

| Option | Description | Selected |
|--------|-------------|----------|
| Fixture job only | Keeps the phase a substrate change with no world-behavior effect; Phase 3 brings real consumers. | ✓ |
| Migrate `location_follow.go:197` | Strongest end-to-end evidence, but it is a synchronous gRPC follow, not a background job. | |
| Pull a Phase 3 consumer forward | Real exercise, but moves scope into a deliberately narrow phase and depends on unbuilt JetStream KV. | |

**Notes:** Q1's rationale is mechanical, not stylistic — `parseEntityType`
(`engine.go:542-548`) returns the prefix only, which is precisely why D-45's `system:retirement`
was unnarrowable.

## Plumbing into checkAccess

*This area changed the shape of the milestone. It is logged in the order it actually unfolded.*

### Q1 (first pass) — How attributes reach `service.go:214`

| Option | Description | Selected |
|--------|-------------|----------|
| Variadic option on `checkAccess` | All 24 call sites compile untouched. | ✓ *(later withdrawn)* |
| Change the signature, update all 24 | Explicit everywhere; a 24+13-site `nil`-noise diff. | |
| Carry attrs on the context | Zero churn; implicit and spooky. | |
| Sibling `checkAccessWithAttrs` | No churn; two paths that drift on metrics and error codes. | |

### Q2 (first pass) — Does 02.1 touch the domain command surface?

**User response (free text):** *"2 feels [right], when looking forward behind 'move character'
right?"*

**Outcome — the user was correct and the question set was flawed.** `MoveCharacter(ctx, subjectID,
…)` (`service.go:985`) calls `checkAccess` at `:990`, so a variadic on the *internal* method has
nothing to pass unless the *public* command already received it. "Access path only" + an explicit
internal variadic do not compose. Claude acknowledged the inconsistency and re-opened the area.

### Q3 (second pass) — Public API shape

| Option | Description | Selected |
|--------|-------------|----------|
| Variadic `CallOpt` on public commands | Composes end-to-end, zero churn. | |
| Generalize `subjectID` into a caller struct | Identity and execution context inseparable; breaking refactor. | ✓ |
| Required explicit param | Same explicitness without the type change; full `nil` diff. | |

**Grounding that unblocked this:** all **21** public `Service` methods begin
`(ctx, subjectID string, …)` — a uniform slot — which removed Claude's "widens the surface
asymmetrically" objection.

### Q4 — Deny-code shape

| Option | Description | Selected |
|--------|-------------|----------|
| Principal-kind wins for job subjects | One branch; code scheme becomes principal-aware for one namespace. | |
| Compose both (`JOB_CHARACTER_ACCESS_DENIED`) | Keeps the resource dimension in the code; more codes, nothing pushed to attrs. | ✓ |
| You decide | Defer to the D-46 retry wrapper's permanent-vs-transient distinction. | |

### Q5 — Handling the refactor after the real blast radius was measured

**Correction issued mid-area.** Claude's earlier estimate of "~19 caller files" came from a
file-level grep that hid the test sites and interface redeclarations. Measured: **47 production
call sites / 12 files, 347 test call sites / 13 files, 3+ interfaces** (`world/mutator.go` 11,
`command/types.go` 9+, `grpc/server.go` 2), plus mockery regeneration. The user was re-offered the
decision rather than held to the low estimate.

| Option | Description | Selected |
|--------|-------------|----------|
| Variadic now, caller struct as its own phase | Unblocks Phase 3 on schedule; leaves migration debt. | |
| Full caller-struct refactor in 02.1 | No intermediate shape; phase stops being narrow. | |
| Caller struct on write commands only | Halves the diff; reintroduces asymmetry. | |
| Variadic now + pin the destination in an ADR | Same as first, with durable rationale. | |

**User response (free text):** *"variadic feels like a codesmell to me. seems like we've build the
args wrong and we need to fix it correctly for something so clearly important."*

Claude agreed and sharpened the diagnosis: the world API is **lossy relative to the authorization
layer** — the engine has had a per-call attribute channel since Phase 3b and the world surface
cannot reach it. A variadic would preserve that defect while hiding it. Claude then proposed
**typed constructors** over a bare struct, so invalid caller/context combinations are
unrepresentable and the migration is a structural codemod rather than 347 judgment calls.

## Schema for `action.*`

### Q1 — Register the `action` namespace?

| Option | Description | Selected |
|--------|-------------|----------|
| Yes — register, declaring every existing key | Compile-time fail-hard on typo'd `action.*` repo-wide. Requires the full audit first. | ✓ |
| No — leave unregistered | Zero regression risk; typos fail closed but silently. | |
| Register after a separate audit lands first | Same end state, isolated sequencing. | |

### Q2 — How it gets registered

| Option | Description | Selected |
|--------|-------------|----------|
| Direct `Register` call in setup | Honest: `action` is a caller-supplied bag, not a resolvable entity. | ✓ |
| Synthetic action provider | Uniform with the other 9, but nil-returning resolvers misrepresent it. | |
| You decide | Defer to the `RegisteredNamespaces()` interaction. | |

**Correction issued in this area.** Claude's original framing of the area ("free-form and
typo-silent") described only the current state. `compiler.go:149-170` **hard-errors** for
undeclared keys in the `action` namespace specifically — the strictest treatment of any namespace —
so registering it is a repo-wide enforcement flip, not documentation. Scouting then found
`seed.go:332` already ships `action.dispatch_location` with no `action` namespace registered,
making "declare every existing key in the same change" a boot-safety requirement rather than
tidiness.
