# Phase 02.2 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

This phase introduces a new ABAC principal type (`job:`), its attribute provider,
an `action` attribute namespace with a now-fatal undeclared-key gate, a typed
`world.JobCaller`, and one fixture seed. The register below is the union of the
`<threat_model>` blocks authored in `02.2-01-PLAN.md` … `02.2-05-PLAN.md`,
verified against the implementation by `gsd-security-auditor` on 2026-08-09.

**Threat-ID collision notice.** `T-02.2-22` and `T-02.2-23` were each allocated
twice, in different plans, for different threats. They are disambiguated below as
`T-02.2-22(01)` / `T-02.2-22(05)` and `T-02.2-23(04)` / `T-02.2-23(05)`. Cite the
qualified form; a bare `T-02.2-22` is ambiguous.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| job consumer boundary → handler | Provenance is stamped from the delivered message BEFORE handler logic; the handler independently derives the resource. Neither side can see or alter the other's value (D-55). | Trigger event id / type / subject ULID |
| `world.Caller` → `types.NewAccessRequest` | The only channel by which a caller value influences `bags.Action`. Unexported field, no exported setter, constructor-built keys only. | Action attribute keys |
| `cmd/holomush/core.go` → ABAC subsystem config | The single point at which the job liveness registry enters the authorization stack. | Job registry handle |
| `world.Service` → gRPC error mapper | Deny codes cross into operator- and client-visible surfaces here. | Principal kind, resource kind (no identifiers) |
| operator-authored DB policy → `policy.Compiler` | Policy text an operator wrote crosses into compilation at `cache.Reload`. As of this phase it can stop the server from booting (D-67). | Policy DSL text |
| seed corpus → `policy.Bootstrap` | In-tree policy text crosses into installation; a bad seed now fails install rather than installing and silently default-denying. | Policy DSL text |
| `ActionNamespaceSchema()` → every future `action.*` reference | The declared set is the allowlist enforced at boot. | Attribute key names |
| invariant registry → future contributors | A registry summary is read as a guarantee; over-claiming is how a later reviewer approves a change that breaks something the registry said was safe. | Invariant prose |
| release documentation → operator | The only channel by which a deployment learns it must run the D-67 pre-flight query before upgrading. | SQL query, error-message shapes |
| host process → policy engine | **NOT** a trust boundary. Nothing in-process can stop Go from calling `Evaluate` with arbitrary arguments (D-53). This model does not claim otherwise. | — |
