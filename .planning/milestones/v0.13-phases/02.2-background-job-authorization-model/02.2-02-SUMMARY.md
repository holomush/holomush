**The production ABAC stack now gates job liveness against one real, injected `jobs.Registry`, and a job's denial names both dimensions — `JOB_CHARACTER_ACCESS_DENIED` — while still classifying as gRPC `PermissionDenied` and still staying out of the engine-failure counter.**

## Accomplishments

- **Plan 01's registration stopped failing closed for structural reasons.** `BuildABACStack` already built the job provider against `cfg.JobRegistry`, but no entrypoint populated it. One `jobs.Registry` is now constructed in `cmd/holomush/core.go` and reaches `attribute.JobProvider` through `ABACSubsystemConfig` → `ABACConfig`.
- **The registration is pinned BY NAME at both tiers**, not left to the seed-coverage guards' side effect. Those guards only notice a missing `job` provider while some seed references `principal.job.*`; exactly one does today, so the day `seed:job-fixture-instance-scoped` is retired both guards go quiet and the registration could be dropped silently — the holomush-g776 / xxel bug class, re-opened.
- **D-58's deny code composes both dimensions with the gRPC classification intact.** The qualifier is a prefix precisely so `grpc_server.go:169`'s `_ACCESS_DENIED` suffix match survives, and that is proven by feeding a REAL denial error through the REAL mapper rather than by re-implementing `strings.HasSuffix` in a test.
- **The metrics split is now a pinned property rather than an accident of the code's shape**, with a paired positive control so the negative cannot be satisfied by watching a counter nothing writes.
- **No new `lifecycle.SubsystemID`** — the 15-site cascade across the pinned 18-element topological start order was not touched.

## The composed deny-code shape

```text
{principalKind}_{entityPrefix}_ACCESS_DENIED     e.g. JOB_CHARACTER_ACCESS_DENIED
{entityPrefix}_ACCESS_DENIED                     unchanged for every human and system caller
{entityPrefix}_ACCESS_EVALUATION_FAILED          unchanged for EVERY caller, jobs included
```

The composition site (`internal/world/service.go::checkAccess`) builds the suffix from a **single** string literal and prepends the qualifier only when `caller.principalKind` is non-zero, so the six shipped entity codes are byte-identical to before.

Two spellings were considered and rejected, and that comparison is recorded at the composition site so it is not re-litigated:

| Rejected | Why |
|---|---|
| `CHARACTER_ACCESS_DENIED_JOB` | breaks `grpc_server.go:169`'s suffix classification outright — every job denial would map to `codes.Internal` |
| bare `oops.With("principal_kind", "job")` | exactly the log-attribute parsing D-58 exists to rule out |

## Why `KnownEntityPrefixes()` and `internal/command/errors.go` were NOT extended

`internal/command/errors.go`'s `entityAccessDeniedCodes` / `entityAccessEvalFailedCodes` are exact-match maps that drive **player-facing message text**. A background job's denial is never rendered to a player, so adding `JOB_*` rows would claim a surface this phase does not have. `world.KnownEntityPrefixes()` is likewise untouched, which is what keeps the cross-package tripwire `internal/command/errors_test.go#TestEntityPrefixCoverage` green **by construction** rather than by a matching edit.

The corollary is the reason the **evaluation-failure** codes stay unqualified: a `JOB_`-prefixed failure code would fall through the eval-failure map to the generic fallback, degrading the message a player sees exactly when the engine is unhealthy. D-58 speaks only of the deny signal.

## The `jobs.Registry` construction site Phase 3 reads from

`cmd/holomush/core.go`, immediately before `abacsetup.NewABACSubsystem(...)`:

```go
jobRegistry := jobs.NewRegistry()

abacSub := abacsetup.NewABACSubsystem(abacsetup.ABACSubsystemConfig{
	DB:              dbSub,
	Registry:        registry,
	CryptoOperators: cryptoConfig.Operators,
	JobRegistry:     jobRegistry,
})
```

Phase 3's job subsystems are the **writers**: they call `jobRegistry.Register(name, writes)` from their own `Start` and `Unregister(name)` from their `Stop`, against **this** instance. Until then the registry is empty, every job resolves to no attributes, and every job-gating seed default-denies — the correct fail-closed state.

## Config injection vs `SetRegistry` — the deviation from `02.2-PATTERNS.md`

`02.2-PATTERNS.md` recommends copying `attribute.PluginProvider`'s two-phase `SetRegistry` initialization. This plan **deliberately does not**, and the rationale is recorded on the `ABACSubsystemConfig.JobRegistry` field:

`PluginProvider` needs two-phase init because its registry **is** `plugin.Manager` — a subsystem built *after* `BuildABACStack` runs, so there is no way to hand it over at construction. `jobs.Registry` has **zero dependencies**, so it can be constructed before subsystem assembly and passed in. The result is one mechanism instead of two, and no window during which the provider holds a nil registry in production.

Nil remains tolerated and fails closed, per D-49: a nil registry reports every job as not running, so `principal.job.*` is absent and every job-gating seed default-denies. That is correct for an entrypoint that runs no background jobs, and it is why the integration assertion deliberately builds the stack with a **nil** registry — registration, not liveness, is what that test pins.

## On the `oops` code spelling

Every new assertion uses `errutil.AssertErrorCode(t, err, "...")`. The plan's analysis was re-confirmed rather than re-derived: `oops.AsOops` returns **two** values against the pinned v1.22.0, so the single-value spelling `.claude/rules/grpc-errors.md:58,:65` prescribes is a build error, and `OopsError.Code()` returns the **deepest** chain code, not the outermost node's own. `errutil.AssertErrorCode` is byte-for-byte the same call, so there is no stronger "direct" form.

That is the right assertion for this contract because `checkAccess`'s deny return wraps exactly **one** oops node over the plain `errors.New` sentinel `ErrPermissionDenied` — `getDeepestErrorCode` stops recursing at a non-`OopsError`, so deepest == the code under test by construction. The `require.ErrorIs` pairing is what pins that construction. Both facts are recorded in a comment above the assertion, citing **GitHub issue #4949** so the next reader knows the rule is drifted rather than the test. **The rule was not fixed as part of this phase**, per the plan.
