    <note>This asserts the deliverable rather than the tool. The superseded form asked the issue tracker for a list length and discarded it, which proved only that `gh` could authenticate — it would have passed just as well had zero issues been filed. The count is now taken INSIDE the loop rather than by a separate `awk 'END{print NR}'` pass, so the two halves of the gate cannot disagree about what a line is: `awk` counts a final line that lacks a trailing newline, `while read` does not, and that mismatch would let the count read four while only three issues were actually checked. Counting each iteration makes `c` the number of issues proven OPEN, by construction. Append with `printf '%s\n' "$n" &gt;&gt; /tmp/p9-02-skipfile-issues.txt` so the last line carries its newline; if it does not, the loop skips that partial line and the gate fails at the count — the safe direction, since it flags rather than silently verifying fewer issues than it claims. Every failing case exits non-zero: no file or an empty one, fewer or more than four lines read, a number that does not resolve, or an issue in any state but OPEN (a failed lookup yields an empty string, which is not `OPEN`). The loop is redirected, not piped, so it runs in this shell — `c` survives it and a bare `exit 1` inside it fails the whole gate.</note>
