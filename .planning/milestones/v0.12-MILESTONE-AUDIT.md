### Rule defect — `CLAUDE.md` instructs a change that breaks dedup

This is the audit's most consequential finding, and it inverts the usual
direction: **the code is correct and the repo rule is wrong.**

`CLAUDE.md` (§"ULID Generation" → Event construction) states that publication
sites MUST construct via `eventbus.NewEvent(...)` and "never a raw
`eventbus.Event{}` literal, never a hand-stamped `ID`" — then names
`internal/world/outbox/wire.go` (`EnvelopeToEvent`) as one of the four
construction sites.

`EnvelopeToEvent` does exactly what the rule forbids, and must:

- `internal/eventbus/types.go:214-224` — `NewEvent` unconditionally assigns
  `ID: core.NewULID()`. There is no parameter by which a caller supplies an ID.
- `internal/world/outbox/wire.go:170` — `EnvelopeToEvent` sets
  `ID: env.EventID`, preserving the ULID minted once at envelope-creation time
  (`wmodel/envelope.go`) and persisted in the outbox row.
- The relay stamps `Nats-Msg-Id` from `Event.ID` (`outbox/relay.go:54`). Retry
  safety depends on that value being **stable across republishes**.

Rewriting `wire.go` to satisfy the rule would mint a fresh ULID on every relay
retry, so JetStream would never dedup, and the outbox's at-least-once
guarantee would become actually-duplicating on the retry path.

**Mitigating fact:** the trap fails loudly, not silently. `relay_test.go:224`,
`:373` and `:385` each assert `env.EventID == ev.ID`, so the "fix" breaks tests
immediately. The hazard is a confused contributor, not a silent production
regression — which is why this is scored non-critical.

**Recommended fix:** amend `CLAUDE.md` to carve out `EnvelopeToEvent` as the
one construction site that MUST preserve a pre-minted ID, with the dedup
rationale stated inline.

## Recommendation

The milestone's substance is done and merged, and as of this audit every phase
carries a verifier pass. The remaining question is whether to close with three
deliberately-deferred requirements and no enforced coverage gate.

**A. Complete the milestone (now the stronger option).** Run
`/gsd-complete-milestone v0.12`. QUAL-02/03/05 are documented deferrals with
open issues (#4860, #4861, #4875, #4876, #4792), not silent drops — which is
the standard a milestone closeout should meet. Fold the coverage-gate finding
into the v0.13 scope rather than holding v0.12 open for it.

**B. Close the coverage gate first.** Requiring a coverage context on ruleset
`11923801` is blocked upstream: `codecov/project` posts on no ref (#4875) and
requiring `codecov/patch` would deadlock docs-only PRs (#4876). This is real
work with an unresolved design question, not a checkbox — it belongs in a
scoped phase, not in a milestone closeout.

Two items to carry forward regardless:

1. The **`CLAUDE.md` `EnvelopeToEvent` rule defect** — a live trap for the next
   contributor who reads the rule and follows it. Fix the rule, not the code.
2. The **coverage gate does not exist** — criterion 1 promises an enforced gate;
   `main` has none. Worth stating plainly in the milestone record so v0.13 does
   not inherit the belief that coverage is enforced.
