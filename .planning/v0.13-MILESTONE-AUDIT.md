## 6. New this audit — an agent-facing documentation hazard

**#4996.** Roughly 70 commands across `.planning/` are written
`-run 'A\|B'` inside GFM table cells. Inside a table cell `\|` is the *required*
escape for a literal pipe — cell splitting precedes inline-code parsing, so it
applies inside backticks — and it **renders as** `|`. The rendered command is
correct.

The raw bytes are not. Go's RE2 treats `\|` as a literal pipe, and a `-run`
pattern matching nothing **exits 0**:

```
-run 'TestProvenanceGuard\|TestEveryRegistryInvariantHasBinding'  →  DONE 0 tests   (exit 0)
-run 'TestProvenanceGuard|TestEveryRegistryInvariantHasBinding'   →  DONE 6 tests
```

A human reading the rendered table gets the correct command; an agent reading raw
bytes via `Read`/`rg` gets the vacuous one. This repo is agent-driven, so the two
audiences see different commands and only one of them is wrong.

Scope is bounded: **zero** occurrences in `docs/`, `Taskfile.yaml`,
`.github/workflows/`, or any test — **no live CI gate is affected**. Do not bulk
unescape: that was attempted and it breaks the tables (one row went from 8 cells
to 13), and `rumdl` does not validate table column consistency, so nothing
catches the damage. Detect with a per-row count of *unescaped* pipes against the
header.

## Method note

Carried forward: two intermediate results in the original audit were **artifacts,
not findings** — an orphan scan reporting 52 orphans (an extractor silently
returning zero) and one reporting 11 phantom requirements (a `[A-Z]+-[0-9]+`
regex matching invariant ids like `INV-ACCESS-13` and the encoding `UTF-8`). Both
were caught by requiring each search to first return a hit on a known-present
case before its absence was believed.

New this pass: §6's hazard was found because a reviewer's claim about RE2
semantics was verified empirically **and its context was not**. Confirming that
`\|` breaks RE2 established nothing about whether those particular strings ever
reach RE2 raw. The correct question is not only "is this claim true?" but "does
this claim apply to this occurrence?"
