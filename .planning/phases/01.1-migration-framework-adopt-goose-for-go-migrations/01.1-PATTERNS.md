## Pattern Assignments

### `internal/store/migrations_format_test.go` (NEW — meta-test, D-13 `$$` ↔ StatementBegin/End)

**Analog:** `internal/store/migrate_embed_test.go` (the file M1 rewrites — the new format test is
its sibling, split out because M1 checks *filenames* and this checks *contents*).

**Why this analog:** it is the only in-tree test that reads the unexported `migrationsFS`
directly. That forces the package clause: **internal test package `store`, no build tag** —
so it runs under plain `task test`, which is what D-13's "fails CI" requires.

**Package + imports to copy verbatim** (`migrate_embed_test.go:1-12`):

```go
// SPDX-License-Identifier: Apache-2.0
// Copyright 2026 HoloMUSH Contributors

package store

import (
	"regexp"
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)
```

Note: **no `//go:build integration`** — this is deliberate and load-bearing. Contrast
`migrations_test.go:4`, which *is* integration-tagged and therefore invisible to `task test`.

**Core pattern — read the embedded dir, `require` the precondition, `assert` per file**
(`migrate_embed_test.go:15-31`):

```go
entries, err := migrationsFS.ReadDir("migrations")
require.NoError(t, err, "should read embedded migrations directory")

for _, entry := range entries {
	assert.True(t, pattern.MatchString(entry.Name()),
		"file %s should match pattern NNNNNN_name.(up|down).sql", entry.Name())
}
```

`require` for the setup read, `assert` in the per-entry loop so one bad file does not hide the
rest — this is the repo's `.claude/rules/testing.md` "require for preconditions, assert for the
check under test" rule in its natural shape. Keep it.

**ACE naming.** The analog's name is a sentence:
`TestMigrationsFSContainsMatchedUpDownPairsWithCorrectNaming`. Mirror the shape, e.g.
`TestEveryDollarQuotedMigrationBodyIsWrappedInStatementBeginEnd`. Not
`TestMigrations_DollarQuote`.

**Demonstrated RED (TDD).** The analog gives no fixture seam — it reads only the real FS. For
the required red step, add a pure-function boundary (`func statementBlockViolations(name, body
string) []string`) and table-drive it over synthetic bodies; then call the same function over
`migrationsFS`. The table-driven shape to copy is `internal/store/migrate_clamp_integration_test.go`'s
`DescribeTable`/`Entry` for the Ginkgo side, or plain `[]struct{name string; ...}` + `t.Run` for
this unit-side test.

### `internal/store/migrate_adopt_integration_test.go` (NEW — C2a–C2e, Ginkgo + testcontainer)

**Analog:** `internal/store/migrate_integration_test.go` — specifically the suite registration
and the `Describe("Migrator")` block at `:138-180`.

**Why this analog:** it is the only in-tree spec that constructs a `store.NewMigrator` against a
raw (unmigrated) database and asserts version transitions — exactly adopt's shape.

**Build tag + package (note the ordering quirk — tag BEFORE the SPDX block here)**
(`migrate_integration_test.go:1-6`):

```go
//go:build integration

// SPDX-License-Identifier: Apache-2.0
// Copyright 2026 HoloMUSH Contributors

package store_test
```

Both orderings exist in the tree (`store_suite_test.go:1-6` puts SPDX first, tag second) and
both compile. Match the sibling you sit next to; do not invent a third.

**Import block** (`migrate_integration_test.go:8-23`) — the dot-import `//nolint:revive` comments
are mandatory house style:

```go
import (
	"context"

	"github.com/jackc/pgx/v5"
	. "github.com/onsi/ginkgo/v2" //nolint:revive // ginkgo convention
	. "github.com/onsi/gomega"    //nolint:revive // gomega convention
	"github.com/stretchr/testify/require"

	"github.com/holomush/holomush/internal/store"
	"github.com/holomush/holomush/test/testutil"
)
```

**Suite bootstrap — DO NOT write your own `TestXxx(t)` runner.** The package already has one
(`store_suite_test.go:22-30`) and a second `RunSpecs` in the same package is a hard failure:

```go
var (
	suiteT   *testing.T
	sharedPG *testutil.PostgresEnv
)

func TestStore(t *testing.T) {
	suiteT = t
	RegisterFailHandler(Fail)
	RunSpecs(t, "Store Suite")
}

var _ = BeforeSuite(func() {
	sharedPG = testutil.SharedPostgres(suiteT)
})
```

New specs are registered by a bare `var _ = Describe(...)` at file scope and reach the container
through the package-level `suiteT` / `sharedPG`.

**Testcontainer database acquisition — adopt needs the RAW (unmigrated, superuser) database**
(`migrate_integration_test.go:143`, helper at `test/testutil/postgres.go:254`):

```go
connStr := testutil.RawDatabase(suiteT, sharedPG)   // blank DB, postgres superuser
```

Contrast `testutil.FreshDatabase(suiteT, sharedPG)` (`postgres.go:221`, used at
`migrate_clamp_integration_test.go:76`) which returns a *template-cloned, already-migrated*
database on `holomush-role` creds. **Adopt tests need `RawDatabase`** — they must create
`schema_migrations` by hand and seed it at a chosen version. There is **no** per-test container:
one shared `postgres:18-alpine` + fast `CREATE DATABASE … TEMPLATE` clone (rationale documented
at `testhelpers_test.go:19-30`; spinning your own container reintroduces the CI starvation
incident named there).

**Assertion idiom inside a Ginkgo spec — Gomega, not testify** (`migrate_integration_test.go:145-167`):

```go
migrator, err := store.NewMigrator(connStr)
Expect(err).NotTo(HaveOccurred())
defer migrator.Close()

Expect(migrator.Up()).To(Succeed())

version, dirty, err := migrator.Version()
Expect(err).NotTo(HaveOccurred())
Expect(version).To(Equal(uint(latestMigrationVersion)))
Expect(dirty).To(BeFalse())
```

testify `require` is still used inside plain helper funcs that take `*testing.T`
(`queryTableNames` at `:78-105`) — the split is: Gomega inside `It`, testify inside `t`-taking
helpers.

**Concurrency spec (C2e).** `migrate_integration_test.go` already imports `sync` (`:11`) — there
is an existing concurrent-migrator spec in that file to model the two-replica adopt race on.

**Describe-string caution.** `internal/store/spec_meta_test.go:47-87` pins certain Ginkgo
`Describe` strings as invariant bindings (e.g. `"INV-STORE-9: TIMESTAMPTZ→BIGINT conversion …"`
at `:73`). If the plan registers a new invariant for ascending-seed ordering, its `Describe`
string becomes the pinned identifier and a row must be added to that `cases` slice **in the same
change**.

### `internal/store/migrate_gointerleave_integration_test.go` (NEW — C4/C4b fixture chain)

**Analog:** `internal/store/migrate_clamp_integration_test.go` (whole file). It is the closest
structural sibling: a single-purpose, self-contained integration file that (a) declares its own
fixture struct, (b) registers one `var _ = Describe(...)`, (c) opens its own pool, and (d) drives
migrations to explicit versions. That is precisely the interleave test's shape.

**Fixture-case struct + `DescribeTable`/`Entry` shape** (`migrate_clamp_integration_test.go:38-56`,
`:110-125`):

```go
type convCase struct {
	targetBefore uint
	target       uint
	table        string
	// …
}

DescribeTable(
	"conversion migration is overflow-safe", verify,
	Entry("000038 eventbus_crypto (crypto_keys)", convCase{ /* … */ }),
	// …
)
```

Use this if the interleave test grows more than one chain; a single `It` is fine for one chain.

**Per-spec context + pool** (`migrate_clamp_integration_test.go:73-79`):

```go
ctx, cancel := context.WithTimeout(context.Background(), 90*time.Second)
defer cancel()

pool, err := pgxpool.New(ctx, testutil.FreshDatabase(suiteT, sharedPG))
Expect(err).NotTo(HaveOccurred())
defer pool.Close()
```

For the interleave chain use `testutil.RawDatabase` (blank schema) and a `*sql.DB` rather than a
pgxpool, because goose's `NewProvider` takes `*sql.DB`. The `database/sql` + pgx-stdlib
blank-import precedent in this package is
`migrations_sessions_location_index_integration_test.go:9-13`:

```go
import (
	"database/sql"
	"errors"

	// Register pgx stdlib driver for database/sql.
	_ "github.com/jackc/pgx/v5/stdlib"
	// …
)
```

**Fixture directory.** RESEARCH §Pattern 4 uses `os.DirFS(fixtureDir)`. There is no in-tree
precedent for a `testdata/` SQL fixture dir under `internal/store` — the closest habit is
`t.TempDir()` written at spec setup. Either is defensible; `testdata/` is more readable and
survives `-count=2`.

**Irreversible-down assertion (C4b/D-09).** The Gomega form matching the analog's error style:

```go
Expect(err).To(HaveOccurred())
Expect(err.Error()).To(ContainSubstring("irreversible"))
```

If the fixture's down uses `oops.Code("MIGRATION_IRREVERSIBLE")`, prefer the repo's code
assertion over substring matching — but see the honest caveat in §Shared Patterns.

### `internal/store/migrations_export_test.go` — add `MigrationSectionForTest` (M6)

**Analog:** the file itself, `migrations_export_test.go:17-23`. This is an **extension**, not a
new file; the existing `MigrationSQLForTest` stays or is re-pointed.

**Exact existing shape to mirror** (`:1-23`):

```go
// SPDX-License-Identifier: Apache-2.0
// Copyright 2026 HoloMUSH Contributors

package store

// MigrationSQLForTest returns the embedded source of the named migration file
// (e.g. "000053_sessions_location_index.up.sql").
//
// It exists so that a migration spec can execute the migration's OWN SQL
// instead of re-typing it as a Go string literal. A re-typed copy makes the
// spec unfalsifiable: it asserts the idempotency of the string the test wrote,
// so deleting IF NOT EXISTS from the migration file leaves the spec green.
//
// migrationsFS is unexported and the specs live in package store_test; both
// packages are linked into the same test binary, so an export_test.go accessor
// is the narrowest seam that does not widen the production surface.
func MigrationSQLForTest(name string) (string, error) {
	data, err := migrationsFS.ReadFile("migrations/" + name)
	if err != nil {
		return "", err
	}
	return string(data), nil
}
```

Three properties to preserve in the new accessor:

1. **`package store`, no build tag, filename ends `_test.go`** — that is the whole trick: the
   file is compiled into both the `store` and `store_test` halves of the test binary, so
   `store_test` specs can reach the unexported `migrationsFS` without widening production.
   It has no build tag today, so it is available to *both* `task test` and `task test:int`
   consumers. **Do not add `//go:build integration`** — `migrations_sessions_location_index_integration_test.go`
   (integration-tagged) and any future unit consumer both need it.
2. **Bare `err` return, not `oops`.** The existing accessor returns the raw `fs` error. Keep
   that; this is a test seam, not a boundary.
3. **The docstring carries the *why*.** The new `MigrationSectionForTest(name, direction)` needs
   its own paragraph explaining that returning a whole merged goose file to a caller that
   `Exec`s it would run the **down** body too (the M4/M5 hazard). That sentence is the reason
   the function exists; a reader who deletes it will re-introduce the bug.

**Callers to migrate** (all three currently assume paired files):
`internal/store/events_audit_partition_migration_integration_test.go:112` (M4),
`internal/store/migrations_sessions_location_index_integration_test.go:163,169` (M5), and the
doc comment at `migrations_export_test.go:7` (M3).

### `internal/store/migrate_adopt.go` (NEW — production, D-01..D-06)

**Analog:** `internal/store/migrate.go:65-87` (`NewMigrator`). Not a perfect match — nothing in
the tree does one-shot bookkeeping adoption — but it is the right sibling for *file shape*:
same package, same error vocabulary, same header.

**Header + import shape** (`migrate.go:1-20`):

```go
// SPDX-License-Identifier: Apache-2.0
// Copyright 2026 HoloMUSH Contributors

package store

import (
	"embed"
	"errors"
	// …
	"github.com/samber/oops"
)
```

**Error idiom — `oops.Code(...).With(k, v).Wrap(err)` at every boundary** (`migrate.go:68`,
`:83`, `:109`, `:120`, `:151`):

```go
return nil, oops.Code("MIGRATION_SOURCE_FAILED").With("operation", "create migration source").Wrap(err)
// …
return oops.Code("MIGRATION_STEPS_FAILED").With("steps", n).Wrap(err)
// …
return oops.Code("INVALID_VERSION").Errorf("version must be non-negative, got %d", version)
```

The house convention is a `MIGRATION_*`-prefixed SCREAMING_SNAKE code. D-05's dirty refusal
should follow suit (e.g. `MIGRATION_ADOPT_REFUSED_DIRTY`) and carry the version via
`.With("dirty_version", v)` rather than baking it into the message only.

**Logging.** `migrate.go:219` uses a **bare** `slog.Warn` with a three-point justification
comment — that is the documented carve-out (init-time, no ctx). The adopt gate **does** have a
`ctx` and MUST use `slog.InfoContext(ctx, …)`. Per RESEARCH §Known Threat Patterns, log the
derived row count and the recorded version **before** the commit, since no human is watching.

**Reusable asset:** `allMigrationVersions()` (`migrate.go:179-190`) already returns an
ascending, defensively-copied `[]uint` (sorted at `:232`). Feed its slice directly to the seed
loop — routing through a map destroys the ordering that Pitfall 1 proves is load-bearing.

## Shared Patterns

### SPDX header (every `.go`, `.sql`)

**Source:** `internal/store/migrate.go:1-2`, all 88 migration `.sql` files (88/88 verified in
RESEARCH). **Apply to:** every new file in this phase.

```go
// SPDX-License-Identifier: Apache-2.0
// Copyright 2026 HoloMUSH Contributors
```

Applied/checked by `task fmt` (license-eye). The converter MUST leave exactly **one** header per
merged `.sql` file (D-11).

### Build tag placement + the `task test` blind spot

**Source:** `internal/store/store_suite_test.go:1-6` (SPDX first), `migrate_integration_test.go:1-6`
(tag first). **Apply to:** both new integration test files.

`task test` does **not** compile `//go:build integration` files. This phase changes
`store.Migrator`'s method set and ~15 integration files consume it — every task touching
`Migrator` gates on `task test:int`, never `task test` alone (RESEARCH Pitfall 8). The D-13
format meta-test is deliberately **untagged** so it runs in the fast lane.

### ACE test naming

**Source:** `internal/store/migrate_embed_test.go:14`
(`TestMigrationsFSContainsMatchedUpDownPairsWithCorrectNaming`),
`internal/store/lint_meta_test.go:49` (`TestLintNoMicrosecondTruncateScansAnExplicitPath`).
**Apply to:** every new `func Test*`.

Names are sentences (Action + Condition + Expectation), PascalCase, no underscores.
`internal/store/migrations_test.go:24` (`TestMigration_000030_BootstrapMetadataReplacement`) is
the pre-ACE legacy form — do **not** copy it for new tests.

### require vs assert

**Source:** `internal/store/migrate_embed_test.go:16` (`require.NoError` for the FS read) vs
`:18,24,29` (`assert.*` for each check). **Apply to:** all new testify-based tests.

### Ginkgo helpers

**Source:** `internal/store/migrations_sessions_location_index_integration_test.go:43`
(`GinkgoHelper()` as the first statement of a spec-called helper). **Apply to:** any helper the
new integration specs factor out, so failures report the caller's line.

### Error-code assertions — honest caveat

`.claude/rules/testing.md` prefers `errutil.AssertErrorCode` over string matching. **There is
currently zero use of it anywhere under `internal/store/`** (verified: all hits are in
`cmd/holomush/`, e.g. `cmd/holomush/core_test.go:319`, `kek_provision_test.go:37`). So there is
no in-package analog to copy. Two consequences for the planner:

- Unit tests for adopt's error paths **should** introduce `errutil.AssertErrorCode(t, err,
  "MIGRATION_ADOPT_REFUSED_DIRTY")` — following the `cmd/holomush` precedent, being the first in
  this package.
- Inside a Ginkgo `It` there is no Gomega equivalent; the in-tree habit is
  `Expect(err.Error()).To(ContainSubstring(...))`. If the code identity matters (D-05's refusal
  does), assert it in a `t`-taking helper with `errutil.AssertErrorCode` rather than a Gomega
  substring.
