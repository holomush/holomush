<objective>
Build the recorded-state cutover from `schema_migrations` to `goose_db_version` (D-01..D-06) and
prove it against a database seeded at the pre-conversion version, including both negative controls
and the ordering regression guard.

Purpose: this is the phase's only irreversible step, and it runs unattended at boot. golang-migrate
records a single current version, never the applied set, so the set must be derived from the
embedded FS — and `gooseutil.UpVersions` treats any filesystem version below the DB's max that is
not recorded as *missing*, a hard error without `-allow-missing` and a re-application with it.
Seeding only version 53 would therefore make goose offer to re-run 43 migrations. Over-seeding is
comparatively harmless; the danger is strictly one-directional.

Output: `internal/store/migrate_adopt.go`, five integration specs (C2a–C2e), and a registry
invariant pinning the ascending-order property that `migrate down` silently depends on.
</objective>
