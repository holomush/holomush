<objective>
Build the character-administration table: dense operator rows, click-header sort, one status
filter, substring search, pagination, and the four states the list can be in.

Purpose: ADMIN-03's read half needs a surface. §11.3 names "a sort control whose options are
drawn from the §7.2 field list" as *the* warning sign, because the field list is the
privacy-bearing set — so sorting is click-header only, there is no facet panel, and the one
`select` filters `status`. D-107 renames the activity column to `Last active` and renders it as
coarse relative text, because sketch 008 found two "status" vocabularies colliding on the
roster and this column must not join them.

Output: `CharacterTable.svelte`, the filter bar, the relative-time formatter with its six
declared buckets, and the characters page wiring all four list states.
</objective>

authoritative than the data is, which is the exact failure coarse text exists to avoid. Making
the absolute value unavailable at the call site is what enforces that rather than trusting each
caller.

Clock skew (a stored value in the future) renders `< 1h ago`; never a negative bucket and never
`in 3h`.

**Columns.** Six at `>=768px`: `Name`, `Player`, `Status`, `Last active`, `Created`, `Ver`.

**The client never re-sorts.** Render `rows` in the order received. The `never` rows' position
is a server contract (D-107); a client-side "fix" to an ordering it thinks looks wrong silently
breaks the property the server test proves.

**Row actions.** At `>=768px`, hover reveals **exactly two**: `Edit` and `Retire…` (or
`Un-retire` when the row's own `status` is retired). **No `⋯` overflow menu** — there is no
third action in v0.13 (no delete, no rename), so an overflow trigger would be an affordance with
nothing behind it. The same actions MUST also appear on `:focus-within` or they are unreachable
without a pointer. Below 768px **no action cluster renders**; the row itself becomes a real
`<button>` opening the edit Sheet, and retire is reached from inside the Sheet's transition
picker — the same component and the same RPC on every band.

**Status** is muted text carrying the word (`active` / `retired` / `idle`). **No session badge,
no presence dot, no colour-coded status, and no `--color-status-online` anywhere** — Phase 5's
green badge is *session* state while this column is *lifecycle*, the two vocabularies collide on
the token `active`, and this table is the one surface where an operator could plausibly read a
green dot as "connected right now".

**Overflow.** Names are bounded server-side at 32 runes and usernames at the `players.username`
cap, so a cell wraps to at most two lines then ellipsizes, with the full value in the row's
accessible name. The page never scrolls horizontally, and the table stays usable at 200% zoom:
columns wrap rather than forcing a horizontal page scroll, and the sticky header stays sticky.

**Pending row.** `pendingRowId` puts exactly one row in a pending state; every other row stays
interactive. On a successful mutation the row flashes with the **shipped** `just-arrived`

guard. Any new transition names its properties — never `all`.

below) inside a `role="status"` region labelled `Loading characters…`. No spinner, no label swap.

Row height 36px minimum at `cozy`; every interactive target reaches 44×44px of hit area
including padding, row actions via an inline-block hit area that overflows the row bounds.
Every breakpoint rule is `@container vp`, never `@media` (except the shipped reduced-motion
guard).
