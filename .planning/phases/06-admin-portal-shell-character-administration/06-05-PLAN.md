<objective>
Give the `characters` admin section its write surface, and make every admin mutation audited in
the same transaction as its state change — with before-values scoped away from player prose.

Purpose: ADMIN-06 as written says "recording before-values", and read to the letter that would
copy player-authored profile prose into `events_audit`, a **retained** table, undoing the
erasure-safe property `BuildCharacterProfileUpdatePayload` was designed with
(`payloads.go:445-466` — designed with it in its doc comment, but **pinned by no test**: this plan
authors the first one, Task 1 Test 4). D-103 splits before-values by field
kind instead: changed attribute **names** for prose, a real before-`status` for lifecycle
transitions, because a lifecycle enum is not player-authored content. An auditor still learns
who, when, which character, which fields, and for a lifecycle transition what the value was.

Per **D-105**, emission goes through the transactional outbox seam in the same transaction as
the state change (§9.3, INV-WORLD-1), reusing the shape `UpdateCharacterDescription` already
uses; the `events_audit` row is **projected** from that envelope by the asynchronous audit
projection, which stays the only writer to that table. There is **no** direct
`INSERT INTO events_audit` — §14 row 9 is explicit that no transactional write path into that
table exists and that building one would bypass the codec / `dek_ref` / dedup contract
`writeAuditRow` maintains. Per **D-104** the envelope Actor is `player:<id>` and the acting
character is omitted. Per **D-103** before-values are split by field kind.

Output: three write RPCs with the 13-path allowlist and the `expected_version` guard; the
eight-step taxonomy widening carrying `before_status`, `section` and `action`; the seed policy
that lets the player-flavoured admin caller pass the world-layer `checkAccess`; and the
integration proof that the envelope is transactional while the `events_audit` row is projected.
</objective>
