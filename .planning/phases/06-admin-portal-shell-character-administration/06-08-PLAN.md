<objective>
Ship the edit surface and the mutation loop: a two-group Sheet whose exclusions are declared
before the form, a transition picker that never sends a status value, a confirm that tells the
operator what retiring actually does, and the success/conflict split that decides whether the
Sheet closes.

problem is that 2 of its 15 rows are deliberately un-editable and must read as intentional. The
status control is exactly the control an implementer would otherwise wire to a `status` field.

Sheet is portalled to `document.body` by default (`sheet-content.svelte:31`), so both phone
rules would silently no-op while everything compiles and every desktop test stays green.

Output: `EditCharacterSheet.svelte`, `LifecycleConfirmDialog.svelte`, the byte-counter shared
with the server's caps, the D-110 mutation loop, and `web/e2e/admin-portal.spec.ts` carrying
the two held-out proofs.

`web/src/lib/components/admin/EditCharacterSheet.svelte`.

**Header:** the title `Edit character` at the Heading role, and one Dense muted metadata line
`{characterId} · v{n}` in **monospace** — the character ULID is the single string in this phase
permitted monospace, because it is an opaque identifier an operator may need to copy.

**Group 1, `Managed elsewhere`, FIRST and COLLAPSED.** Collapsed it costs ~30px and shows
`Name {name} · Status {status}` plus a right-aligned `managed by their own operations`.
Expanded it shows `Name` and `Status` as full rows with their reasons:
- Name: `Names go through the normalization pipeline and a uniqueness check, so they are not
  editable from this form.`
- Status: `Use the lifecycle control below — it sends the transition, not a status value.`
Declaring the exclusions **before** the form is the whole point: the operator learns what this
surface does not do before they start typing.

**`version` is header metadata, never a row and never editable.** It is the concurrency guard
carried as `expected_version` (§9.4); a row alongside `Name`/`Status` would imply a door that
does not exist.

**Group 2, `Editable here`** — the 13 maskable profile fields inside `Field.FieldGroup`, each
with a `name` attribute and a `{byteCount(v)} of {cap}` counter.

**Where those 13 current values come from: an `AdminGetCharacter` fetch on open** (cross-AI review
R-21). An earlier revision required the Sheet to open from row data, issue no fetch, and render
all 13 current values — three properties that cannot all hold, because `AdminCharacter` is the
**list** projection and carries no profile prose at all. Seeding from it would render every prose
input blank and **overwrite existing content** on the first save. Plan 06-04 now returns an
`AdminCharacterDetail` from `AdminGetCharacter` carrying `description` plus the twelve
`profile.*` values; this Sheet fetches it.

The loading state is honest, not hidden:

- The **header** (`Edit character`, `{characterId} · v{n}`) and **Group 1** render immediately
  from the row — the row already has name, status and version, so the operator sees the right
  character instantly and the fetch is never a blank modal.
- **Group 2** renders `skeleton` rows at the field count until the detail resolves.
- `Save changes` is `disabled` while loading — a save cannot be issued against an unpopulated
  form, which is the failure mode this whole change exists to prevent.
- On failure: `Couldn't load this character. Try again.` inside the Sheet with a retry control,
  Save still `disabled`. Never an empty form that looks editable.
- Seed `loaded` from the resolved detail and `working` from `loaded` through `untrack`, per
  `ProfileSection.svelte:40-60`; dirty stays `loaded` vs `working`, so nothing is dirty on arrival.

**The lifecycle control**, labelled `Lifecycle`, is a **transition picker that never sends a
status value**. Selecting `Retired` routes to the confirm dialog, which sends
`AdminRetireCharacter`; selecting `Active` routes to the confirm, which sends
`AdminUnretireCharacter`. Selecting a transition does **not** apply it. `idle` appears and is
permanently unselectable (dimmed) with the reason
`idle — system-invoked on inactivity. Not implemented in this release.` The control carries an
always-visible footnote naming the RPC it will send
(`Sends AdminRetireCharacter — never a status value.`, or the un-retire equivalent when the
character is retired) — stated literally because this is exactly the control an implementer
would otherwise wire to a `status` field.

**The mask is visible and an empty mask is inert.** Dirty is derived from `loaded` vs `working`
`$state` records — **never** a flag set by an input handler, which would survive an edit that
put a field back the way it started. That derivation drives both the footer count and the
`disabled` state of `Save changes`.

**Geometry: two mechanisms, because one of them cannot be CSS.** An earlier revision had a single
`@container vp (max-width: 767px)` block "flip it to `side=bottom`". **That is impossible**
(cross-AI review R-44, orchestrator-verified): `side` is a Svelte **prop** (`sheet-content.svelte:18`,
`:25`) emitted as `data-side={side}` (`:36`); CSS can restyle `[data-side=right]` geometry but can
never mutate that attribute to `bottom` nor select the bottom transition classes. The E2E
assertion `data-side="bottom"` could not have passed under its own specified mechanism.

Split it:

1. **`side` is derived in Svelte from the measured container width.** Read the `vp` element from
   the shared `vpContainer` store (plan 06-06), attach a `ResizeObserver` in `$effect`, keep its
   `inlineSize` in `$state`, and compute
   `const side = $derived(vpWidth > 0 && vpWidth < 768 ? 'bottom' : 'right')`, passed to
   `Sheet.Content`. Measuring the **container** rather than `window.innerWidth` is what keeps the
   flip on the same threshold as the CSS block beside it, whatever the container's width turns out
   to be. Disconnect the observer on teardown. Before `vpWidth` is known, default to `'right'` —
   the desktop shape — rather than flickering through `bottom`.
2. **CSS keeps only what CSS can do**: exactly one `@container vp (max-width: 767px)` block
   carrying the 84% height on the bottom variant and the 16px font on every `input`, `textarea`
   and `select`. Two rules, one block, so a reader cannot honor one and miss the other. The 16px
   floor is a platform constraint, not a style preference: any font `<16px` in a **focused** input
   triggers iOS Safari's zoom-on-focus, which does not unzoom on blur.
3. **380px right overlay above the phone band**, via an explicit `class` on `Sheet.Content`
   overriding the generated `sm:max-w-sm` 384px default. Do not edit the generated file.
4. **Pass `portalProps={{ to: <the vp element from the store> }}`** — the prop already exists at
   `sheet-content.svelte:20,24`. Without it the portal renders to `document.body`, **outside**
   `vp`, and the `@container vp` block never matches: the height and font rules silently no-op
   while the build stays green. **Retargeting the portal is necessary for the CSS half and is NOT
   what makes the side flip work** — say so in a comment, because the two are easy to conflate and
   a reader who "fixes" the portal will believe they fixed the flip.

**No grab handle** (D-109). `bits-ui` has no swipe-dismiss, so a handle would promise a gesture
the component cannot honor. Closing is backdrop tap, `Escape`, the `×`, and `Cancel`; all four
MUST work at every band. No back arrow on the phone sheet — it would make the sheet a route.

`bits-ui` Dialog semantics: focus trapped, focus returns to the invoking row action on close,
`Sheet.Title` and `Sheet.Description` always present.

Copy: `Save changes` (verb+noun, the milestone convention), `Cancel`. Terminology binding:
**character**, **player**; never "room", "user", "avatar", "account".
