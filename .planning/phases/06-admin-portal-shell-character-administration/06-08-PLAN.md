<objective>
Ship the edit surface and the mutation loop: a two-group Sheet whose exclusions are declared
before the form, a transition picker that never sends a status value, a confirm that tells the
operator what retiring actually does, and the success/conflict split that decides whether the
Sheet closes.

Purpose: this is where the phase's honesty properties get spent. The Sheet's whole design
problem is that 2 of its 15 rows are deliberately un-editable and must read as intentional. The
status control is exactly the control an implementer would otherwise wire to a `status` field.
And the `@container vp (max-width: 767px)` rules cannot be verified by a passing build — the
Sheet is portalled to `document.body` by default (`sheet-content.svelte:31`), so both phone
rules would silently no-op while everything compiles and every desktop test stays green.

Output: `EditCharacterSheet.svelte`, `LifecycleConfirmDialog.svelte`, the byte-counter shared
with the server's caps, the D-110 mutation loop, and `web/e2e/admin-portal.spec.ts` carrying
the two held-out proofs.
</objective>

**Group 1, `Managed elsewhere`, FIRST and COLLAPSED.** Collapsed it costs ~30px and shows

Expanded it shows `Name` and `Status` as full rows with their reasons:

Declaring the exclusions **before** the form is the whole point: the operator learns what this

**`version` is header metadata, never a row and never editable.** It is the concurrency guard
carried as `expected_version` (§9.4); a row alongside `Name`/`Status` would imply a door that
does not exist.

**Group 2, `Editable here`** — the 13 maskable profile fields inside `Field.FieldGroup`, each
with a `name` attribute and a `{byteCount(v)} of {cap}` counter.

**The lifecycle control**, labelled `Lifecycle`, is a **transition picker that never sends a

`web/src/lib/components/admin/LifecycleConfirmDialog.svelte` — an **`alert-dialog`**, because
this confirmation requires a decision and MUST NOT be dismissible by a backdrop click; the
installed `dialog` does not carry that role, and reusing it would ship a confirmation for an
audited mutation on a character the operator does not own that a stray backdrop tap can silently

Retire copy — title `Retire {name}?`, confirm `Retire character` on `--color-destructive`,
cancel `Cancel`, and this body verbatim:

> Retiring takes this character out of active play. It does not hide them — their public profile
> stays visible and everything they have already posed or played in is unchanged. The name stays
> reserved. You can undo this at any time.

The clause map, so a reviewer can check all four landed: *out of active play* → sentence 1;
*not hidden* → sentence 2 (profile + published history); *name stays reserved* → sentence 3;
*undoable* → sentence 4. This is **retire-specific copy and is NOT Phase 5's player-facing
not-retroactive string** — that string addresses a player choosing what to reveal about their own
profile, which an admin is not. The misconception this actor is likeliest to hold is that
retiring is a takedown, and the body corrects exactly that.

Un-retire copy — title `Return {name} to active play?`, body `This character becomes playable
again. Their public profile and history are unchanged.`, confirm `Un-retire character`
(**primary, not destructive**), cancel `Cancel`. Un-retire confirms too, deliberately: both
directions are audited mutations by an operator on a character they do not own, and the
transition picker's contract is that selecting a transition *routes to the confirmation* rather
than applying it.

Both entry points — the table's row action and the Sheet's lifecycle picker — route to **this
one component** and send **the same RPC**. Two entrances, one component, one mutation.

**The mutation loop, D-110's binding sequence.** Wire it in the characters page:

| Step | Success | `Aborted` (version conflict) |
|---|---|---|
| 1 | `Save`/confirm becomes `disabled` + `aria-busy="true"`, **keeping its label** — no swap to "Saving…", no spinner | same |
| 2 | the row enters the pending state | same |
| 3 | **the Sheet closes** | **the Sheet stays open** |
| 4 | the row updates **in place from the response** — never a table refetch — and flashes via the shipped `just-arrived` keyframe | **every typed value is preserved** |
| 5 | the toast fires, **naming the RPC** | the conflict `alert` renders inline with the fresh version; focus moves to the first conflicting field. **No toast — nothing finished.** |

The toast is the receipt for a **finished** action, so a Sheet still open behind it would be
ambiguous, and the Sheet's `version` header metadata would already be stale.

Toast strings, exactly:
- `AdminUpdateCharacter · update_mask: {n} paths · v{old} → v{new}`
- `AdminRetireCharacter · {name} · v{old} → v{new}` plus an `Undo` action
- `AdminUnretireCharacter · {name} · v{old} → v{new}`

Duration **6s** (longer than the 4s default — this is a receipt and the `Undo` needs a usable
window), dismissible, and never the sole carrier of the outcome: the row already updated in
place. One `<Toaster />` mounts once, in the admin layout.

Naming the wire call is **accountability**, not debug output: an admin is acting on a character
they do not own, recorded to the audit log under their player id (§10.7). The rule is
*narration is wrong on read surfaces and right on audited writes*.

**The `Undo` sends `AdminUnretireCharacter`** — never a status value — carrying
`expected_version` = the **new** version from the retire response, through the same RPC and the
same code path the transition picker uses.

**Conflict copy**, inline `alert` with `role="alert"` inside the open Sheet:
`Someone else edited this character. Your copy is version {mine}; the server is now at {theirs}.
Your changes were not applied — reload to see the current values, then re-apply.` plus a
`Reload` control. Both numbers are versions, which the table already shows; this is the one place
a server-supplied **number** reaches the screen, and no server-supplied **string** does.

Other failures: `Couldn't save. Try again.` and
`Couldn't change this character's lifecycle. Try again.` Resolve every failure into the small
authored union (`'' | 'conflict' | 'generic'`); never the `e instanceof Error ? e.message : …`
idiom.

Copy that asserts a property of the system is a claim and must be grounded. The properties that
actually hold here are *reserved*, *reversible* and *not hidden*.
