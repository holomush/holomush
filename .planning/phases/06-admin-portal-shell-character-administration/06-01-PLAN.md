<objective>
Stand up `/admin` as an ABAC-gated trust boundary by wiring the authorization substrate
Phase 2 already shipped to a real RPC surface and a real screen, end-to-end, before any
section is built.

Purpose: the ROADMAP states the gate "is the **first thing built in this phase**, before any
section, so every subsequent section inherits it." This plan is that gate, proven over the
wire with a paired positive control, and made structurally un-forgettable by a fail-closed
method→section descriptor **per D-99** — the gate is carried by a method→section descriptor
table plus an interceptor, not by a per-handler call, and it mounts **core-side only** because
`.claude/rules/gateway-boundary.md` and §10.4 both put an `internal/web/` authorization decision
in the wrong process. `AdminListSections` is the first of D-100's two registry RPCs, and the
envelope Actor convention it will later carry is D-104's.

Output: `holomush.adminportal.v1.AdminPortalService` carrying `AdminListSections`; the
method→section descriptor table; the two zero-caller gRPC constructors collapsed into ONE
factory that cannot build an ungated server, used by production and by the gate test's bufconn
listener alike; the `Web`-prefixed gateway proxy; the SvelteKit `/admin` shell that renders
its nav from the server's answer; and the tests that make each of those fail RED under the
specific bug it guards.
</objective>

<wire_contract_is_settled>
**The admin portal's wire contract is `holomush.adminportal.v1.AdminPortalService`, in
`api/proto/holomush/adminportal/v1/adminportal.proto`. This is settled by the maintainer; it is
not an open question, and no task in this phase re-asks it.**

An earlier revision proposed `holomush.admin.v1.AdminService` behind a `checkpoint:decision`.
That name is **already taken**: `api/proto/holomush/admin/v1/admin.proto:6` declares
`package holomush.admin.v1` and `:19` declares `service AdminService` — the break-glass operator
service (`Status`, `Authenticate`, `Approve`, `ResetTOTP`, `Rekey`, `RekeyResume`, `RekeyAbort`,
`RekeyStatus`, `RekeyList`, `AdminReadStream`), generated into `pkg/proto/holomush/admin` with
`adminv1connect` bindings. Two services of the same name in one proto package is a hard protobuf
error, so the phase would have failed at `task proto`.

**The operator service is served over a UNIX domain socket, not the core gRPC server.**
`internal/admin/socket/` mounts `adminv1connect.NewAdminServiceHandler`, and
`cmd/holomush/admin_client.go:50-60` dials that socket at `http://admin`. None of its RPCs ever
traverses the server this plan gates, so no defensive design against "the prefix gate would also
cover TOTP reset and crypto rekey" is needed or wanted — that risk does not exist.

Why a distinct package rather than cohabitation: the prefix gate exists precisely so a future
admin RPC cannot escape by naming. Fusing two different auth models under one prefix — an
operator break-glass surface guarded by `AssertOperatorAdmin` over a UDS, and a player-session
portal guarded by `admin_section:` ABAC over the network — would weaken exactly the property the
gate is built to hold. The portal gets its own gate boundary; the operator control plane is
untouched by this phase.

The rename is total. `holomush.admin.v1.AdminService` MUST NOT name any artifact this phase
creates — see Task 2's final acceptance criterion, which greps for it repo-wide.
</wire_contract_is_settled>
