<objective>
Make the six deferred sections reachable, gated, and refusing after the gate — and ship the
non-authoritative `roles` hint the rail uses to decide whether to draw `/admin` at all.

Purpose: ROADMAP Success Criterion 4 requires the refusal to be reachable **over the wire**,
not only at the helper level. `section.AssertSectionAccess` already returns
`SECTION_NOT_IMPLEMENTED` after steps 1–3 (`gate.go:163-167`) and `gate_test.go:209` proves it
in-package; what does not exist is an RPC through which a caller can actually reach it. D-100
supplies exactly one endpoint with the section id as a **parameter**, so seven denial
assertions iterate one method rather than manufacturing six stub RPCs whose only job is to be
denied.

Output: `AdminGetSection(section_id)`, its `Web`-prefixed proxy, `repeated string roles` on
`WebCheckSessionResponse`, and the seven-section wire-level denial iteration with paired
positive controls.
</objective>

**`internal/grpc/admin_interceptor.go` (modify) — the third gating arm. This is the load-bearing
edit of this task, and it is why the interceptor is in `files_modified`.** Plan 06-01 shipped a
two-arm shape switch. A `SectionFromRequest` descriptor falling through to the fixed-`SectionID`
arm would call `AssertSectionAccess(ctx, engine, playerID, "", action)`, which `gate.go:90-92`
refuses with `ADMIN_SECTION_REQUEST_MALFORMED` **before evaluation** — every `AdminGetSection`
call, admin or not, would fail before the handler ran. Add the arm explicitly:

- Assert `req.(interface{ GetSectionId() string })`, mirroring 06-01's
  `GetPlayerSessionToken()` assertion. `ok == false`, or an id that is empty after
  `strings.TrimSpace`, is a **new fail-closed code `ADMIN_SECTION_NO_SECTION_ID`** mapped to
  the same static `PermissionDenied` refusal — never a pass-through and never a default section.
- Call `section.AssertSectionAccess(ctx, deps.Engine, playerID, id, d.Action)` and refuse on
  error, mapping through the shared `mapAdminSectionError`.
- On success stash the returned `section.Section` in ctx behind an unexported key with an
  exported `AdminSectionFromContext(ctx)` reader.
- Make the shape switch **exhaustive with a denying default**: a descriptor carrying no
  recognised shape is refused with `ADMIN_SECTION_NOT_DECLARED`, so a fourth shape added later
  denies rather than acquiring whichever arm happened to be reachable.

**Do NOT move the gate into the handler.** D-99 replaced the per-handler assertion with the
structural declaration, and `AdminGetSection` is the single RPC in the phase whose section id is
**attacker-controlled** — the last one that should carry an exception.

`internal/grpc/admin_sections.go` — new file carrying `(*AdminPortalServer).AdminGetSection`. Because
the interceptor has already gated, resolved and stashed, the handler is thin: read
`AdminSectionFromContext`, project it onto `AdminSection`, return. It calls **no** gate helper
and **no** `section.Lookup`. A handler-side lookup would reintroduce the registry-enumeration
oracle D-06 closed; a handler-side gate call would reintroduce the D-99 exception.

Put the shared refusal mapping in one unexported `mapAdminSectionError(ctx, err) error`, placed
where **both** the interceptor and every later admin handler can call it (a shared file in
`internal/grpc`, not inside `admin_sections.go`, since the interceptor now needs it too), so
translation happens at exactly one layer:
`DENY_ADMIN_SECTION` and `DENY_ADMIN_SECTION_UNREGISTERED` and `ADMIN_SECTION_NO_SECTION_ID`
all → `status.Error(codes.PermissionDenied, adminDeniedMessage)` using the **same** package const
plan 06-01 introduced; `SECTION_NOT_IMPLEMENTED` →
`status.Error(codes.FailedPrecondition, sectionNotImplementedMessage)` with its own static const;
`ADMIN_SECTION_EVALUATION_FAILED` → `codes.Internal` with a static `"internal error"` message and
`errutil.LogErrorContext` carrying the real error. Never `%v` an inner error into a status message.

**`SECTION_NOT_IMPLEMENTED` is therefore produced by the interceptor, not the handler** — step 4
of `AssertSectionAccess` runs inside the gate call the interceptor makes. That is correct and is
what makes the planned-section refusal reachable only *after* the ABAC decision. Note the
consequence for plan 06.1-02: a `FailedPrecondition` carries a static message and **no response
body**, so the web planned-section screen cannot read display metadata from it — 06.1-02 renders
from the already-authorized `AdminListSections` layout data instead.
