**`internal/store/migrations/000057_character_admin_search_indexes.sql`** — the next free
version (000056 is the highest `.sql`; `000055` is a **Go** migration, which is the apparent
gap). SPDX header, then `-- +goose Up` creating two indexes:
`CREATE INDEX IF NOT EXISTS idx_characters_normalized_name_trgm ON characters USING gin (normalized_name gin_trgm_ops);`
and
`CREATE INDEX IF NOT EXISTS idx_players_username_trgm ON players USING gin (username gin_trgm_ops);`
Use **plain** `CREATE INDEX`, never `CONCURRENTLY` — goose wraps each migration in a
transaction and `CONCURRENTLY` would force `-- +goose NO TRANSACTION`, surrendering atomicity
for two tables this size. Do **not** re-`CREATE EXTENSION`: `pg_trgm` is a hard dependency of
`000001_baseline.sql:17`, so any deployment that can run migration 1 already has it, and
repeating it here would read as a new deployment requirement. `-- +goose Down` drops both
indexes with `IF EXISTS` in reverse order. The file contains no `$$`-quoted body, so no
`StatementBegin`/`StatementEnd` wrapper is needed; it also MUST NOT contain prose that spells
the goose annotation token, which is a hard parse error.

**`internal/world/postgres/character_repo.go`** — add two methods, both following `Get`'s full
projection and `ListAll`'s row-loop + per-stage error-code taxonomy (`*_FAILED`,
`*_SCAN_FAILED`, `*_PARSE_FAILED`, `*_ITERATE_FAILED`, `defer rows.Close()`,
`make([]*T, 0)`, terminating `rows.Err()`):

- `AdminListCharacters(ctx, opts AdminCharacterListOptions) (AdminCharacterPage, error)`
- `AdminSearchCharacters(ctx, normalizedTerm string, opts AdminCharacterListOptions) (AdminCharacterPage, error)`

`AdminCharacterListOptions` carries `SortField` (a typed enum over exactly the **five**
§11.3 Sort=Yes fields), `Descending bool`, `StatusFilter` (optional), `PlayerID` (optional

**The detail read for the edit surface — and the layer it lives at, decided here rather than
discovered** (cross-AI review C2-17). An earlier revision put `AdminGetCharacterDetail` on
`CharacterRepository` in `internal/world/postgres/character_repo.go` while telling the executor to
"follow `internal/grpc/characteraccess_owner.go`'s `ownedProfileAttributes`". Those two
instructions point at different layers and different mechanisms: `ownedProfileAttributes`
(`characteraccess_owner.go:159`) is a **gRPC-server helper** that reads through
`s.world.ListPropertiesByParent(ctx, caller, …)` — an ABAC-mediated `world.Service` call with a
deliberately chosen caller subject and an `isGovernedProfileName` filter — while raw
`entity_properties` SQL lives in a **different repository**, `internal/world/postgres/property_repo.go`.
An executor could satisfy every stated criterion either way, including a way that evaluates the
admin's own subject against per-row grid policies and returns a **partially filtered** attribute
set — which would seed the 06.1-04 Sheet with missing fields and re-create the R-21 overwrite hazard
one layer down.

**The decision: compose at the gRPC layer, from the PROPERTY REPOSITORY, not from
`world.Service.ListPropertiesByParent`.**

An intermediate revision routed the property half through
`world.Service.ListPropertiesByParent` under the admin's own **player** subject. That does not
work, and it fails **silently**, which is the worst available failure mode here (cross-AI review
C3-17). `ListPropertiesByParent` runs a `property:<id>` / `read` ABAC decision **per row** and its
own doc comment says a deny decision means the *"property [is] filtered out SILENTLY"*
(`internal/world/service.go:1774-1800`). Under the D-104 player-flavoured caller **every row is
denied**: the shipped property-read permits are all `principal is character`
(`seed.go:111-143`), `principal is viewer` (`seed.go:684-815`) or `principal is plugin`
(`seed.go:394-396`), and the only player-principal policy in the corpus is
`seed:admin-section-access`, scoped `resource is admin_section` (`seed.go:985-987`). Plan 06-05's
new `seed:admin-character-administration` does not reach it either — that policy is scoped
`resource is character`. So the caller would pass the portal interceptor and receive an **empty
property slice**, and Task 2's own Test 9 (all twelve values present) would be unsatisfiable
against the tree. It also contradicted this plan's own "no second ABAC check" statement below.

Two repairs were available. **Widening the policy corpus is rejected**: a
`permit(principal is player, action in ["read"], resource is property)` grant would let an admin
player subject read **every property row in the world** through any code path taking a player
caller — far wider than the twelve fields the edit surface needs — and it would add a *second*
seed-census edit in a *second* wave, compounding bookkeeping 06-05 already owes for one. Worse, it
leaves the silent-drop behaviour in place: a later narrowing of any property policy would blank
Sheet fields with no error, and the Sheet would then **overwrite existing content on save** —
exactly the R-21 hazard the detail read exists to close.

**So: a bounded trusted projection.**

- **No `AdminGetCharacterDetail` method is added to `CharacterRepository`.** The character
  repository does not learn to read `entity_properties`; that table belongs to
  `PropertyRepository` and giving a second repository a door to it is the precedent this codebase
  has repeatedly refused.
- `AdminCharacterReader` carries the **two** list/search methods plus `Get`. A **second**,
  one-method interface — `AdminProfileReader`, wrapping
  `ListByParent(ctx, parentType string, parentID ulid.ULID) ([]*world.EntityProperty, error)`
  exactly as `world.PropertyRepository` declares it at `internal/world/property.go:40-41` — supplies
  the property half. It is wired by `WithAdminProfileReader` at both composition roots, which
  each already construct `worldpostgres.NewPropertyRepository(pool)` inline
  (`cmd/holomush/sub_grpc.go:499`, `internal/testsupport/integrationtest/harness.go:505`).
- The detail read is assembled in `internal/grpc/admin_characters_read.go` from `Get` (the full
  character row, including `description`) plus that `ListByParent` call. **No per-row ABAC
  decision is evaluated.**
- **The name filter is `isGovernedProfileName`'s set**, reused not re-spelled — the twelve §7.2
  `profile.*` names, package-private in the same package at
  `internal/grpc/characteraccess_projection.go:238`, so it is directly callable. A property row
  outside it is dropped, and a NULL `Value` is skipped for the same reason
  `ownedProfileAttributes` skips it (`characteraccess_owner.go:176-179`): a flag-style row carries
  no value to write back and would round-trip through the edit surface as a blank the operator

**Write the authorization argument into the handler's doc block, for `abac-reviewer`, in these
terms:** the authorization for this projection is the `admin_section:characters` **read** decision

reviewed change, not an incidental one. Name the rejected alternative and why, so a later reader
does not "restore" it: routing through `world.Service.ListPropertiesByParent` would return an
empty set today and a silently-partial set under any future policy, and an edit form cannot
distinguish a silently-partial read from an empty field.
