and player usernames, a total ordering that puts `never` last in both directions, and three
gated RPCs.

search method today (`ListByPlayer` at `:340`, `ListAll` at `:708`).

Output: migration `000057`, two repository methods with the join and the three-clause
ordering, three admin read RPCs with their descriptor entries and `Web`-prefixed proxies, and
the both-directions sort test that a one-direction test cannot substitute for.

**`internal/world/postgres/character_repo.go`** — add two methods, both following `Get`'s full
projection and `ListAll`'s row-loop + per-stage error-code taxonomy (`*_FAILED`,
`*_SCAN_FAILED`, `*_PARSE_FAILED`, `*_ITERATE_FAILED`, `defer rows.Close()`,
`make([]*T, 0)`, terminating `rows.Err()`):

- `AdminListCharacters(ctx, opts AdminCharacterListOptions) (AdminCharacterPage, error)`
- `AdminSearchCharacters(ctx, normalizedTerm string, opts AdminCharacterListOptions) (AdminCharacterPage, error)`

`AdminCharacterListOptions` carries `SortField` (a typed enum over exactly the §11.3-permitted
set), `Descending bool`, `StatusFilter` (optional), `PlayerID` (optional equality filter, the
click-to-filter path), `Limit` and `Offset`. `AdminCharacterPage` carries `Rows []AdminCharacterRow`
and `TotalCount int64`. `AdminCharacterRow` embeds the full `*world.Character` plus
`PlayerUsername string`.

The SELECT reads the full character projection `Get` uses **plus** `p.username`, from
`characters c JOIN players p ON p.id = c.player_id`. The search predicate is
`(c.normalized_name ILIKE '%' || $n || '%' OR p.username ILIKE '%' || $n || '%')` with the term
bound as a **parameter** — never string-concatenated into SQL. `total_count` comes from a
`COUNT(*) OVER ()` window on the same query so the count and the page cannot disagree.

The ORDER BY is exactly three clauses and is emitted from a closed `switch` over the sort-field
enum (never from caller-supplied text):
`ORDER BY (c.last_active_at = 0), c.last_active_at {ASC|DESC}, c.normalized_name ASC`
for the `last_active_at` key, and `ORDER BY c.{col} {dir}, c.normalized_name ASC` for the
others. The **first** clause is what makes the `0` sentinel sort last in *both* directions —
descending gets it free as the column minimum, ascending does not. The **third** clause is the
tiebreak that makes the order total: without it the `never` block falls back to whatever
secondary key the plan happens to carry and the ordering is untestable. An unrecognised sort
field returns `oops.Code("CHARACTER_ADMIN_SORT_FIELD_UNSUPPORTED")` — reject, never default.

Do **not** copy `ListAll`'s projection. Its doc block at `:700-707` warns that it reads only
`id, name`, so `Status` and `LastActiveAt` are zero-valued *by omission*, and a lifecycle
decision from that result violates INV-WORLD-5.

Normalization: the term is passed to the repository **already normalized** by the service
layer through the same `charname` function that produces the stored `normalized_name`. The
repository does not normalize and does not lower-case; there is exactly one normalizer.
