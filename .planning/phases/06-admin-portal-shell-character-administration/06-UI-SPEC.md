# Phase 6 — UI Design Contract

> Visual and interaction contract for the admin portal shell, the character administration
> table, the edit Sheet and its mutation loop, the planned-section state, and the single root
> not-found boundary. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Upstream authority.** `06-CONTEXT.md` (D-99…D-110), `06-RESEARCH.md`, `01-SPEC.md` §9–§11,
`.claude/rules/branding.md` and `.claude/skills/sketch-findings-holomush/` are normative and
already settle most of this phase. This document adds only the *visual and interaction*
contract on top of them, and resolves the items CONTEXT.md assigned to Claude's Discretion.
Where this document and CONTEXT/SPEC appear to disagree, CONTEXT/SPEC wins and this document
is the bug.

**Continuity with Phase 5.** `05-UI-SPEC.md` is the shipped sibling contract. Phase 6 reuses
its spacing scale, its palette discipline and its accent-list method verbatim. Where Phase 6
*diverges* (it introduces three component idioms Phase 5 explicitly declined), the divergence
is named and scoped below — it is not a silent reversal, and it does **not** retrofit Phase 5.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn-svelte (already initialized — `web/components.json`) |
| Preset | style `nova`, baseColor `slate`, aliases `$lib/components/ui` |
| Component library | `bits-ui` 2.18.1 headless primitives (the Svelte analogue of radix) |
| Icon library | `@lucide/svelte` 1.25.0 — **the only icon dependency.** shadcn-svelte's own docs for `empty` show `@tabler/icons-svelte`; that import MUST be rewritten to `@lucide/svelte` when the component is generated. A second icon package is not added. |
| Font | App chrome: `-apple-system, 'Inter', system-ui, sans-serif` (`app.css` `@layer base`). No new face. Monospace (`JetBrains Mono`) is terminal-only and appears **only** in the character-id metadata line of the Sheet header (see Typography). |
| Styling | Tailwind v4 utilities for layout/spacing + `var(--color-*)` custom properties for all color |

**Tailwind v4 gotcha (binding).** `@theme` compiles `var()` at **build time**. Never put a
`var()` reference inside `@theme` for a value that changes at runtime. All new color use reads
`var(--color-*)` in scoped CSS or the matching Tailwind utility (`bg-card`,
`text-muted-foreground`) — never a hardcoded hex (`web/CLAUDE.md`).

### Component inventory — ten added, one added beyond the locked ten, several declined

**The locked ten** (ROADMAP Phase 6 sketch-findings line; `06-CONTEXT.md`; `foundations.md`).
Install with `cd web && pnpm dlx shadcn-svelte@latest add <name>` (`web/CLAUDE.md:111`), then
confirm each generated file matches the `nova` style already in `web/src/lib/components/ui/`.

| Component | Used for | Binding constraint |
|-----------|----------|--------------------|
| `table` | the character list | The **operator** idiom. MUST NOT be used for any player-owned list — Cards stays the player idiom (`foundations.md`, "two idioms, deliberately"). |
| `pagination` | 412 characters | Page size **50**. See Layout → the table. |
| `empty` | the planned-section state; the table's two non-data states | `Empty.Media variant="icon"` takes a `@lucide/svelte` glyph. No `Empty.Content` action on the planned-section state — that state has no next step. |
| `alert` | the version-conflict banner inside the Sheet | **Only** carrier of `--color-destructive` in this phase besides the retire confirm button. Not used for the planned-section state (that is `empty`), and never for an informational notice. |
| `avatar` | the rail-foot identity block at ≤1023px | **`Avatar.Fallback` only. `Avatar.Image` is never rendered** — no media path exists in v0.13 and the operator has no portrait. It renders the same tinted initial plate Phase 5 unified across surfaces (16% primary fill, 32% primary border, letter in `--color-primary`). |
| `breadcrumb` | `Admin › Characters` | Two levels, never three — there is no third level in v0.13 (the Sheet is an overlay, not a route). |
| `skeleton` | the table loading state | Permitted **here** and only here. Phase 5 declined `skeleton` because a field-shaped skeleton pre-announces a response shape a *privacy-partitioned* response may not have. The admin list is explicitly **not** privacy-partitioned (§11.3's own safety test), so the objection does not reach it. It MUST NOT be introduced on any `profile.*` surface. |
| `select` | the **status filter** | **Never a sort control.** §11.3 names "a sort control whose options are drawn from the §7.2 field list" as *the* warning sign. Sorting is click-header only. There is exactly one `select` in this phase. |
| `field` | the edit Sheet's two field groups | Scoped to the admin Sheet. It does **not** retrofit Phase 5's authoring forms (see divergence note). |
| `sonner` | the post-mutation toast (D-110) | Pulls the npm dependency `svelte-sonner` (name is CLI-determined, not plan-determined — `06-RESEARCH.md` A3). One `<Toaster />` mounts once, in the admin layout. |

**One addition beyond the locked ten — `alert-dialog`.**
`foundations.md` names it separately from the ten (*"Also needed: `alert-dialog` (the retire
confirmation)"*), so this is a gap in the enumerated list rather than a contradiction of it.
It is added because the retire/un-retire confirmation is a modal that **requires** a decision
and MUST NOT be dismissible by backdrop click — that is precisely the `alertdialog` role,
and `dialog` (installed) does not carry it. Reusing `dialog` would ship a confirmation for an
audited mutation on a character the operator does not own that a stray backdrop tap can
silently cancel.

**Explicitly declined — the planner MUST NOT add these:**

| Declined | Reason |
|----------|--------|
| `data-table` / TanStack Table | The table has five columns, one sort key at a time, one page size and no column reordering. A headless table engine is a dependency and a second sorting vocabulary for a surface whose sorting is deliberately constrained to six server-side fields. |
| `command` for a section jump | Already installed and already carries the palette. Phase 6 adds **no** admin entries to it — palette membership flows through `visibleSections()`, and `/admin` deliberately never enters that registry (see Layout → the not-found page). |
| `drawer` / `vaul-svelte` | The only reason to add it is drag-to-dismiss on the phone bottom-sheet, which **D-109 drops**. `Sheet side="bottom"` is a prop at a breakpoint, not a second component. |
| `progress`, `spinner` | Loading is `skeleton` rows (table) or a disabled `aria-busy` button (submit). No spinner ships in this phase, matching Phase 5. |
| `toggle-group` for the status transition | The transition control is a `select` inside the Sheet with one legal option and one permanently-disabled option; a toggle group implies both are reachable. |

| Component | Phase 5 | Phase 6 | Why the difference holds |
|-----------|---------|---------|--------------------------|
| `sonner` / toasts | Declined; success is a persistent inline `role="status"` region | **Added** | D-110 requires a receipt that **names the RPC**, because an admin is acting on a character they do not own and it is audited under their player id. `foundations.md`: *"narration is wrong on read surfaces and right on audited write surfaces."* Phase 5's inline regions are **unchanged** — sonner does not replace them. |

## Typography

Exactly **4 sizes, 2 weights**. Three of the four sizes are the same values `05-UI-SPEC.md`
declared (12 / 14 / 20); the fourth (16) exists solely to satisfy a platform constraint and
appears nowhere except a focused input below 768px.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Dense | 12px | 400 | 1.4 | **Table cell text** (name, player, status, `Last active`, `Created`, `Ver`), the Sheet's `Managed elsewhere` collapsed summary line, the character-id metadata line in the Sheet header, the toast body, pagination range text |
| Label | 12px | 600 | 1.4 | Table column headers, nav item labels, the `planned` badge, group headers (`Managed elsewhere` / `Editable here`), field labels in the Sheet, breadcrumb, the rail-foot avatar initials |
| Body | 14px | 400 | 1.5 | Sheet input values, the retire-confirm dialog body, the conflict-banner text, the planned-section line, the not-found body, the empty-state bodies |
| Heading | 20px | 600 | 1.2 | The `<h1>` of each admin section, the Sheet title (`Edit character`), the confirm-dialog title, the planned-section name, the not-found `Not found` |

Rules:

- **Two weights, full stop:** 400 and 600. The sketches' `font-weight: 700` is pinned to 600.
- **12px is the floor.** No 11px, no 11.5px, no 10.5px; every sub-12px sketch value collapses
  into the 12px sizes above. 12px `--color-status-text` on `--color-card` measures 7.5:1
  (AAA for body, comfortably AA at 12px) — see Color.
- **Two roles share 12px on purpose.** `Dense` (400) is data; `Label` (600) is chrome. The
  weight is what separates a value from its header in a table this tight. This is still 4
  sizes and 2 weights.
- **Monospace is confined to one string:** the character ULID in the Sheet header metadata
  line (`01JQ7X…8F2 · v7`). It is an opaque identifier an operator may need to copy, which is
  the one legitimate monospace case outside the terminal. Everything else — including the
  `update_mask: N paths` footer and the toast — is the system sans-serif.
- **Phone-band input exception (platform constraint, not a style preference).** Any font
  `<16px` in a **focused** input triggers iOS Safari's zoom-on-focus, which does not unzoom on
  blur. Inside `@container vp (max-width: 767px)` **only**, every `input`, `textarea` and
  `select` in the Sheet and in the table's filter bar renders at **16px/400/1.5**. This is the
  fourth declared size and it has exactly this one use. It rides in the *same* container-query
  block as the `side="bottom"` flip — one block, two rules — so a reader cannot honor one and
  miss the other.

## Color

The palette is fixed by `web/src/app.css` `@theme` and `.claude/rules/branding.md`. **This
phase introduces no new token.**

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--color-background` | `#0b0c0e` | Page ground; the content column; the table body |
| Secondary (30%) | `--color-card` / `--color-surface` / `--color-sidebar` | `#101418` | The section rail, the admin nav column, the Sheet, the toast, the confirm dialog, the table's sticky header block; `--color-border` `#1d2a33` hairlines between them |
| Accent (10%) | `--color-primary` / `--color-ring` | `#3dd6f7` | See the reserved-for list below |
| Muted text | `--color-status-text` / `--color-muted-foreground` | `#9aa7b2` | Column headers, the `planned` badge, `Last active` values, `Created`, `Ver`, the collapsed `Managed elsewhere` summary, the `update_mask` footer, the planned-section line, breadcrumb, pagination range, the not-found body |
| Destructive | `--color-destructive` | `#fc7f7f` | **Exactly two places:** the version-conflict `alert` (border + text) and the retire confirm dialog's confirm button. Nothing else. |

**Accent reserved for — the complete list. Anything not on it is not accent:**

1. The **focus ring** on any input, button, link, nav item, sortable header or table row
   (`--color-ring`, same hex).
2. The **active-item bar and label** in the admin nav column, and the rail's shipped active bar
   (`SectionRail.svelte` treatment, unchanged).
3. The `Admin` rail button's **`is-context` tint** at ≤1023px — primary tint at 0.7 opacity,
   **no bar** (the bar belongs to the section you are actually on).
4. The **rail-foot avatar plate** at ≤1023px: `color-mix(in srgb, var(--color-primary) 16%,
   transparent)` fill, `color-mix(… 32% …)` border, initials in `--color-primary`. Identical
   treatment to Phase 5's portrait, so the two halves read as one system.
5. The Sheet's primary **`Save`** button — solid `--color-primary` on
   `--color-primary-foreground`.
6. The **sorted-column indicator** in the table header (the caret and its header label).
7. The **post-update row flash** — the shipped `just-arrived` keyframe, which is already
   `color-mix(in srgb, var(--color-primary) 12%, transparent)` (`app.css:103-106`). Reused,
   not re-authored, and it stays inside the shipped
   `@media (prefers-reduced-motion: no-preference)` guard.

**Not accent, explicitly:** the `planned` badge (muted), the lifecycle `status` cell, the
`Retire…` / `Un-retire` row action, the `Edit` row action, the toast (surface + muted text),
the breadcrumb, the pagination controls, the `Managed elsewhere` group and its summary, the
planned-section glyph and copy, the not-found glyph and destination links, the search input,
the status `select`, `Last active` values.

**Amber is forbidden.** `--color-cursor` `#ffb300` is the **cursor only** (`branding.md`
INV-1). It MUST NOT appear as an accent, link, button, badge, status color, warning color or
highlight anywhere in this phase. In particular the `planned` badge is **not** a warning and
takes muted text on a hairline border, not amber.

**No green, and no session vocabulary, on this surface.** `--color-status-online` `#7fd98f`
(Phase 5's session badge) MUST NOT appear in the admin portal. The table's `status` column is
**lifecycle** (`active | retired | idle`); Phase 5's badge is **session** state. The two
vocabularies collide on the token `active` (`anti-patterns.md` §15), and this table is the
one surface where an operator could plausibly read a green dot as "connected right now" — the
exact misreading D-107 renames the neighbouring column to avoid. The admin table renders **no
session badge, no presence dot, and no colour-coded status**: `status` is muted text carrying
the word.

**No hardcoded brand string.** `HoloMUSH` MUST NOT appear in any copy written by this phase
(INV-6). The game's own display name is server-side-only (#4905). The one permitted "back"
target is the word `Home`.

**Contrast, computed against `--color-card` `#101418`:**

| Pair | Ratio | Verdict |
|------|-------|---------|
| `--color-foreground` `#e8edf2` | 15.0:1 | AAA |
| `--color-status-text` `#9aa7b2` | 7.5:1 | AAA for body, AA at 12px |
| `--color-primary` `#3dd6f7` | 10.7:1 | AAA |
| `--color-destructive` `#fc7f7f` | 7.5:1 | AAA |

Every text/background pair in this phase MUST come from that table or exceed 4.5:1. **Colour
is never the sole carrier of meaning:** the sorted column carries a caret glyph as well as the
accent, the `planned` badge carries the word, the conflict `alert` carries text and both
version numbers, the retire confirm carries its full body copy.

## Surfaces & Routes

| Path | Route group | Auth posture | Delivers |
|------|-------------|--------------|----------|
| `/admin` | `(authed)` | admin (ABAC on `admin_section:`) | Redirects/renders the first permitted section — in v0.13 always `characters` |
| `/admin/characters` | `(authed)` | admin | The character table, its filters, and the edit Sheet overlay |
| `/admin/{stats,players,moderation,audit,config,plugins}` | `(authed)` | admin | The minimal planned-section state (003-A) |
| `web/src/routes/+error.svelte` | **root, exactly one** | any | The ordinary not-found (010-B) |

**The Sheet is an overlay, never a route.** There is no `/admin/characters/[id]`. That is a
deliberate scope reduction (006 rejected variant C for exactly this): a routed edit surface
becomes deep-linkable, which drags the not-found obligation into the edit surface. Recorded
here so it is inherited rather than re-derived.

**`/admin` is invisible without permission.** No rail icon, no nav entry, and a deep link to
any `/admin/*` path renders the **ordinary** not-found — never a redirect, never a bespoke
"forbidden" page. `adapter-static` + `fallback: 'index.html'` already makes every unknown path
HTTP 200 + `index.html`, so indistinguishability is structural at the HTTP layer and only has
to be maintained in the client render.

**UX invisibility is never the boundary.** The ABAC gate is (§10.4). Hiding the entrance
*concentrates* the denial path onto callers deliberately bypassing the UI; it does not remove
the need for the RPC to deny. No `+layout.ts` guard may be described, in code comments or
acceptance text, as the access control.

## Layout

### Responsive — the three-column frame (001/C2)

Breakpoints are **container queries** against a
`container-type: inline-size; container-name: vp` wrapper on the admin shell — never media
queries. The shell is a bounded region inside the app, not the viewport.

| Container width | Rail | Admin nav | Content | Sheet |
|-----------------|------|-----------|---------|-------|
| **≥ 1024px** | 48px icons | 232px, labels + `planned` badges | full table (5 columns) | 380px right overlay |
| **768–1023px** | 48px icons | **merged into the rail** below a divider | full table (5 columns) | 380px right overlay |
| **< 768px** | width 0 | width 0 | `.mobilebar` (hamburger + breadcrumb); `Created` and `Ver` columns drop | `side="bottom"`, 84% height |

Two merge fixes are load-bearing and both are **scoped inside `@container vp (max-width:
1023px)`** — a global `.is-context` strips the active bar at full width, where it is the only
location signal:

1. `.rail-btn.is-context` — the `Admin` button keeps its primary tint but **surrenders the
   active bar** to the section you are on. Two "you are here" bars in one column at two
   hierarchy levels reads as a bug.
2. `.rail-identity` — the identity block orphaned by `.adminnav { width: 0 }` returns at the
   rail foot, rendered **only** at the collapsed breakpoint so it never duplicates the nav's
   own copy at ≥1024px.

**Two hazards the executor must handle — both are concrete, both are cheap:**

| Hazard | Detail | Required handling |
|--------|--------|-------------------|
| **The Sheet is portalled outside the container** | `sheet-content.svelte:31` wraps its content in `<SheetPortal>`, which renders to `document.body` by default — **outside** the `vp` container. A `@container vp (max-width: 767px)` rule would then never match, and the `side="bottom"` flip and the 16px input rule would both silently no-op. | Pass `portalProps={{ to: <the vp shell element> }}` on `Sheet.Content` so the overlay renders inside the container. The prop already exists (`sheet-content.svelte:24`). Verify at 375px that the Sheet is a bottom sheet — a green build proves nothing here. |
| **The shipped rail is on a media query** | `SectionRail.svelte:114` uses `@media (max-width: 767px)`. The admin nav will be on `@container vp`. At any width where the two disagree (the shell is inset from the viewport by any amount), the rail and the admin nav collapse at different moments. | Either the shell wrapper is full-bleed so container width == viewport width at this breakpoint, or the rail's own 767px rule is migrated to the same `@container vp`. Decide in the plan; do not leave it to coincidence. |

### `/admin/characters` — the table (002/A)

```
Admin › Characters                                        ← breadcrumb (Label)
Characters                                                ← h1 (Heading)

[ Search characters and players        ] [ Status ▾ ]     ← filter bar
1–50 of 412                                               ← range (Dense, muted)

┌ Name ▲ │ Player │ Status │ Last active │ Created │ Ver ┐ ← Label, click-to-sort
│ …      │ …      │ …      │ 2h ago      │ …       │ 7   │ ← Dense
│  ⋯ hover ⇒ [ Edit ] [ Retire… ]                        │
└───────────────────────────────────────────────────────┘
[ ‹ 1 2 3 … › ]                                           ← pagination
```

- **Sorting is click-header only.** No sort dropdown, no facet panel — §11.3 names those as
  *the* warning sign, because the field list is the privacy-bearing set. Sortable columns are
  exactly: `Name`, `Player` (the joined `players.username`, per A2), `Status`, `Last active`
  (per A1), `Created`. **`Ver` is not sortable** — it is not a §11.3 field and it is a
  concurrency guard, not an ordering.
- **One `select`, and it filters `status`.** Options: `All`, `Active`, `Retired`, `Idle`.
  `Idle` is listed because it is a real lifecycle value that could exist in data; listing it
  in a **filter** does not put it on a mutation wire, which is what §10.6 prohibits.
- **Search is substring** (D-106), over the stored normalized character name and the joined
  `players.username`. The client sends the raw typed string and does **no** normalization —
  a client-side TypeScript mirror of `charname.Normalize` is forbidden for the same reason
  Phase 5 forbade it (two sources of truth for a security-adjacent normalizer). Debounce
  **250ms**; no minimum length gate.
- **Player name is click-to-filter** (equality) — already permitted by §11.3's `player_id`
  row and unchanged by A2.
- **`total_count` is safe here and only here.** The admin list is not privacy-partitioned;
  its audience already sees every field it could order by. This MUST NOT be cited as
  precedent for a count on the public directory.
- **Row actions, resolved (this closes 006's open call):**

| Band | Affordance |
|------|-----------|
| ≥768px | Hover reveals **exactly two**: `Edit` and `Retire…` (or `Un-retire` when the row is retired). **No `⋯` overflow menu** — there is no third action in v0.13 (no delete, no rename), so an overflow trigger would be an affordance with nothing behind it. |
| <768px | **No action cluster is rendered** (there is no hover). The **row itself** is the tap target and opens the edit Sheet. Retire is reached from inside the Sheet's transition picker, which is where it lives on every band anyway. |

  Both entry points route to the **same** confirm dialog and send the **same** RPC. Two
  entrances, one component, one mutation.

- **`Created` and `Ver` drop below 768px, and `Ver` is not relocated** (this closes the other
  006 open call). The Sheet header carries `v{n}` at the moment the operator opens the editor,
  and the conflict `alert` names **both** version numbers at the moment a conflict occurs.
  Those are the only two moments the value is load-bearing, and both are covered.
- **`Last active` renders as coarse relative text** (D-107), labelled **`Last active`** —
  never `Online`, never `Last seen`. Buckets are fixed here (CONTEXT assigned granularity to
  discretion):

| Stored value | Renders |
|--------------|---------|
| `0` | `never` |
| < 1 hour | `< 1h ago` |
| 1–23 hours | `{n}h ago` |
| 1–29 days | `{n}d ago` |
| 1–11 months | `{n}mo ago` |
| ≥ 12 months | `{n}y ago` |

  **No `title` tooltip carrying an absolute timestamp.** The value lags by up to one flush
  interval (AR-03-03); a precise stamp behind a hover reads as more authoritative than the
  data is, which is the exact failure coarse text exists to avoid. `never` sorts **last in
  both directions** — that is a server contract, restated here because the UI must not
  re-sort client-side to "fix" an ordering it thinks looks wrong.
- Pagination page size **50**. Range copy `{start}–{end} of {total}`.

### The edit Sheet (004/C, 005-A, 006-B, D-109, D-110)

```
┌ Edit character                                    [×] ┐  ← Heading + close
│ 01JQ7X…8F2 · v7                                       │  ← mono, Dense, muted
├───────────────────────────────────────────────────────┤
│ ▸ Managed elsewhere                                   │  ← group header, COLLAPSED
│   Name Ashwood, Miren · Status active   managed by …  │  ← Dense summary, ~30px
│                                                       │
│ Editable here                                         │  ← group header
│   [ 13 maskable profile fields ]                      │  ← Field.FieldGroup
├───────────────────────────────────────────────────────┤
│ update_mask: 2 paths          [ Cancel ] [ Save ]     │  ← footer; Save inert if empty
└───────────────────────────────────────────────────────┘
```

- `Managed elsewhere` is **first and collapsed**. The exclusions are declared before the form,
  costing ~30px instead of ~120px. Expanding shows `Name` and `Status` as full rows with their
  own actions.
- **`version` is header metadata, never a row and never editable.** It is the concurrency
  guard carried as `expected_version` (§9.4); a row alongside `Name`/`Status` would imply a
  door that does not exist.
- **The status control is a transition picker that never sends a status value.** Selecting
  `Retired` sends `AdminRetireCharacter`; selecting `Active` sends `AdminUnretireCharacter`.
  `idle` **appears and is permanently unselectable** (dimmed, with the reason). Selecting a
  transition does not apply it — it routes to the confirm dialog, which is where the RPC is
  sent. The control's own footnote states this literally (see Copywriting), because this is
  exactly the control an implementer would otherwise wire to a `status` field.
- **The mask is visible and an empty mask is inert.** The footer shows `update_mask: {n}
  paths` or `update_mask: empty — no-op`; `Save` is `disabled` until something changes.
- **Geometry: one shape, one override.** 380px right overlay at every band, plus exactly one
  `@container vp (max-width: 767px)` block flipping it to `Sheet side="bottom"` at 84% height
  and raising input font to 16px. A prop at a breakpoint, not a second component.
- **No grab handle** (D-109). `bits-ui` has no swipe-dismiss, so a handle would promise a
  gesture the component cannot honor. Closing is: backdrop tap, `Escape`, the `×`, and
  `Cancel`. All four MUST work at every band.

### The mutation loop (D-110 — binding sequence)

| Step | Success path | `Aborted` (version conflict) path |
|------|--------------|-----------------------------------|
| 1 | `Save` becomes `disabled` + `aria-busy="true"`, keeping its label | same |
| 2 | Row enters a pending state | same |
| 3 | **The Sheet closes** | **The Sheet stays open** |
| 4 | The row updates **in place from the response** — never a refetch — and flashes via the shipped `just-arrived` keyframe | The typed text is **preserved**, every field of it |
| 5 | The toast fires, **naming the RPC** | The conflict `alert` renders inline with the fresh version; focus moves to the first conflicting field. **No toast — nothing finished.** |

This mirrors Phase 5's D-93 exactly (verified live in `05-UAT.md` test 3). The toast is the
receipt for a **finished** action, so a Sheet still open behind it would be ambiguous, and the
Sheet's `version` header metadata would already be stale.

### The planned-section state (003/A)

Glyph, section name, one line: `Registered and gated. No handler yet.` Nothing else.
Centred and vertically anchored (naturally responsive; 006 confirmed it survives narrowing
for free). **No gate trace, no authorization provenance, no scope preview** — five of the six
planned sections have no documented scope anywhere in the SPEC, so a scope panel would be
*invented* for five of six, and plausible UI copy is read back as a requirement by the next
planner.

### The not-found page (010/B) — one root `+error.svelte`

```
[glyph]
Not found
We couldn't find that page.

Home · {the viewer's own sections from visibleSections()}
```

- **Exactly one `+error.svelte`, at `web/src/routes/`.** SvelteKit resolves the *nearest*
  boundary; a second one (e.g. `routes/admin/+error.svelte`) destroys the indistinguishability
  three surfaces rest on, silently, in a one-file PR that looks harmless. Ship the meta-test
  asserting the count is **== 1** — enumerate files and assert length, never `rg -c` (which
  counts matching lines and also passes at zero).
- **The renderer takes no reason parameter.** It often *could* know why it is rendering (an
  RPC denied). If it has nothing, a future change cannot surface it.
- **No path echo.** Echoing `/admin/moderation` confirms the string was routed somewhere.
- **`/admin` MUST NOT appear in the destination list, and MUST NOT be added to `SECTIONS`.**
  Two reasons, both binding: (a) putting an admin entry in `web/src/lib/nav/sections.ts` with
  a client-side visibility gate is precisely the mirrored-client-registry hazard D-101 and
  §10.1 Pitfall 7 forbid, and it would mean widening `SectionVisibility` beyond `isGuest` —
  a security-adjacent default that #4962 says must not change incidentally inside a UI phase;
  (b) the destination list must never become an authorization probe. The list is exactly
  `Home` + `visibleSections(viewer)` as shipped. The rail's `Admin` entry is drawn separately,
  from `roles` on `WebCheckSessionResponse` (D-102), by the rail itself.
- **Indistinguishability is per-viewer, not global.** An admin hitting `/admin/moderation`
  *should* see the planned-section state — that is the gate permitting them. Requiring global
  sameness would forbid ever showing an admin their own screen.
- **Ship the negative control.** The opacity test MUST be demonstrated **red** against a
  deliberately-divergent render (010's `☣ inject leak` shape) before its green is trusted. In
  a correct implementation the renderer does not branch on which kind of miss occurred, so the
  paths are identical *by construction* and a naive assertion passes trivially.
- **Zero permitted sections ⇒ the ordinary not-found.** If `AdminListSections` returns an
  empty set for a caller it did not deny, `/admin` renders the same not-found as a denial.
  This is unreachable in v0.13 (the seed policy is resource-**type** scoped, so the permitted
  set is all-or-nothing) but the branch must exist and must not render a distinct state.
  Sketch 003's `No sections available.` nav copy is therefore **declined** — it was authored
  before `/admin` became invisible-without-permission and it is a third rendering of "nothing
  here" that the locked decision removed.

### The phone drawer (006)

Below 768px the drawer holds **rail sections and admin sections together**, separated by a
divider and **two group labels** — those labels do the hierarchy work `.rail-btn.is-context`
does at 768–1023px, and a flat merged list has no equivalent device. The labels are
**`Workspace`** and **`Admin`**. `Workspace` matches the in-repo type name
(`WorkspaceSection`, `nav/sections.ts:23`). **The game's name is never a group label**
(INV-6, and it reaches no web surface anyway — #4905).

Terminology is binding (`.claude/rules/terminology.md`): **character**, **player**,
**session**, **connection**, **location**. Never "room", "user", "avatar", "account".

milestone's convention and a bare verb would read as a regression against its sibling.

### Static explanatory copy

| Element | Copy |
|---------|------|
| Collapsed `Managed elsewhere` summary | `Name {name} · Status {status}` + right-aligned `managed by their own operations` |
| Expanded `Name` row reason | `Names go through the normalization pipeline and a uniqueness check, so they are not editable from this form.` |
| Expanded `Status` row reason | `Use the lifecycle control below — it sends the transition, not a status value.` |
| Lifecycle control footnote (always visible) | `Sends AdminRetireCharacter — never a status value.` (or `AdminUnretireCharacter` when the character is retired) |
| `idle` option, permanently disabled | `idle — system-invoked on inactivity. Not implemented in this release.` |
| Sheet footer, dirty | `update_mask: {n} paths` |
| Sheet footer, clean | `update_mask: empty — no-op` |
| `planned` nav badge | `planned` |

**Copy that asserts a property of the system is a claim and must be grounded.** Do not write
"permanent", "cannot be undone", "deleted", "removed" or "always" anywhere in this phase. The
properties that actually hold are *reserved*, *reversible* and *not hidden*.

### Empty states

| Element | Copy |
|---------|------|
| **Planned section** (six of seven) | Name (Heading) · `Registered and gated. No handler yet.` **No action, no glyph label, no scope, no gate trace.** |
| Table — **no results** (filters applied) | Heading `No characters match those filters.` · body `Try a different search or clear the status filter.` · action `Clear filters` |
| Table — **zero characters** (the game has none) | Heading `No characters yet.` · body `Characters appear here once players create them.` · **no action** — an admin cannot create a character for a player, and a CTA with nothing behind it is an invented promise. |
| Admin nav with zero permitted sections | **Not rendered at all** — the route renders the ordinary not-found instead. See Layout. |

**`no results` and `zero characters` are deliberately different states with different copy and
different actions. Do not collapse them.**

### Loading states

| Element | Copy |
|---------|------|
| Table | `skeleton` rows matching the live column count for the current band (6 at ≥768px, 4 below), inside a `role="status"` region labelled `Loading characters…` for assistive tech. **No spinner.** |
| Sheet open | The Sheet opens already populated from the row's loaded data — there is no fetch on open, so there is no loading state. |
| In-flight submit | The button keeps its label, becomes `disabled` and gains `aria-busy="true"`. **No label swap to "Saving…"** (it reflows the button) and no spinner. |

### Error states

**Branch rule, binding.** The client branches on **exactly two** conditions and no others:
gRPC `Aborted` (oops `WORLD_CONCURRENT_EDIT`) → the inline conflict `alert`; gRPC
`PermissionDenied` on any `/admin/*` load → the **ordinary not-found render**. Everything else
→ the generic error copy. It MUST NOT branch on `DENY_ADMIN_SECTION` vs
`DENY_ADMIN_SECTION_UNREGISTERED`, must never surface either string, and must never render a
"forbidden" or "access denied" state — that is the single most natural thing an implementer
would write and it is exactly the disclosure the design exists to close.

| Element | Copy |
|---------|------|
| Version conflict (`Aborted`), inline `alert` in the open Sheet | `Someone else edited this character. Your copy is version {mine}; the server is now at {theirs}. Your changes were not applied — reload to see the current values, then re-apply.` + a `Reload` control. **The Sheet stays open and every typed value is preserved.** |
| Save — any other failure | `Couldn't save. Try again.` |
| Retire / un-retire failure | `Couldn't change this character's lifecycle. Try again.` |
| Table load failure | `Couldn't load characters. Try again.` + a `Try again` control |
| Search / filter request failure | `Couldn't run that search. Try again.` |
| Any `/admin/*` denial | The **ordinary not-found** (`Not found` / `We couldn't find that page.` / `Home` + the viewer's sections). No path echo, no reason, no code. |
| Not-found page (all four kinds of miss) | Heading `Not found` · body `We couldn't find that page.` · destinations `Home` + `visibleSections(viewer)` |

**No internal code, message or wrapped error text is ever rendered** (`.claude/rules/grpc-errors.md`).
The conflict copy is the one place a *number* from the server reaches the screen, and both
numbers are versions, which the table already shows.

### Success states — the toast names the RPC (D-110)

| Mutation | Toast |
|----------|-------|
| `AdminUpdateCharacter` | `AdminUpdateCharacter · update_mask: {n} paths · v{old} → v{new}` |
| `AdminRetireCharacter` | `AdminRetireCharacter · {name} · v{old} → v{new}` + an `Undo` action |
| `AdminUnretireCharacter` | `AdminUnretireCharacter · {name} · v{old} → v{new}` |

- **The `Undo` on retire sends `AdminUnretireCharacter`** — never a status value — carrying
  `expected_version` = the **new** version from the retire response. It is the same RPC the
  transition picker sends, through the same code path.
- **Why the technical copy is not the mistake 001 and 003 rejected.** Those rejected
  implementation detail on *read* surfaces. This is an admin acting on a character they do not
  own, recorded to the audit log under their player id (§10.7). Naming the wire call is
  *accountability*, not debug output — the operator is told exactly what was written under
  their name. The rule: **narration is wrong on read surfaces and right on audited writes.**
- Toast duration **6s** (longer than the 4s default — this is a receipt, and the `Undo` needs
  a usable window). It is dismissible, and it MUST NOT be the only place the outcome is
  visible: the row already updated in place.

### Destructive confirmation (D-108 — four fixed clauses, wording resolved here)

The four required clauses are locked by D-108; the phrasing was assigned to discretion. This
copy is **retire-specific and is NOT Phase 5's not-retroactive string** — that string
addresses a player choosing what to reveal about their own profile, which an admin is not. The
misconception this actor is likeliest to hold is that retire is a takedown.

**Retire — `alert-dialog`:**

| Slot | Copy |
|------|------|
| Title | `Retire {name}?` |
| Body | `Retiring takes this character out of active play. It does not hide them — their public profile stays visible and everything they have already posed or played in is unchanged. The name stays reserved. You can undo this at any time.` |
| Confirm | `Retire character` (`--color-destructive` background) |
| Cancel | `Cancel` |

Clause map, so a reviewer can check all four landed: *out of active play* → sentence 1;
*not hidden* → sentence 2 (profile + published history); *name stays reserved* → sentence 3;
*undoable* → sentence 4.

**Un-retire — `alert-dialog`:**

| Slot | Copy |
|------|------|
| Title | `Return {name} to active play?` |
| Body | `This character becomes playable again. Their public profile and history are unchanged.` |
| Confirm | `Un-retire character` (primary, **not** destructive) |
| Cancel | `Cancel` |

**Un-retire confirms too, and that is deliberate:** both directions are audited mutations by an
operator on a character they do not own, and the transition picker's contract is that
selecting a transition *routes to the confirmation* rather than applying it.

**There is no delete in this portal.** There is no `AdminDeleteCharacter` RPC; §4.4 and §10.6
both forbid wiring `world.Service.DeleteCharacter` to an admin button. No copy, tooltip,
menu item, disabled control or `aria-label` in this phase may contain the words *delete*,
*remove*, *purge* or *erase* as an action on a character.

## Accessibility & Interaction

| Requirement | Rule |
|-------------|------|
| Form `name` attributes | Every input, textarea and select carries `name` (Playwright, `web/CLAUDE.md`). Submit buttons carry `type="submit"`. |
| Icon-only controls | Every control whose visible content is an icon alone carries an accessible name — the 48px rail section buttons, the `Admin` rail button, and the `.mobilebar` hamburger. Use visually-hidden text inside the button (not `aria-label`) wherever the name should also be available to a translation pass, and `aria-expanded` on the hamburger. An unlabelled icon trigger is announced as "button" and is unusable by screen reader; the rail is the one place in this phase where an affordance has no adjacent text to borrow. |
| Sortable headers | `<th>` contains a real `<button>` with `aria-sort` on the `<th>` (`ascending`/`descending`/`none`). The sort state is not conveyed by the caret colour alone. |
| Row actions | Hover-revealed actions MUST also appear on **keyboard focus within the row** (`:focus-within`), or they are unreachable without a pointer. Below 768px they are not rendered and the row is a real `<button>`/link. |
| Sheet | `bits-ui` Dialog semantics: focus trapped, focus returns to the invoking row action on close, `Escape` closes. `Sheet.Title` and `Sheet.Description` are always present (bits-ui warns otherwise). |
| Confirm dialog | `alert-dialog` role — **not dismissible by backdrop click**. Initial focus lands on `Cancel`, not on the destructive confirm. |
| Toast | `sonner` renders a polite live region. The toast is **never the sole carrier** of the outcome — the row already updated in place, so a missed toast loses nothing. |
| Status regions | Table load and mutation outcomes announce via `role="status"` (polite); the conflict `alert` uses `role="alert"` (assertive). |
| Focus | Visible ring on every interactive element (`--color-ring`); never `outline: none` without a replacement. On a conflict, focus moves to the first conflicting field. |
| Motion | The row flash reuses the shipped `just-arrived` keyframe inside the shipped `@media (prefers-reduced-motion: no-preference)` guard (`app.css:98-110`). The Sheet slide is `bits-ui`'s own transition. **Any new animation joins that guard rather than adding its own**, and transitions name their properties — never `all`, so the guard cannot silently stop covering a property added later. |
| Colour independence | No state is signalled by colour alone (see Colour). |
| Touch | Every interactive target has ≥44×44px of hit area at every band, padding included. |
| Text scaling | The table must remain usable at 200% browser zoom: columns wrap rather than force horizontal scroll of the whole page; the sticky header stays sticky. |

## Anti-Pattern Guard (executor checklist)

Each of these was made or nearly made in the sketch corpus, or is named by the SPEC as the
reflexive instinct. Reintroducing any is a bug, not a taste call.

- [ ] No `Last seen` / `Last login` column, and no absolute-timestamp tooltip on `Last active`.
- [ ] No sort dropdown and no facet panel — click-header sorting only.
- [ ] No multi-select, no bulk bar, no batch retire. All admin RPCs are singular.
- [ ] No `⋯` overflow menu on a row — there is no third action in v0.13.
- [ ] No delete, remove, purge or erase affordance, label, tooltip or `aria-label`.
- [ ] No `status` value on any mutation wire; `idle` shown, never selectable.
- [ ] No `version` row in the Sheet — it is header metadata.
- [ ] No enabled `Save changes` on an empty mask.
- [ ] No swallowed 409 — the conflict names both versions and says "not applied".
- [ ] No Sheet closing on a conflict; no toast on a conflict.
- [ ] No table refetch after a successful mutation — the row updates in place.
- [ ] No grab handle on the bottom sheet (D-109).
- [ ] No back arrow on the phone sheet — it would make the sheet a route.
- [ ] No second `+error.svelte` anywhere under `web/src/routes/`.
- [ ] No "Access denied" / "Forbidden" / "You don't have permission" page or state.
- [ ] No redirect on a denied deep link — the ordinary not-found.
- [ ] No path echo and no reason parameter on the not-found render.
- [ ] No `/admin` entry in `web/src/lib/nav/sections.ts`, and no client-side admin section registry.
- [ ] No template `{#if}` gating a nav entry — the nav is a server-filtered projection.
- [ ] No route guard described as the access control anywhere in code or acceptance text.
- [ ] No branch on `DENY_ADMIN_SECTION` vs `DENY_ADMIN_SECTION_UNREGISTERED`, and neither string rendered.
- [ ] No response-shaped telemetry for refusal type (a header, status or body field reopens the oracle) — log it server-side.
- [ ] No speculative "coming soon" or scope copy on the five undocumented planned sections.
- [ ] No authorization trace, registry footer or gate provenance in the operator's face.
- [ ] No session badge, presence dot or `--color-status-online` anywhere in the admin portal.
- [ ] No amber outside the cursor.
- [ ] No hardcoded `HoloMUSH` in copy, and never as a drawer group label.
- [ ] No `total_count` cited from this surface as precedent for the public directory.
- [ ] No client-side mirror of `charname.Normalize` in the search box.
- [ ] No media query for a new admin-shell breakpoint — `@container vp`, and reconcile the shipped rail's 767px `@media` with it.
- [ ] No `Sheet.Content` without `portalProps` targeting the `vp` container — otherwise both phone rules silently no-op.
- [ ] No dense table for a player-owned list; Cards stays the player idiom.
- [ ] No hover-only affordance without a `:focus-within` equivalent.
- [ ] No opacity or indistinguishability test trusted without a demonstrated RED.
