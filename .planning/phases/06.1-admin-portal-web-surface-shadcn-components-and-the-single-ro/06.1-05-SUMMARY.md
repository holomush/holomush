# Phase 06.1 Plan 05: One breakpoint, by construction Summary

**Sixteen hand-duplicated viewport literals across thirteen files collapsed onto Tailwind's own `--breakpoint-md`/`--breakpoint-lg` tokens plus one shared `DESKTOP_MEDIA_QUERY`, held there by a source census that forbids a new literal in either spelling and a 767/768 browser sweep that catches the two mechanisms disagreeing.**

## Accomplishments

- **The JS half stopped duplicating the boundary.** `EditCharacterSheet` deleted its own `MediaQueryList` effect and its `'(max-width: 767px)'` string; `side` now derives from `isDesktop(true)`. The hook was hardened first — it previously *threw* in this jsdom, which is why the component had hand-rolled a guard rather than reusing it.
- **The CSS half stopped duplicating it too.** All sixteen authored `@media` rules — nine `max-width` and seven `min-width`, across thirteen files at three different directory depths — read `theme(--breakpoint-md)` or `theme(--breakpoint-lg)`.
- **A census now forbids a relapse.** `TestNoAuthoredViewportRuleCarriesAHandWrittenBreakpointLiteral` scans every `.svelte`/`.css`/`.ts` file under `web/src` and flags a `767`, `768`, `1023` or `1024` on any viewport-deciding line, with a two-path allowlist that is itself checked for staleness.
- **A browser sweep can now see the two halves disagree.** The new `Proof 1c` block measures both columns and the Sheet at 767/768 and both columns at 1023/1024 — proven load-bearing by two independent mutations.

## Erratum (2026-08-15, closed by plan 06.1-07)

This section is APPEND-ONLY. Nothing above it is edited, reordered or deleted —
the original claim stays exactly where it was written, and this correction sits
beside it.

The `key-decisions` entry at line 45 reads:

> "The JS half keeps the `min-width` form and the component negates it, rather
> than minting a second query — `(min-width: 768px)` is the exact complement of
> `width < 48rem` at fractional widths"

**That claim is false at any root font size other than 16px.** The CSS half
compiles `theme(--breakpoint-md)` to `48rem`, and `rem` in a media query
resolves against the browser's INITIAL font size; the JS half was a px literal,
which does not. The two are numerically identical only at the 16px default. At a
20px default the CSS boundary sits at 960px while the px query stayed at 768px,
so anywhere in [768, 960) the shell rendered its phone shape while `isDesktop()`
still reported desktop — a phone-band shell wearing a desktop side sheet.

The fractional-width reasoning in the original sentence is correct in itself and
is unaffected: `width >= T` and `width < T` are exact complements at fractional
widths. What was wrong was treating a px `T` and a rem `T` as the same `T`.

Recorded as gap `G-06.1-2` in `06.1-VERIFICATION.md` and closed by plan
`06.1-07`, which put both halves in rem and added
`web/e2e/admin-band-root-font.spec.ts` — a Playwright project running at a 20px
root font size, the one axis along which the two halves can diverge and the one
every proof written for this phase up to that point was blind to.
