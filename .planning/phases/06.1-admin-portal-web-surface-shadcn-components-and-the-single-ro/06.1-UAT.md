  root_cause: |
    The 768px breakpoint is a hand-written literal repeated across seven authored
    sites (six CSS `@media` rules + one JS `matchMedia` string), with no shared
    token and no guard. Nothing keeps them equal.

    The values are NOT a bespoke scale — they restate Tailwind's own defaults
    off-by-one. Verified in the pinned tailwindcss@4.3.3 at
    `web/node_modules/tailwindcss/theme.css:327-331`:
      --breakpoint-md: 48rem  = 768px   (root font-size measured 16px)

    So `max-width: 767px` is "below md" and `max-width: 1023px` is "below lg".

    Read live from the running app, `--breakpoint-md` is NOT emitted to :root
    (while the hand-defined `--rail-w` IS, at 48px). So CSS can reference the
    token via `theme()`, but `matchMedia` in JS cannot read it at runtime — the
    JS side needs its own bridge (a `:root` custom property in the `--rail-w`
    style, or a TS constant pinned by a test).
