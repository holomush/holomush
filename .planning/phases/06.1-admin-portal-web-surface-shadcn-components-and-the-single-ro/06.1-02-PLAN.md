<objective>
Build the admin shell: a two-column responsive frame that collapses on the same viewport
breakpoints the shipped rail already uses, the `Admin` rail entry that makes `/admin` reachable
at all, a nav that is a projection of the server's answer rather than a client registry, and the
minimal planned-section state the six deferred sections render.

Purpose: ADMIN-07 requires navigation filtered "by registry contract, not by template `{#if}`
blocks", and §10.1 names a mirrored client-side registry as Pitfall 7's hazard. D-101 keeps the
registry server-side so a future per-section grant needs no client change. Today the seed policy
is resource-**type** scoped, so the permitted set is all-or-nothing — which is exactly why a
client mirror would look correct and stay correct until the moment it did not.

Output: `AdminNav.svelte` rendering the awaited response, the `@media` frame with the merged
rail-width strip at 768–1023px, the `Admin` rail entry drawn from the `roles` nav hint, the
planned-section route, and the two-class error split that renders the ordinary not-found on a
denial and one viewer-identical retry state on an outage.
</objective>

  <action>
**The responsive frame is built from viewport `@media` queries. No container query is
introduced anywhere.** This reverses the previous revision's mechanism, and the reversal is the
point of this task (cross-AI review C2-02, C2-03).

**What actually has to be true.** The property the phase needs is: *the shipped rail's collapse
rule and the admin shell's collapse rule fire at the same moment.* The shipped rail's rule is
`@media (max-width: 767px)` at `SectionRail.svelte:114` — a **viewport** query. A property
defined against the viewport is satisfied *by construction* by another viewport query at the
same literal, and only *coincidentally* by a container query, which agrees exactly when the
container's width happens to equal the viewport's. Two revisions have now been spent arguing
about whether some element is as wide as the window. That argument is the smell: the tool is
wrong for the property.

**Why the previous two attempts both failed, so neither is retried.**

- Revision 1 put `container-name: vp` on the admin layout's own root and claimed full-bleed.
  False above 768px — the admin layout nests inside `.section-col`, beside a 48px rail, so the
  container measured `innerWidth − 48` and the 768–815px band had the rail visible while the
  admin shell was already mobile (R-35).
- Revision 2 moved it up to the shipped `.shell`, where the width equality is true. But
  `container-type: inline-size` implies `contain: … layout …`, which makes `.shell` the
  **containing block for every `position: fixed` descendant** — and `.shell` renders every
  authed route. `Composer.svelte:190` (`position: fixed`, driven by viewport-relative
  `clientX/clientY` drag math and a persisted position pref) and `CommandPalette.svelte:125,131`
  would both re-anchor 44px down, on the game's primary surface, and the revision's own safety
  grep was scoped to two paths that cannot see them (C2-02, orchestrator-verified). Portalling
