### The browser proof — I ran it, at the axis that matters

The previous round's finding was *proven* in a browser, so its closure had to be too. I ran the full
Docker E2E stack, not a source read:

```
$ task test:e2e -- admin-band-root-font
[chromium-large-font] › admin-band-root-font.spec.ts:81  the JS query and the CSS token are exact complements at a 20px root font
```

What those two tests actually assert, read from source rather than from the summary:

- **The harness first.** `:95-100` asserts `getComputedStyle(document.documentElement).fontSize === 20`
  **before** any complement assertion. If `--blink-settings=defaultFontSize=20` ever stops applying,
  the spec fails instead of silently reverting to the 16px blind spot it exists to leave.
- **The token is read at runtime**, off `:root` (`:86-92`), and asserted to be rem-shaped (`:105-108`) —
  which also keeps the *correction* of the previously-false census rationale honest.
- **Eight widths** — 640, 767, 768, 900, 959, 960, 961, 1024 — each asserting
  `matchMedia(DESKTOP_MEDIA_QUERY).matches === matchMedia('(width >= <token>)').matches` **and**
  `=== !matchMedia('(width < <token>)').matches` (`:110-132`). 900 and 959 are inside the
  [768, 960) band that the previous round proved divergent.
- **The rendered consequence**, not only the query algebra: at 900px the rail and `.adminnav-col` must
  poll to zero width and the Sheet must read `data-side="bottom"`; at 1000px both must be drawn and the
  Sheet must read `data-side="right"` (`:135-170`).

`web/playwright.config.ts:35-55` wires this as a second project with `testMatch`/`testIgnore` and no
project-level `grep`, so it runs by default in the required `E2E Test` check and does not shadow the
config-level quarantine filter. Both are correct as read.

## Gaps Summary

**The phase goal is achieved and no gaps remain.** All four ROADMAP criteria are MET, and the two that
this phase kept failing are enforced by guards I put under mutation myself rather than read about:

- **Criterion 4** is closed at the axis that defeated every earlier proof. Both halves are rem, one
  authored band value survives in the tree, the census forbids the *new* visible spelling everywhere
  else, its exemption moved from a file to a symbol, and — the part that matters — the agreement is

  launch flag stops applying. I ran it.
- **Criterion 3's** residue is closed: the guard reads the cap the constructor *emits* and refuses to
  resolve an expression it cannot read, so the `maxBytes: 90` escape is RED with a message naming all
  seven affected paths.
- **G-06.1-7**, the one gap round 3 opened, is closed by a comment-only correction I verified as
  comment-only, with a positive control proving the removed string was really there.

**The transferable lesson from this phase:** round 2's lesson was *vary every axis the two expressions
can differ on*; it was applied correctly and the defect is genuinely gone. Round 3 added one level up:
a guard's **prose** is not covered by the guard, and a claim of the form "X fails on Y" is exactly as
checkable as running Y. Round 4 adds the last turn of the screw — the repair of a comment is itself a
change that can be wrong, so it gets the same treatment: read the replacement against the arithmetic,
and prove the deletion with a positive control rather than an absence.
