## Criterion 1 — MET

**The nav is a projection of the response, with no template gate.**
`web/src/lib/components/admin/AdminNav.svelte:29` is `{#each sections as section (section.id)}` over the awaited array, rendered verbatim. No `{#if}` decides whether an entry is drawn; the only two `{#if}`s in the component (`:39`, `:42`) read `section.status` and `activeId` — per-entry data fields, not a hard-coded id list. The glyph is `monogram(section.displayName)` (`:25`), deliberately not an id→icon map, so the component holds no client-side mirror of the server's set at all.

**No client-side section registry was introduced.** `git log ca0ace19b..HEAD -- web/src/lib/nav/sections.ts` returns zero commits — the shipped registry is untouched, `/admin` is not in `SECTIONS`, and `SectionVisibility` is not widened.

**Roles change only what is DRAWN.** `SectionRail.svelte:44` is `let showAdmin = $derived(roles.includes('admin'))` — the sole consumer of the roles hint, and it gates one rail entry. `roles` is a **required** parameter of `setPlayerProfile` (`authStore.ts:51-56`), so a missed call site is a `svelte-check` failure rather than a silently role-less rail; all six call sites pass it (`login/+page.ts:24`, `login/+page.svelte:115` and `:127` — the latter documented as the no-session-response case, `register/+page.ts:24`, `(authed)/+layout.ts:25`, `+page.ts:49`).

**A drawn link the viewer may not use still ends in a denial at the RPC — verified server-side, not assumed.** The client never treats the nav response as authorization: `admin/+layout.ts:11-14` and `[section]/+page.ts:9-13` both state, in the code, that the load is not the access control. Every admin surface still issues a real RPC (`characters/+page.ts:49`; `client.ts:131-258`), and no wrapper passes a caller-asserted identity — `client.ts:118-122` records that `CookieMiddleware` injects `X-Session-Token` and the gateway lifts identity from it, so a forged client-side `roles` array reaches no decision point. The server-side refusal is unit-pinned at `internal/grpc/admin_interceptor_test.go:120` (`TestTheInterceptorRefusesANonAdminWithTheTypedDenyCode`) and exercised over the real stack at `web/e2e/admin-portal.spec.ts:587-623`, where a registered non-admin with a character is refused on `/admin`, `/admin/characters` and `/admin/moderation`.

**The client never renders a DENY_ code.** `rg -n 'DENY_' web/src --glob '!**/lib/components/ui/**' --glob '!**/lib/connect/**' --glob '!**/*test*'` returns **0**. The six matches without the test exclusion are all negative-control fixtures that inject a `DENY_*` string and assert it is *not* rendered (`characters-page.svelte.test.ts:224,229`; `EditCharacterSheet.svelte.test.ts:269,273`; `LifecycleConfirmDialog.svelte.test.ts:213,220`) — the opposite of the prohibited pattern, and the thing that proves it. *(Note: plan 02's prohibition text specifies a grep without a test-file exclusion and asserts it returns zero; the literal grep returns 6. **Failure classification is total and fail-safe.** `web/src/lib/connect/errors.ts:81-90`: `Unavailable`/`DeadlineExceeded` → `infrastructure`; every other `ConnectError` code → `denial`; a non-`ConnectError` throw (never reached a server) → `infrastructure`. ### What is short of MET

**The Sheet's field set is a hand-maintained parallel list, not the server's allowlist.**

`ADMIN_EDITABLE_FIELDS` at `web/src/lib/components/admin/EditCharacterSheet.svelte:61-75` is thirteen literal `line(...)`/`prose(...)` calls authored in TypeScript. Its doc comment (`:12-16`) states "THE SET IS THE SERVER'S, NOT THIS FILE'S" and cites `adminProfileMaskablePaths` (`internal/grpc/admin_characters_write.go:130-170`) — but that is a **claim about provenance, not a derivation**. What is genuinely derived is the wire *field name*, via `adminWireField` (`:47`, `:55`), the one-line rule the request builder also uses (`client.ts:205-206`, consumed at `:232`) — so the form and the wire cannot disagree about what a path is *called*. The *membership* of the set is authored twice.

I checked both sides path-by-path and they match exactly today: `description` + the twelve `profile.*` names, and the caps agree (`description` and five long `profile.*` at `world.MaxDescriptionLength`, seven short at `world.MaxNameLength` — matching the TS split of 6×4000 / 7×100).

The only assertion over the set is `EditCharacterSheet.svelte.test.ts:159-180`, which compares `ADMIN_EDITABLE_FIELDS.map(f => f.path)` against a **hardcoded literal array in the same test file**. That pins the list against accidental edits, but it is an echo of the client's own list — it cannot see the Go allowlist and would stay green if the server's set changed. There is no cross-language guard: `rg 'EditCharacterSheet|ADMIN_EDITABLE_FIELDS' --type go` returns **0**, and no `test/meta` file references either.

**Mitigating, and why this is a WARNING rather than a BLOCKER:** the drift fails closed. `admin_characters_write.go:30-34` documents, and the handler enforces, exact-string map lookup with an unlisted path **rejected rather than ignored** — so a client that sent a path the server dropped gets a refusal, not a silent unadvertised mutation. The residual exposure is the reverse direction: a path the server *adds* is simply not editable in the UI until someone remembers this file.

## Criterion 4 — PARTIALLY MET

### The "same viewport mechanism" half is MET, and verified rather than asserted

`rg 'container-type|container-name' web/src --glob '!**/lib/components/ui/**'` returns **0** — no authored web source declares a containment context anywhere, so nothing rebases a percentage or a fixed descendant. Both collapse rules are viewport media queries:

- `web/src/lib/components/shell/SectionRail.svelte:168` — `@media (max-width: 767px) { .rail:not(.is-drawer) { width: 0; border-right-width: 0; } }`
- `web/src/routes/(authed)/admin/+layout.svelte:193` — `@media (max-width: 767px) { .adminnav-col { width: 0; border-right-width: 0; } ... }`

Identical mechanism, identical literal, so at any given viewport width they fire together. The rail *width* is genuinely shared: `--rail-w` is defined once at `web/src/app.css:73` and read by both `SectionRail.svelte:152` and `admin/+layout.svelte:186`. The 1023px merged-strip band is behaviourally pinned at `admin-portal.spec.ts:330-334`, which asserts `|navWidth - railWidth| <= 1` at 780px — a real discriminating assertion over the shared token.

### The "by construction rather than by coincidence" half is NOT achieved

The `767px` breakpoint has **no** shared source of truth. It appears as five independent string literals in authored source:

| File:line | Rule |
|---|---|
| `web/src/lib/components/shell/SectionRail.svelte:168` | the shipped rail's collapse |
| `web/src/routes/(authed)/admin/+layout.svelte:193` | the admin nav column's collapse |
| `web/src/lib/components/admin/CharacterFilterBar.svelte:134` | filter-bar stacking |
| `web/src/lib/components/admin/CharacterTable.svelte:357` | column drop + row tap target |
| `web/src/lib/components/admin/EditCharacterSheet.svelte:708` | bottom-sheet height + 16px inputs |

There is no `--breakpoint` token, no `@custom-media`, no Tailwind `theme()` reference, and no build-time indirection. `rg '767' web/src --glob '*test*'` shows the only test-side occurrences are the Sheet's own `matchMedia` stub (`EditCharacterSheet.svelte.test.ts:75,612-621`) and `CharacterTable.svelte.test.ts:245`, a source-string scan of *its own file*. **No test compares one file's literal to another's.**

The E2E does not close it either. Its viewports are exactly 375, 780, 1280 (`admin-portal.spec.ts:168, 315, 363, 457, 585`). At 375px both columns are asserted zero-width (`:182`, `:186`); at 780px both are non-zero (`:325`, `:333`). Those two samples **bracket** the threshold but never test it: change `admin/+layout.svelte:193` from `767px` to, say, `700px` and both E2E assertions still pass, while at 750px the rail collapses and the admin nav does not. The one width where a divergence becomes visible is never exercised.

So the criterion's own contrast — "by construction rather than by coincidence" — is not met as worded. What is met is the *mechanism* clause: nothing here is a container query, so the two rules cannot fire at different moments because of how wide some element happens to be. What is absent is any construction that keeps the two literals equal. They agree today by duplication, and nothing turns red if one changes.

*(Note: the phone-band claims that do NOT rest on jsdom are properly discharged. `admin-portal.spec.ts:253` asserts `data-side=bottom` — the Svelte `matchMedia` derivation at `EditCharacterSheet.svelte:199`, which CSS cannot produce — and `:257-266` independently asserts the computed 84vh geometry and 16px input font. Two mechanisms, two assertions, as the plan required. The jsdom-only assertion at `CharacterTable.svelte.test.ts:239-268` is explicitly labelled a stylesheet scan in its own doc comment and names the browser-level proof that covers the behaviour — honest, not overclaimed.)*

## Summary

The phase goal is achieved. The four surfaces the goal names — the eleven-component set, the single root boundary, the permission-filtered shell, the character table, and the Sheet with its mutation loop — all exist, are wired to real RPCs, and are exercised over the real stack rather than only in jsdom. The two hardest claims to fake, criterion 1's server-side denial and criterion 2's per-viewer indistinguishability, are backed by genuinely discriminating tests: a filesystem census with a `Len == 1` predicate, and a set-equality reduction over four miss kinds with a recorded negative control.

Two criteria fall short of their own strongest wording, in the same way and for the same reason: a correctness property that holds today holds by **duplication** rather than by construction, with nothing that turns red when the duplicate drifts.

- **Criterion 4** promises the two collapses fire together "by construction." They do fire together — same mechanism, same literal, no container queries anywhere — but the literal is written five times with no shared token and no test at the 767/768 boundary. Changing one leaves every gate green.
- **Criterion 3** promises the Sheet's field set "is the server's field-mask allowlist." The two sets are identical today, and the wire *names* are genuinely derived from one rule; but the *membership* is authored in TypeScript and pinned only against a literal echo in its own test file. Drift fails closed at the server, so the risk is a field going quietly uneditable rather than a mutation going through unadvertised.

Neither is a blocker: no artifact is missing, stubbed or unwired, no key link is broken, and no debt marker was left behind. Both are durability gaps that need a human decision — accept via an override, or open follow-up work for a shared breakpoint token plus a boundary assertion, and a meta-test pinning `ADMIN_EDITABLE_FIELDS` set-equal to `adminProfileMaskablePaths`.
