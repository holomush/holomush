## What the responsive frame actually does, and why it is @media

The property the phase needs is: *the shipped rail's collapse rule and the admin shell's collapse rule fire at the same moment.* The shipped rail's rule is `@media (max-width: 767px)` at `SectionRail.svelte:114` — a **viewport** query. A viewport query at the same literal satisfies that by construction; a container query satisfies it only when the container's width happens to equal the viewport's, which is an argument rather than a guarantee.

Three bands, all `@media`:

| Band | Rail | Admin nav | Extras |
|---|---|---|---|
| ≥1024px | 48px icons (inherited) | 232px, monogram + label + `planned` badge | — |
| 768–1023px | 48px icons, `Admin` entry `.is-context` (tint, no bar) | narrowed to `var(--rail-w)`; labels clipped but announced; badge becomes a dot | `.rail-identity` returns at the strip's foot |
| <768px | width 0 | width 0 | `.mobilebar` breadcrumb; the drawer carries both groups |

**Nothing declares containment.** `container-type: inline-size` implies layout containment, which makes the declaring element the containing block for **every** `position: fixed` descendant. The `(authed)` subtree has three today (`Composer.svelte:190`, `CommandPalette.svelte:125,131`) plus every Sheet overlay and content — and `Composer` is positioned from viewport-relative `clientX/clientY` drag math and a persisted position pref. `git diff --exit-code web/src/lib/components/terminal/` exits **0**: the fix is not to move the Composer, it is not to create the containing block. The Sheet keeps its generated `document.body` portal, so its overlay still covers the topbar and its height percentages still resolve against the viewport.

**The admin layout composes exactly two columns** and imports no `SectionRail` (`rg -n 'SectionRail' web/src/routes/(authed)/admin/` → 0). The rail is inherited from one level up; a second would double-render.

## The refusal split, and where its default points

`classifyAdminFailure` reads the gRPC code and nothing else. Splitting refusal-from-outage is a *different axis* from splitting on which refusal arrived: the first does not correlate with what the caller may do (a non-admin during an outage sees exactly what an admin sees), the second is the enumeration oracle the whole surface exists to close.

The residue is the part worth stating. `Unavailable`, `DeadlineExceeded` and a non-`ConnectError` throw are infrastructure; **everything else defaults to denial**, and that is fail-safe rather than fail-open — the denial branch renders the ordinary not-found, the most conservative screen available and exactly what an unauthorised viewer already sees. Defaulting the other way would render a retry state for a genuine refusal, which announces that something is there to retry. The reasoning is in the function's own doc comment and pinned by a case per code including `ResourceExhausted`, which the union does not enumerate.

`redirect(3xx)` appears in **exactly one file** under the admin tree — `admin/+page.ts`, the canonical-index resolution for a caller who has already passed the gate. Neither the layout nor `[section]` redirects.
