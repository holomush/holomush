### WR-01: The completeness equality preempts the offender assertion

**Files modified:** `test/meta/web_phone_band_breakpoint_census_test.go`
**Commit:** `ca0785f36`
**Applied fix:** Moved `require.Empty(t, offenders, …)` to run **before** the
corpus-completeness equality — the **order** only. Neither assertion was
weakened, narrowed, or filtered; the equality is still
`ruleCensusOccurrences+allowlistLines == bandRelevant` with nothing subtracted
from either side.

The review offered two shapes. I took the reordering rather than the
`bandRelevant-len(offenders)` variant: subtracting offenders off the measured
side makes the equality's meaning depend on a second list, and the ordering
already makes the subtraction unnecessary — reaching the equality now *proves*
there are no hand-written widths in the corpus, so the case the subtraction
would have handled cannot arise.

The ordering constraint runs in both directions and is now written into the file
so it is not undone by a future tidy-up: the offender assertion must stay AFTER
the allowlist staleness loop (a dead exemption changes what an offender means)
and BEFORE the equality (a hand-written width is band-relevant too, so it breaks
both, and only the offender message gives the correct instruction).
