<objective>
Close G-06.1-3: the Sheet's field allowlist, its two byte caps, and its
path-to-cap mapping are all hand-maintained across the Go/TypeScript boundary
with nothing enforcing any of the three.

Purpose: ROADMAP criterion 3 says the Sheet's field set IS the server's field-mask
allowlist. Today that is provenance, not derivation — the Sheet's doc comment
asserts it and `rg 'ADMIN_EDITABLE_FIELDS' --type go` returns nothing. The Go side
already practises the anti-drift principle one package over
(`internal/world/validation.go:24-30` aliases the charname leaf's bounds
explicitly so the two cannot drift, D-28); the web client is the one surface that
did not get the same treatment.

Output: one Go test that reads the real allowlist symbol and the real world
constants and compares them against the Sheet's declaration, plus the removal of
a web-side test that compares the list against a hardcoded copy of itself in the
same file and therefore cannot fail on drift.
</objective>

<grounding>
Verified in this worktree; do not re-derive.

**Three things are duplicated, not one.** The PATH SET (13 entries each side,
set-equal today), the two BYTE CAPS (`SHORT` and `LONG` in the Sheet's module
script, TypeScript literals whose only link to Go is a trailing comment naming
`world.MaxNameLength` and `world.MaxDescriptionLength`), and the PATH-TO-CAP
MAPPING (which paths the Sheet declares via `line` and which via `prose`).

**The authority is `adminProfileMaskablePaths`** at
`internal/grpc/admin_characters_write.go:130`, a `map[string]adminProfileMaskField`
whose struct is declared at `:98-102` with fields `maxBytes int`,
`isDescription bool`, `value func(...) string`. It is UNEXPORTED, and
`internal/world`'s `MaxNameLength = 100` / `MaxDescriptionLength = 4000` are at
`internal/world/validation.go:20-21`.

**The existing web-side assertion cannot fail.**
`EditCharacterSheet.svelte.test.ts:159-180` asserts the array's length, its 7/6
cap split, and its exact path list against a literal array written into the same
file. Every one of those is an echo: a drift that changes both sides of the same
file leaves it green, and a drift on the Go side is invisible to it entirely.

**The drift that exists already fails CLOSED.** `admin_characters_write.go`
compares mask paths by exact string against the closed allowlist and REJECTS an
unlisted path rather than ignoring it, so a TypeScript-only path surfaces as an
operator-visible refusal rather than a wrong write. That is why this gap is
`minor` and why the fix is a guard rather than a redesign.

**`adminWireField`** (`web/src/lib/admin/client.ts:205-206`) is the single rule
that flattens a mask path to its request field: strip a leading `profile.`
segment, otherwise pass through. Both `line()` and `prose()` call it, so the
`name` on every entry is derived, never authored.
</grounding>

<design_decision>
The design question the gap poses — Go meta-test that parses the TypeScript, or
generated TypeScript emitted from the Go map, or a shared schema both derive from
— is settled here as the FIRST, and the test is placed in `package grpc` rather
than in `test/meta/`.

**Why a parsing guard and not codegen.** Generated TypeScript would buy exactness
at the price of a generator, a Taskfile target, and a stale-diff CI check, for
thirteen strings and two integers that change roughly never. A shared schema costs
a new artifact plus two parsers and one more thing to keep in step. `test/meta/`
already hosts exactly this kind of cross-surface census — `web_error_boundary_census_test.go`,
added by this very phase, walks `web/src/routes` from Go — so the parsing guard is
the in-tree shape, not a novel one. Prefer in-tree precedent over new machinery.

**Why `package grpc` and not `test/meta`.** The authority is unexported. A test in
`test/meta` would have to parse the Go source with `go/ast` to reach
`adminProfileMaskablePaths`, which means comparing a re-parse of the map against a
parse of the TypeScript — two derived readings, neither of which is the value the
server actually enforces. In `package grpc` the map is a live symbol, `world.MaxNameLength`
is a live constant, and only ONE side needs parsing. That is strictly less
machinery and strictly closer to the truth. It also puts the guard beside
`TestAdminProfileMaskAllowlistMatchesSpec`, which already pins the same map
against the SPEC — the two together say the map agrees with the SPEC above it and
with the client below it.

The cost accepted: a Go test now knows a web file path. That is the same coupling
`web_error_boundary_census_test.go` already carries, and the test fails loudly on
a moved file rather than silently skipping.
</design_decision>
