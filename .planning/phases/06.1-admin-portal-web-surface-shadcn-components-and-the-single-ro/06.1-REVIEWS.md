## Current HIGH Concerns

### H-1 — Five Svelte component tests are assigned filenames that run in the wrong Vitest project `[REGRESSION-FROM-FIX]`

*Source: codex-C. Plans: `06.1-02`, `06.1-03`, `06.1-04`.*

The repo deliberately routes only `*.svelte.test.ts` through the client project with
browser resolution; ordinary `*.test.ts` runs in the **server** project
(`web/vite.config.ts:12`). The plans name `SectionRail.test.ts` and `AdminNav.test.ts`
(old 06-06:15), `CharacterTable.test.ts` (old 06-07:12), `EditCharacterSheet.test.ts`
and `LifecycleConfirmDialog.test.ts` (old 06-08:9).

Existing component tests consistently use `SectionRail.svelte.test.ts`,
`ProfileSection.svelte.test.ts`, `CommandPalette.svelte.test.ts`. As written the new
mount/render/focus tests do not receive the project configuration created for Svelte
components. **Rename every component-test artifact and every reference to
`*.svelte.test.ts`.**

### H-2 — The `<768px` drawer grouping has no workable mechanism and no verifying criterion (C2-34 only apparently closed)

*Source: codex-C (HIGH) and opencode-4a (HIGH) — independent consensus. Plan: `06.1-02`.*

At phone width the plan zeroes both persistent nav columns and promises one combined
parent drawer. The shipped drawer is `<SheetContent><SectionRail variant="drawer"/></SheetContent>`
in the **parent** layout (`web/src/routes/(authed)/+layout.svelte:31-37`), closed over
its own `SectionRail`. A component mounted in the *child* admin layout cannot project
content into that Sheet — the same "data flows downward" argument the plan uses to kill
rail-injection applies to DOM containment. The escape hatches are closed: the parent
layout's diff is criterion-locked to "only the `roles` prop threaded into the two
`SectionRail` instances", and a second Sheet bound to the same `mobileNavOpen` store
would double-overlay.

No acceptance criterion pins the drawer's Admin group at all. The 375px E2E asserts the
mobilebar and zero-width rails, not drawer contents — so it passes while the promised
Admin group is absent.

**Resolve honestly, then pin it.** Either (a) loosen the parent-layout diff criterion to
permit an optional admin-group slot fed by a small child-to-parent registration, and say
so; or (b) drop the two-group single-drawer design for v0.13 and let `AdminNav`'s own
drawer variant be the whole content of the admin drawer on `/admin/*`, and say *that*.
Either way add a criterion (component test or the 375px E2E) that opens the hamburger and
navigates between two admin sections inside the opened drawer.

### H-3 — The C2-32 scoped grep's exclusion glob silently does not exclude; the criterion fails every correct implementation `[REGRESSION-FROM-FIX]`

*Source: opencode-4a. Plan: `06.1-02`.*

The headline criterion is `rg -n 'DENY_' web/src --glob '!lib/connect/**'` → asserted zero
matches. Executed at HEAD, **it prints all 11 generated matches**
(`web/src/lib/connect/holomush/admin/v1/{admin_pb,read_stream_pb}.ts`). ripgrep matches
globs against the path *as searched* — `web/src/lib/connect/...` does not match
`!lib/connect/**`; the exclusion needs `!**/lib/connect/**` (verified: that spelling
returns 0).

So the criterion is false at HEAD, false after a correct implementation, and its own
"demonstrated RED" would be invisible against the 11-line baseline. This is the exact
defect class C2-32 existed to fix, reintroduced by its fix — the disposition's "verified
at HEAD" must have checked the match count, not the exclusion working.

**Fix to `--glob '!**/lib/connect/**'` and put the verified HEAD output (11 lines → 0)
into the criterion text**, so the exclusion's *function* is pinned, not just its intent.

### H-4 — The C2-10 computed-position Vitest case is unsatisfiable under jsdom and fails a correct implementation `[REGRESSION-FROM-FIX]`

*Source: opencode-4b1 (HIGH); codex-C raised the same mechanism as MEDIUM. Plan: `06.1-03`.*

The criterion requires asserting, *inside the phone band*, computed `position: relative`
on the `<tr>` and `static` on the Name `<td>`, with a demonstrated RED. The rule lives
inside `@media (max-width: 767px)`; the suite runs in jsdom (`web/vite.config.ts:10`,
jsdom 29.1.1), which has no sub-1024px viewport — and this repo already knows its media
evaluation is unreliable: `SectionRail.svelte.test.ts:21-30` stubs `matchMedia` to
`matches: false` for exactly this reason.

Computed `position` therefore reads `static` whether the CSS is right or wrong, and the
mandated "move it back onto the `<td>` → FAIL" experiment demonstrates nothing.

**Fix:** drop the computed-style assertion. Rely on (a) the already-present selector-level
grep (`position: relative` on the *row* selector, not a cell selector) and (b) `06.1-04`'s
retargeted Playwright tap on a non-Name cell — the only environment that can prove span. If
a unit-level guard is wanted, assert on the **stylesheet text** (the rule appears inside the
`@media` block and targets the `tr` selector).

> The C2-10 *mechanism* is sound and genuinely closed — `position: relative` moved from the
> `<td>` to the `<tr>` is the correct containing-block repair. Only its new unit proof is broken.

## Current Actionable Non-HIGH Concerns

### M-1 — Required `roles` migration omits live `setPlayerProfile` callers

*Plan: `06.1-02`. **Adjudicated from HIGH to MEDIUM** — codex-C rated it HIGH for the omission;
opencode-4a rated the mechanism sound. Both are right about different questions.*

Verified at source: there are **5** production call sites (opencode-4a counts 6 including a
`:118` fallback) and the plan lists **4** — `web/src/routes/+page.ts:41` is missing, as are the
store tests at `web/src/lib/stores/authStore.test.ts:15,30`. Neither file is in `files_modified`.

Because `setPlayerProfile` takes a **typed object parameter** (`authStore.ts:38-43`), a required
field makes the omission a `svelte-check` failure rather than a silent bug — loud at execution.
It is still wrong in `files_modified`, **which is what the wave-collision detector reads**, and
`+page.ts:41` is a session-resolution path where a missed `roles` pass is precisely the
"silently role-less rail" the required-arg design exists to prevent.

**Fix:** correct the enumeration, add `web/src/routes/+page.ts` and
`web/src/lib/stores/authStore.test.ts` to `files_modified`, and assert that `roles` is stored
and reset.
