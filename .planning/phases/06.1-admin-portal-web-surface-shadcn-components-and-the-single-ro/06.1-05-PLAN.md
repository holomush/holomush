<grounding>
Every claim below was verified in this worktree before this plan was written. Do
not re-derive them; do not contradict them.

**The token exists and the project does not override it.** Pinned
`tailwindcss@4.3.3` declares `--breakpoint-md: 48rem` and `--breakpoint-lg: 64rem`
at `web/node_modules/tailwindcss/theme.css:327-331`. Root font size is 16px, so
those are 768px and 1024px. `web/src/app.css` overrides neither.

**`theme()` inside a Svelte scoped style block REQUIRES an `@reference` line, and
fails loudly without one.** Measured: adding `@media (width < theme(--breakpoint-md))`
to `Sidebar.svelte` with no `@reference` fails `pnpm build` with
`Error: Could not resolve value for theme function: ` followed by the theme
function call. Adding `@reference "../../../app.css";` as the first line inside
the `<style>` block makes the same build pass. This is because
`svelte.config.js` configures no `vitePreprocess`, so a component style block is
handed to `@tailwindcss/vite` as a standalone stylesheet with no theme loaded.
No Svelte style block in this repo uses `@apply` or `theme()` today, so there is
no in-tree precedent to copy — this grounding IS the precedent.

**All seven target files sit exactly three directories below `web/src`,** so the
reference path is the identical string `../../../app.css` in every one of them.

**The full conversion was applied to all seven files and built green.** Emitted
CSS was compared 1:1 before and after: each `@media (width<=767px)` became
`@media not all and (width>=48rem)` and each `@media (width<=1023px)` became
`@media not all and (width>=64rem)`, with the same rule counts in the same
assets, and the unrelated 600px rule untouched. The experiment was reverted; the
tree you are given is the pre-fix state.

**The range form is a correctness improvement, not tidying.** A `max-width`
declared one below the boundary and a `min-width` declared at it are not
complements: at a fractional width such as 767.5px — reachable under browser zoom
and fractional DPI scaling — neither matches, and the JS half and the CSS half of
this component take different branches. `(min-width: 768px)` IS the exact
complement of `width < 768px` at every width, which is why the JS side keeps the
`min-width` form and the component negates it rather than minting a second query.

**JS cannot read the token at runtime.** Tailwind v4 compiles breakpoints away at
build time: read live from the running app via `getComputedStyle(document.documentElement)`,
`--breakpoint-md` is NOT emitted to `:root`, while the hand-defined `--rail-w` IS
(48px). So the JS half needs its own number. `web/src/lib/hooks/mediaQuery.svelte.ts`
already declares it once as `DESKTOP_MEDIA_QUERY` and `ScenesShell.svelte:78`
already consumes it through `isDesktop()`. Routing the Sheet through the SAME
hook is the fix; minting a third mechanism is not.

**Both measured elements animate.** `SectionRail.svelte:157` and
`admin/+layout.svelte:113` both carry `transition: width 180ms ease`. A viewport
sweep that measures before that settles reads mid-animation widths — this already
invalidated one measurement pass during UAT. Every resize in the new E2E block
waits 300ms before measuring.

**Ground truth the sweep must reproduce** (measured live over 13 widths, zero
disagreements): 360-767 -> rail 0, nav 0. 768-1023 -> rail 48, nav 48.
1024+ -> rail 48, nav 232.

**jsdom applies no media query and computes no layout.** No component test can
prove reflow. The boundary proof lives in Playwright and nowhere else.
</grounding>
