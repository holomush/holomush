Prove the whole Phase-4 architecture end-to-end on one thin path: a logged-out
visitor standing nowhere reads a character's **name and in-world description**
through the web, and a profile the viewer cannot reach is indistinguishable from
a character that does not exist.

`world.Service`, the new `CharacterAccessService` facade, the `Web*` proxy,
production wiring, and the integration harness — with exactly one call path
through each, production-quality, with a real end-to-end verification.

Purpose: catch an architectural dead-end after one commit rather than after ten.
Every later plan in this phase expands horizontally from the slice proven here.

Output: the `characteraccess` proto package, the facade with its narrow
dependency interfaces and viewer-tier switch, the `read_description` ABAC action
and its two permits, the web proxy, and a passing full-stack integration spec.

## Deliberate scope acceptance — Task 1

Task 1 modifies 17 files spanning proto, generated Go and TypeScript, generated
docs, ABAC seeds, `world.Service`, a new facade, a new projection, a new web proxy,
production wiring, the integration harness and a new Ginkgo spec. That is well past
the 5-8 file guidance, and `estimate.tokens: 75000` at `confidence: low` makes it
the phase's highest-variance plan.

**This shape is deliberate and the context risk is accepted.** Task 1 is the
phase's tracer: it proves one profile read end-to-end through every layer the phase
will later expand. Splitting the proto-plus-regeneration step into its own task
would produce an intermediate commit in which the proto declares a service with no
Go implementation and no registration — `task build` stays green but the tracer's
whole value, a runnable end-to-end verify, is gone until the second task lands.
A regeneration failure is also cheap to diagnose and re-run in place; it does not
benefit from task isolation the way a genuine dependency would.

The accepted risk: if Task 1 exhausts context mid-regeneration, the recovery is to
re-run `task proto && task web:generate` and continue, not to re-plan. The executor
should commit after the proto regeneration succeeds and before starting the ABAC
and facade work, so that recovery point exists on disk.
