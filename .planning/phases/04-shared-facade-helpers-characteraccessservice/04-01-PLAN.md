**The viewer-identity seam — D-83 taken literally, and it belongs in THIS plan.**
D-83 locks that "the viewer tier is resolved **in the facade**, at
viewer-principal construction" and that "**the facade is the only layer holding
the session**". A facade that holds no session repository cannot satisfy that
sentence, and `GetCharacterProfile` already accepts a `player_session_token`, so
the resolution step lands here in wave 1 rather than arriving with the owner
audience in wave 3. Add to `CharacterAccessServer`:
  - fields `playerSessionRepo auth.PlayerSessionRepository` and
    `playerRepo auth.PlayerRepository`, supplied by the constructor. Both are
    already in scope at both call sites — `cmd/holomush/sub_grpc.go` and
    `internal/testsupport/integrationtest/harness.go` each build them today for
    `NewSceneAccessServer` — so this adds two arguments and no new production type.
  - an unexported value type `viewerIdentity` carrying exactly a `tier string` and
    a `playerID string`.
  - `resolveViewerIdentity(ctx context.Context, rawToken string) (viewerIdentity, error)`,
    which performs the I/O:
      * an **empty** token resolves to `{anonymous, ""}` with a nil error;
      * a non-empty token goes through the package-level
        `resolvePlayerSessionWithRepo` (`internal/grpc/auth_handlers.go:174`);
        **any** resolution failure — expired, unknown, or the `NOT_CONFIGURED`
        code — also resolves to `{anonymous, ""}` with a nil error, logged at
        debug through `slog.DebugContext`. This is fail-closed, not fail-open:
        `anonymous` is the least-privileged rung, so the fallback can only ever
        narrow what the caller sees, and a logged-out visitor whose stale cookie
        is still attached must still get the public page rather than a 401;
      * a resolved session then loads the player via `playerRepo.GetByID`.
        `IsGuest` true yields `{guest, playerID}`; false yields `{player, playerID}`.
        A `GetByID` **error** is the one non-nil return: log through
        `errutil.LogErrorContext` and let the caller map it to `codes.Internal`.
        A rung is a policy answer and an outage is not one (01-SPEC section 8.10,
        and the `Internal` row of 04-02's gate error matrix).
  - Its doc comment must state, in one sentence each: why it is not
    `playerGate.resolveAndGate` (that helper returns `PermissionDenied` for any
    guest — `internal/grpc/sceneaccess_service.go:144-146`, INV-SCENE-64 — and the
    public read must yield a guest rung, so the two are different questions on
    purpose), and why an unresolvable token degrades to `anonymous` rather than
    erroring.
