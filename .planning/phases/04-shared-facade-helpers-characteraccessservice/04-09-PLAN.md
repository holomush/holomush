     character-scoped write that is not a column on `characters` and therefore

     one-producer-of-record rule. Add its `registry` entry with the character

     declaring the character id and the set of changed attribute names. Bump
     `AppSchemaVersion` from 2 to 3 — its own doc comment requires a bump whenever

  2. `internal/world/service.go` — add the matching PRIVATE `kind*` constant to the

**The closure builder.** Add a method to `worldMutator` beside
`updateCharacterPreferences`, capturing the EXISTING private `propertyWriter`
field. It takes the intent, the character carrying the caller's expected version,
the attribute upserts, and the attribute names to delete, and routes them through
`mutate()`.

Two seams differ from every other closure builder and are the reason this task is
sized as its own commit:

  - **The CAS guard.** Property rows carry no version; the character row does, and
    the profile is part of the character aggregate. So the closure runs the
    version-guarded `characterWriter.Update` FIRST — fail-fast on a stale version
    before doing any property work — with `char.Version` set to the CALLER's
    expected version, never a freshly-read one, exactly as `setCharacterStatus`'s
    doc comment requires (INV-WORLD-7). This also bumps the character version, so
    the aggregate keeps one optimistic-concurrency token.
  - **The delta.** `characterWriter.Update` already returns a
    `*wmodel.MutationDelta`; the property writers return a bare `error`. Return the
    character update's delta and do NOT hand-construct one — the envelope's
    manifest is finalized from a real repo delta, as `mutate()` requires.

After the guarded update succeeds, apply the property rows through
`propertyWriter`: create a row for a name with no row, update a row that exists,
delete the row when the new value is the empty string.

**Row construction is specified here, not left to the executor (addresses review
finding HIGH-3).** An earlier revision of this plan told the executor to read
"the visibility defaulting `Create` applies" — no such defaulting exists.
`applyVisibilityDefaults` (`internal/world/postgres/property_repo.go:180-191`)
returns early unless the row is ALREADY marked `restricted`, and then fills only
`VisibleTo` / `ExcludedFrom`; `Visibility` itself is passed straight into the
INSERT at `:60-65`, so the column's `DEFAULT 'public'` never applies and an empty
string fails the CHECK at `migrations/000001_baseline.sql:361-362`. Every created
row therefore sets every field explicitly:

| Field | Value | Why |
|---|---|---|
| `ID` | `idgen.New()` | Entity primary key. CLAUDE.md's ULID table assigns entity PKs to `idgen.New()`; `core.NewULID()` is for event and session ids and MUST NOT be used here. |
| `ParentType` | `"character"` | The parent vocabulary `ListByParent` and every property policy key on. |
| `ParentID` | the character ULID | — |
| `Name` | the section 7.2 attribute name, already validated against the closed twelve | — |
| `Value` | pointer to the new value | `Value` is `*string`; the empty string is the DELETE signal and never reaches a create. |
| `Owner` | pointer to the owning character's ULID string | `seed:property-owner-write` (`seed.go:129-134`) and `seed:property-private-read` (`:117-122`) both compare `resource.property.owner` against `principal.character.id`. A nil `Owner` makes every later per-row decision on this row wrong, and it is unrecoverable without a backfill. |
| `Visibility` | the literal `"public"` | Term B on the viewer path is `seed:viewer-property-public-read` (`seed.go:756-760`), which permits exactly `visibility == "public"`. The withholding lever for a profile field is term A — the per-attribute tier floor (section 8.6) — not this column, so a `profile.*` row that is not `public` is invisible at every rung and defeats the phase. v0.13 has **no** game-configured property-visibility default; say so in a comment rather than implying one exists. |
| `CreatedAt` | the command's clock | `updated_at` is stamped SQL-side by `NOW()` (`property_repo.go:56-62`); do not set it app-side and do not fight that clock domain. |

For an update, carry the existing row's `ID`, `Owner`, `Visibility` and
`CreatedAt` forward unchanged and change only `Value` — an update must not
silently re-home ownership or re-open visibility.

**The exported Service command.** Add `UpdateCharacterProfileAttributes` to
`world.Service` in `internal/world/service.go`, taking a `Caller`, the character
ULID, an expected version, and a map from section 7.2 profile attribute name to
new value. Its body MUST carry the `if s.mutator == nil` guard and the
`s.mutator.<closureBuilder>(…)` call directly, in the shape used at `:340-348`
and `:859-871` — the census's go/ast direction reads this method's own body for
the `s.mutator` selector and does not follow calls into a helper.

Three guards precede the executor call, and each is here rather than in Task 2
because each closes a hole that would otherwise be open in this commit:

  1. Reject `expectedVersion <= 0` with the version-required code BEFORE any read,
     copying `RetireCharacter`. The repository's `expectedVersion == 0`
     unversioned-write affordance exists for repo-level callers; INV-WORLD-7
     requires an existing-row character mutation to CARRY an expected version, and
     the Task 1 closure is built on that guarantee — without this rejection the
     closure runs its CAS against a meaningless version.
  2. Reject any key outside section 7.2's twelve names — D-82 enumerates them:
     pronouns, concept, species, age, faction, currently, timezone, appearance,
     personality, biography, rumors, rp_preferences. Deferring this would ship a
     commit whose ABAC-gated write accepts ANY property name on the character;
     that is an unbounded write surface, not a functionality gap.
  3. `checkAccess` with action `write` against **`access.CharacterResource(characterID.String())`
     with the `prefixCharacter` prefix**, so the shipped `seed:player-self-access`
     (`seed.go:39-43`) is what decides for an owning character. Copy the call
     shape verbatim from the shipped sibling at `service.go:848-850`. Deferring
     this would ship an ungated write path.

     **This is a correction — do NOT gate on the property resource (addresses
     review finding HIGH-2).** An earlier revision named `seed:property-owner-write`
     and `checkAccess(write, property resource)`. That cannot work for a create
     and it contradicts the SPEC. `access.PropertyResource` (`prefix.go:255`)
     takes a property id, which a not-yet-created row does not have; resolving
     `resource.property.owner` requires `PropertyProvider.ResolveResource` to
     fetch the row (`attribute/property.go:87-100`), which fails closed with
     `PROPERTY_FETCH_FAILED` when there is none — so the FIRST write of any
     `profile.*` attribute would default-deny and IDENT-02 could never work.
     01-SPEC section 9.3 states the gate directly: `UpdateCharacterProfile` is
     gated by **ABAC `write` on `character:<id>`**. One decision per command, on
     the character, before any read.

     Note what this does **not** give up: the created rows still carry `Owner`
     set to the owning character (see the construction table below), so
     `seed:property-owner-write` remains available as defense in depth for any
     later per-row write path. It is simply not the gate for this command, and
     no second per-property check is added here — a second gate over coverage the
     character gate already has is the duplicate-gate cost 01-SPEC section 2.6
     names.

Then read the character, read its existing properties through `propertyRepo` (the
reader view is sufficient — the write goes through the executor), partition the
requested changes into creates, updates and deletes, build the intent with the new
kind, and route through the closure builder with the character's Version set to
the CALLER's expectedVersion.
