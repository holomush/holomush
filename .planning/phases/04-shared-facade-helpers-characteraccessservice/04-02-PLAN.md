## The Phase-4 gate error matrix (surface × outcome → code)

**This table is the phase's single source of truth for what code leaves the
gate. Plans 04-04, 04-05, 04-06 and 04-07 cite it rather than restating it.**
It exists because review findings HIGH-1 and MEDIUM-2 are the same question
asked on two surfaces, and answering them in two places is how they drifted
apart. Rows are transcribed from 01-SPEC section 9.6 (`:2210-2236`) and section
8.7; the `Internal` row is transcribed from section 8.10 and from the shipped
behavior at `internal/grpc/sceneaccess_service.go:114-118`.

| Surface | Outcome | Wire status | Code | Message |
|---------|---------|-------------|------|---------|
| public read (`GetCharacterProfile`, `ListCharacterDirectory`) | profile below its reachability floor **or** id names no row **or** id unparseable | `NotFound` | `CHARACTER_PROFILE_NOT_FOUND` | one generic literal, identical across all three causes (section 8.7) |
| owner read (`ListMyCharacters`, `GetMyCharacter`) | id unparseable **or** id names no row **or** character not owned | `NotFound` | uniform not-found-equivalent | one generic literal, identical across all three causes — this is exactly what `playerGate.ownedCharacter` already returns, consumed unchanged |
| owner **mutation** (`UpdateCharacterProfile`, `UpdateCharacterDescription`) | id unparseable **or** id names no row **or** character not owned | `PermissionDenied` | `CHARACTER_NOT_OWNED` | one generic literal, identical across all three causes |
| **any** surface | the character repository (or any dependency) failed | `Internal` | the handler's own internal code | one generic literal; `errutil.LogErrorContext` / `slog.ErrorContext` first; never collapsed into a row above |

Three consequences, each of which a plan must honor:

1. **`ownedCharacter`'s own contract is the second row, not the third.** It
   returns `NotFound` for non-ownership (`sceneaccess_service.go:124`). The owner
   READ surfaces consume that verbatim. The owner MUTATION surfaces map it to
   `PermissionDenied` in the facade — 01-SPEC `:2219` assigns `CHARACTER_NOT_OWNED`
   → `PermissionDenied` and scopes it to *"an `owner`-audience **mutation**"*,
   while the uniform-`NotFound` rule at `:2223` is scoped to
   `CHARACTER_PROFILE_NOT_FOUND`, i.e. the public read. The two are different
   rules on different surfaces, not a contradiction. 04-06 owns that mapping.
   The same table's `CHARACTER_NOT_FOUND` → `NotFound` row (`:2218`) carries no
   audience scope, but it does not reach this matrix either: that code is stamped
   only where a single character row is fetched or updated **by id**
   (`internal/world/postgres/character_repo.go:53`, `:169`, `:253`, `:288`,
   `:377`, `:421`, `:527`), whereas ownership here resolves through
   `charRepo.ListByPlayer` (`character_repo.go:340-351`), which stamps only
   `CHARACTER_LIST_FAILED`. An id naming no row is therefore simply absent from
   the player's list and is indistinguishable from an id the player does not own,
   so the mutation surface's nonexistent-id cause collapses into row 3 **by
   construction rather than by a mapping choice** — which is why §9.6 needs no
   amendment for it. (A row deleted after ownership resolves and before the
   domain write is a race against an already-authorized caller, not this cause.)
2. **Uniformity is preserved on every row, including the mutation row.** All
   three mutation causes collapse to one `PermissionDenied` with one message, so
   the mutation surface is no more of an existence oracle than the read surface.
   The change from the read surface is the *status*, not the opacity.
3. **The `Internal` row is never absorbed into rows 1–3.** That is finding
   HIGH-1: an infrastructure failure is not an authorization outcome, and
   masking it breaks INV-SCENE-63's observability contract at
   `sceneaccess_service.go:695-706`.
