symmetric-difference diff on failure; the shipped precedent's semantics are set
equality but its failure rendering is per-element, so this is a strict
improvement on the precedent rather than a new mechanism.

  <action>
Create `test/meta/characteraccess_routing_census_test.go`.

**Universe.** The census is over the **owner**-audience RPCs, both halves of each
proxy pair (D-73). Criterion 1's literal phrasing — every character-returning RPC
— cannot hold: the directory and the public profile serve anonymous viewers by
design, and the guest gate rejects guests outright, so routing them through it
would break the public profile. The owner audience is exactly the set where the
contract is that the caller must be a non-guest player who owns this character.
Public reads are gated by the reachability floor and the per-attribute floors and
are asserted by their own tests. State that reasoning in the file header.

**Facade half.** Walk **every** non-test Go file in `internal/grpc` — not one
file — using the directory-walk shape the caller census uses, for the reason its
own header gives: relocating a handler into a sibling file must not carry it out
of the universe. For each exported method whose receiver type is in the accepted
facade-type set, use the identifier and selector predicates to decide membership:
a method routes through the gate when its body references the guest-gate method
name as a selector on its own receiver, and through ownership when it likewise
references the ownership method name. Because the gate is reached by method
promotion from the embedded struct, both call shapes are a selector on the
method's own receiver — which is precisely why D-78 chose the embedded-struct
shape.

**Web half.** The proxies call neither gate method: they forward a token and
compute nothing, so the facade predicate would report every one of them as a
non-member and the census's proxy half would assert nothing at all. Give it its
own predicate: an owner-audience proxy is a member when its body references the
session-token header identifier **and** references its paired facade method name
as a selector. Both conjuncts matter — the first proves the token is read from
the header rather than the body, the second proves the proxy reaches the gated
facade RPC rather than some other surface.

**Comparison.** Each of the three derived sets is compared against a checked-in
expected set by set equality, failing with the symmetric-difference diff from
Task 1. Do not write a loop over the expected entries: that shape iterates the
expected set, so an unexpected member is never visited and a stale expected
member fails for the wrong reason or gets deleted to make the suite green.

**No exemption list.** D-72 is designed so this census needs none — every
declared RPC has a live handler. Do not add one preemptively, and do not add one
later to make a red census green.

**Demonstrate the RED.** Temporarily delete the guest-gate call from one existing
owner-audience handler, run the census, capture the failure output verbatim
showing the handler named in the missing group, then revert. Record that output
in the SUMMARY as the census's RED evidence.

  <action>
Create `test/meta/character_rpc_census_test.go`.

**Derivation.** Walk the generated service descriptors through the global proto
registry: iterate registered files, then services, then methods, taking each
method's fully-qualified name in package-service-method form. Blank-import every
generated package whose services must be in scope so their registration runs, and
guard against an incomplete registration with an anti-vacuity assertion on the
discovered service count, following the guard the API-coverage meta-test already
carries.

**Membership predicate.** A method is a member when its output message
transitively contains a message from a checked-in set of character-shaped message
full names — walk the message's fields, recursing into message-typed fields with
a visited set so a cyclic schema terminates. Check in the character-shaped name
set explicitly, one entry per message, and assert it is non-empty.

**The name-reachable members.** Section 3.3 records that several members are
reachable only by explicit enumeration: responses carrying a bare display-name
scalar, and the public export surfaces whose payload is rendered bytes with no
proto field naming a character. A descriptor-graph predicate cannot see those, so
carry them as an explicitly enumerated list with one commented member per
justifying reason, and assert that list's membership is exact — the idiom the
caller census already uses, chosen so removing a member is a visible edit rather
than a silent loosening. Union that list into the derived set before comparing.
This enumeration is **not** an exemption list: it adds members, it never excuses
one.

**Comparison.** The key is the fully-qualified proto method name compared as an
exact string — never a substring or prefix match, because one member's name is a
substring of another's and a substring key would silently collapse them; and
never a Go handler identifier, which is not derivable from a descriptor and is
not stable against refactor. The comparison is set equality, order-independent,
and fails with the symmetric-difference diff from Task 1. The checked-in expected
set is the section 3 inventory: section 3.3's rows plus the Phase-4 rows section
9 adds, minus the row section 2.4 deletes. Transcribe it from those tables; do
not re-derive it. Add a file-header note that a later phase adding a
character-returning RPC adds its inventory row in the same change (D-72).

**Demonstrate the RED both ways.** Temporarily add a character-returning method
to the derived side without an inventory row and capture the extra-group failure;
then temporarily add an inventory row with no RPC and capture the missing-group
failure. Revert both and record the two captured outputs in the SUMMARY, so the
census is shown to fail in each direction rather than only one.
  </action>
