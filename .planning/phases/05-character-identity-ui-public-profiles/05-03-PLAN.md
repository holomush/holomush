<objective>
Reshape character creation from the name-only stub into the structured identity card IDENT-01
requires, as one atomic breaking change: a new `CharacterAccessService.CreateCharacter` taking
name, pronouns, concept, species, age and faction and returning `OwnCharacter`, plus its
`WebCreateCharacter` proxy — with the shipped name-only request/response replaced outright per
§2.5's breaking-change posture (D-86).

Purpose: creation is the one owner-audience mutation still living off the facade, and the
shipped `WebCreateCharacterResponse` returns a bare `character_name` scalar with a
`success`/`error_message` pair — a shape that cannot carry the twelve-field identity model, the
D-88 echo, or the version the edit surface needs next. The reshape cannot be split across
plans: the moment `WebCreateCharacterResponse` changes shape its handler stops compiling, so
"the old shape dies in the same change" is a build constraint, not a preference.

Output: two proto surfaces, one facade handler with a closed code→status mapping, one
repointed gateway proxy, the constructor dependency creation needs, and the census rows all
four gates demand.
</objective>

## Pinned decisions this plan settles

**Q1 — the create transaction shape (PINNED; ratified by the checkpoint below).**
`CharacterGenesisService.Create` commits character + binding + genesis envelope in one
transaction (INV-WORLD-1/4). The five structured `profile.*` values are `entity_properties`
rows written by a **different** domain command that demands `expectedVersion >= 1`; nothing in
the tree writes both in one transaction, and widening `CharacterGenesisService` to do so
widens a path carrying INV-WORLD-1 on a plan already reshaping two protos.

So: **two transactions, the create authoritative.** On a second-write failure the RPC returns
**success** with the created `OwnCharacter`, the un-set keys simply absent from its `profile`
map, and logs the failure with the character id and the attempted mask paths. Reporting failure
instead would send the player to retry, and the retry collides with the name they just reserved
— `CHARACTER_NAME_TAKEN` for their own character, the exact duplicate-create hazard
`web/src/lib/scenes/createFlow.ts` documents. The owner repairs the gaps on `/characters/[id]`,
where all five fields are editable. Fields the client left empty are not written at all, so a
name-only create makes no second call.

**Q3 — `CHARACTER_LIMIT_REACHED` and `CHARACTER_NO_STARTING_LOCATION` map to
`codes.FailedPrecondition` (PINNED).** Both are real create-path outcomes with no §9.6 row.
Neither is an invalid argument (the name was fine) and neither is an outage the player should
retry blindly. Recorded as SPEC amendment 4; plan 05-05 files the amendment record.

**Q6 — the `WebCreateCharacter` census row is MOVED, not duplicated.** Leaving it in
`characterNameReachableRPCs()` while its response is also type-reachable keeps set equality
green (both paths add the same key) but leaves a self-certifying entry in a class whose own doc
says it exists only for surfaces a type predicate cannot reach.

**Message carriage (PINNED — this is RESEARCH Pitfall 4's "make the carriage explicit").** The
facade returns `status.Errorf(codes.X, "%s", <authored constant>)`, never `err.Error()` and
never a `%v` of a wrapped error. `internal/grpc/auth_errors.go` already holds one authored
player-facing constant per create-path code and per `charname.Gate` verdict — reuse those nine
and add only the three `charname` produces that it lacks. The switch resolves the code with
`oops.AsOops(err).Code()`, which returns the **deepest** code in the chain (#4902); that is
safe **here specifically** because every outer code whose deepest child could shadow it
(`CHARACTER_CREATE_FAILED`) maps to `Internal`, which is also where an unrecognised deepest code
lands. Task 1 pins that with a test rather than leaving it as a comment.
