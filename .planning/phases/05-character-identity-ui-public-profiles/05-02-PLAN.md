capability and the first route the app has ever served outside `(authed)`.

indistinguishable, because the difference discloses what **this viewer** may not see.

tests that cover behaviour v0.13 data cannot reach.

## Pinned decisions this plan settles

**The public profile and the owner authoring surface share NO presentational component**
(CONTEXT lists this as Claude's discretion). They render the same twelve names but answer
different questions: `PublicProfile.svelte` is a read-only renderer whose correctness property
is *absence*, and `/characters/[id]` is five independent forms whose correctness property is
*per-section save*. Coupling a privacy-critical renderer to a form is how an "improvement" to
one silently changes the other. The **one** shared primitive is
`CharacterPortrait.svelte` — UI-SPEC unifies the portrait treatment (16% `color-mix` tint) across
the profile and the roster, so a single component is what makes "one treatment" true rather
than asserted. — **Reversibility: reversible.**

**The route splits into a shell and a body.** `web/src/routes/c/[id]/+page.svelte` owns the
route param, the fetch and the three-way render branch; `PublicProfile.svelte` is props-only.
This is not decoration: `+page.svelte` reads `$app/stores`, which a vitest mount cannot supply
without a module mock, and the absence contract is the property most worth a held-out test.
A props-only body is directly mountable with the repo's own `mount`/`unmount` idiom. —
**Reversibility: reversible.**

**No `+page.ts` is added.** `web/src/routes/+layout.ts` is two lines (`ssr = false`,
`prerender = false`) and `adapter-static` runs with `fallback: 'index.html'`, so every path
already returns HTTP 200 with the SPA shell — route-level indistinguishability (§8.7) is
structural, not something this route implements. A `load()` here would add a second place the
not-found decision could be made.
