<objective>
Ship the owner's authoring surface at `/characters/[id]`: five sections, each with its own
Save, its own update mask, its own status region and its own error region, plus the standing
PROFILE-12 statement that privacy here is not retroactive.

Purpose: `UpdateCharacterProfile` (twelve `entity_properties` rows) and
`UpdateCharacterDescription` (the `characters.description` column) are separate RPCs that guard
the **same** `characters.version` with **no transaction spanning them**. A whole-form save is a
two-call chain whose second call can lose a concurrent edit after the first committed, leaving
a partial save and a stale form with no rollback. Per-section save dissolves that: the
system's shape and the interface's shape agree, a conflict costs the player one section of
typing instead of twelve, and the partial-failure state stops existing (D-93).

Output: one route, two reusable components, and the held-out byte-counter test that pins the
one place the client and the server can silently disagree about a limit.
</objective>

## Pinned decisions this plan settles

**Section grouping (CONTEXT's Claude's-discretion item, settled here).** The five sections and
their exact mask paths are UI-SPEC's table and this plan adopts it verbatim: Identity
(`profile.pronouns`, `profile.concept`, `profile.species`, `profile.age`, `profile.faction`);
In-world description (no mask — its own RPC); Appearance & history (`profile.appearance`,
`profile.personality`, `profile.biography`); Hooks & current (`profile.rumors`,
`profile.currently`); Out of character (`profile.rp_preferences`, `profile.timezone`). The
partition is exactly the twelve names in `updateCharacterProfileMaskablePaths` plus the
description — no path is in two sections and none is unassigned. — **Reversibility: reversible.**

**No shared presentational component with `/c/[id]`.** Plan 05-02 records the reasoning: the
public renderer's correctness property is *absence* and this surface's is *per-section save*,
and coupling a privacy-critical renderer to a form is how an improvement to one silently
changes the other.

**The not-retroactive copy** is UI-SPEC's authored string, rendered once at the top of the
page. Its placement is D-91's: there is no player-facing retirement flow in v0.13, so
PROFILE-12's retirement half moves to Phase 6 alongside `AdminRetireCharacter`. Attaching the
notice to the roster's not-playable section instead would put a warning where nobody is making
a decision.

    - Given a 99-byte multi-byte value (for example a run of 33 three-byte CJK characters) against a 100-byte cap, the counter reports 99 of 100 and does not report the value as over cap.
    - Given a 100-byte multi-byte value against a 100-byte cap, the counter reports exactly 100 of 100 and does not report it as over cap — the server's comparison is strictly greater-than.
    - Given a 101-byte multi-byte value against a 100-byte cap, the counter reports 101 of 100 and marks it over cap.
    - The same three cases against the 4000-byte cap behave identically at 3999 / 4000 / 4001.
    - Given a value below 80% of its cap the component renders nothing at all.
    - Given an ASCII value the byte count equals the string length, so the common case is unchanged.
    - A value containing an astral-plane character (a surrogate pair, string length 2) is counted as its four UTF-8 bytes, not as two.
