<objective>
Commit the session-lifecycle matrix as a machine-readable registry, add the harness seam the
lifecycle specs need, and cover the first transition family — fresh character selection and
both reattach paths.

Purpose: the phase's success criterion asks for a matrix covering connect, reconnect,
multi-character, and idle-timeout paths. The source matrix is twelve transitions across four
transport columns with ten positions marked not applicable, leaving thirty-eight populated
cells. Committing it as a registry rather than as prose is what lets a later meta-test prove
the claims are true. Separately, the existing session integration suite is wired against raw
stores, not the in-process harness, so the transition specs need a seam that does not exist yet.

Output: the registry with every position dispositioned, a shared harness accessor, and the
first family of specs.

Decisions implemented: D-12 (the full matrix, with each cell getting a passing spec or an
explicit covered-elsewhere pointer — noting the corrected count of 38 populated cells, not 48),
D-13 (committed matrix plus a bijection meta-test modelled on the quarantine registry; the
meta-test itself lands in a later plan so it is green on arrival), D-16 (the existing multi-tab
authentication suite is cited for the cells it already covers rather than duplicated).
</objective>
