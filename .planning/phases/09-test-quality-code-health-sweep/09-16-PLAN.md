<objective>
Lock the session-lifecycle matrix with a bijection meta-test, so a cell can never claim
coverage that does not exist.

Purpose: the architecture review that motivated this phase named its own root theme as
assurance artifacts overstating what the code delivers. A committed matrix table is precisely
such an artifact. This meta-test is what stops it becoming one: a row claiming a spec must have
a spec, a spec must belong to a row, and a row claiming coverage elsewhere must point at
something real. The repository already has exactly this guard for its quarantine registry, so
the pattern, the parsing shape, and the failure message form are all established.

Output: one meta-test in the existing meta package, green on landing.

Decisions implemented: D-13 (committed matrix plus a bijection meta-test so coverage claims
cannot silently rot; it lives in the meta package alongside the two existing ratchets — that
placement was Claude's discretion — and carries no invariant-registry entry, following the guard
it models).
</objective>

    Extend the existing shape test in the meta package into a full guard, matching the quarantine
    guard's structure. Two of the three assertions below are new; the third already exists and is
    only strengthened. Reuse the registry parser plan 09-12 wrote — a second parser in the same
    file would drift from the first.

    First, the bijection: collect the identifiers of every registry row whose disposition is spec
    coverage, collect the identifiers appearing in in-code marker comments across the integration
    test tree, sort both, and require them equal with a message that prints both sets. Exclude
    rows marked not applicable, rows marked covered elsewhere, and rows marked not-implementable-from-harness-defaults
    from the registry side; none of those kinds has a marker by design, and including them would
    make the comparison unsatisfiable. The exclusion must be symmetric — a marker naming a row of
    any excluded kind must fail, not be quietly ignored. That symmetry is what stops a
    not-implementable row being quietly upgraded to covered by someone adding a marker for it.

    Second, the pointer check: for every row marked covered elsewhere, require the cited file to
    exist and the cited spec text to appear within it. This is what stops a plausible-sounding
    pointer standing in for real coverage.

    Third, the shape check: this already exists from plan 09-12 and requires the full grid — one
    row per position of the twelve-transition, four-column matrix — with exactly one disposition
    per row. Keep it; it is what stops a registry that lost a row from satisfying the bijection
    trivially. Extend it only to account for the not-implementable-from-harness-defaults
    disposition, which must count as a disposition for exclusivity purposes and must carry an
    issue number.

    While reconciling, verify one thing about the administrator-boot row specifically, because it
    is the row round-2 review found mis-dispositioned twice: its notes must cite the
    `resetpassword --kick` path that actually exists and name the two gaps that leave the row
    uncovered. Notes describing that capability as absent from the tree would be a false claim in
    a committed, machine-read artifact — the exact defect class this guard exists for. If you find
    that wording, fix the notes and record it in the SUMMARY; do not merely let the bijection pass
    over it, since the bijection checks disposition kinds and not the truth of a note's prose.

    Exclude this test file itself from the marker walk, and exclude the registry file. Both
    contain marker-shaped text by construction — the regex literal in one and the row
    identifiers in the other — and a walk that reads them flags itself. The quarantine guard
    already does exactly this self-exclusion and is the model.

    Do not add an entry to the invariant registry and do not annotate this test with an
    invariant binding. The quarantine bijection this guard models is itself unregistered, and
    the rule forbids annotating a test with a binding unless it genuinely proves a registered
    invariant. Record that choice in the SUMMARY so it reads as a decision rather than an
    omission.
