<objective>
Add a timestamped variant of the integration harness's direct-emit helper that returns the
emitted event's identifier.

Purpose: every history-floor spec in this phase — the two reattach/expiry privacy tests and
the floor-preservation arm — needs events at controlled points relative to a session's arrival
time. The existing helper emits at the current instant and returns only an error, so ordering
would have to be established with sleeps. This plan closes exactly that gap and unblocks three
downstream spec plans.

Output: one new method on the harness Session type, with the existing method untouched.

Decisions implemented: D-15 (a timestamped emit variant for deterministic ordering with no
sleeps; the sibling-method form is taken over a variadic option because only a new method can
also add the event-identifier return the floor specs need — the shape was Claude's discretion).
</objective>

    method's signature. The sibling takes the same parameters plus a timestamp, and returns the
    emitted event's identifier as a string together with an error. Keeping the existing method
    intact means no current call site changes and the shared-type blast radius stays at zero;
    a variadic option on the existing method would satisfy the timestamp requirement but could
    not add the identifier return, which the downstream floor specs need in order to assert on
    a specific event.

    never a hand-stamped identifier — then set the timestamp field on the constructed event
    before publishing. Qualify the domain-relative subject the same way the existing method
    does. Reuse the same nil-publisher guard and the same error-wrapping form. Publish through
    the same production publisher the existing method uses, so persistence and audit semantics
    are identical.

    Write a doc comment in the shape of the existing method's: state what it does, that it
    bypasses the command dispatcher, that the subject is domain-relative and gets qualified,
    that the timestamp is caller-controlled so specs can establish ordering without sleeping,
    and that the returned identifier is the emitted event's. Name the deferred backlog item
    about sleep-based synchronisation as the reason the timestamped form exists.

    This package is imported by integration specs behind a build tag, so the unit lane will not
    compile it — verify with the integration lane, not `task test`. Production code must never
    import this package; do not add any production call site.
