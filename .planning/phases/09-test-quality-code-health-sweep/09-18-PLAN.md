<objective>
Correct the test names that genuinely fail the naming convention, fix the vague subtest labels,
and lock both with a committed ratchet.

Purpose: the convention's binding requirement is that a test name communicates an action, a
condition, and an expectation. Its underscore guidance is a recommendation, not a requirement.
A predicate that flags every underscore returns 1,106 hits, of which the large majority are
already full sentences that merely use an underscore as a separator — renaming them would be a
multi-thousand-line diff that fixes nothing and conflicts with every concurrent branch. The
tightened predicate flags names whose final segment is a bare single token, which are genuinely
topics rather than sentences, and returns roughly 114. That is the real defect population, and
it is within the sizing threshold the phase set for itself.

This runs last among test-modifying work by design: the coverage backfill and the lifecycle
matrix both add test files, and running the sweep after them means it also verifies this phase's
own new tests. Every plan in this phase that touches a test file is named in this plan's
`depends_on`, so the last-mover guarantee is a dependency contract rather than a side effect of
wave numbering — the two wave-2 test-touching plans, the attribute-provider work and the
certificate-package backfill, are listed alongside the later ones for exactly that reason.

Output: the hit set fully remediated with no allowlist, and a ratchet that keeps it empty.

Decisions implemented: D-06 (the naming half of the union scope), D-07 as tightened by the
settled decision (a violation is an underscore-form name whose final segment is a single
CamelCase token, with the invariant-binding prefix exempted), D-08 (fix every hit of the
predicate that ships — no allowlist), D-09 (the sizing gate was the release valve: the literal
predicate returned 1,106 hits against a roughly-150 threshold, so the predicate was tightened
rather than an allowlist reintroduced), D-10 (the sweep runs last, as a single pass, so it also
verifies this phase's own new tests).
</objective>
