<objective>
Repair and prove the end-to-end coverage measurement chain, then remove the two
`.codecov.yml` ignore entries whose stated justification depends on that chain working.

Purpose: every other QUAL-02 acceptance criterion in this phase reads a coverage number.
The chain that produces those numbers is currently broken in a way that is invisible from
CI (the `E2E Test` job succeeds while the `e2e` flag uploads 0.0% and the codecov commit
report shows only 2 sessions). Un-ignoring `cmd/holomush` wiring before the chain is proven
would add roughly 656 uncovered statements and drop project coverage about a point — fighting
the very gate this phase installs.

Output: a demonstrably non-empty `coverage-e2e.out` carrying real counts for the core
wiring file, and a `.codecov.yml` whose ignore list and baseline comment tell the truth.

Decisions implemented: D-02 (project target, re-pointed to 80% on the measured number rather
than the falsified ~54.6% baseline), D-03 (uncoverable code — applied in its reversed form: the
two pre-existing `cmd/holomush` ignores are removed rather than accepted), D-05 (no coverage
theatre), D-22 (all work lands on the milestone branch as one pull request).
</objective>

    Establish the actual cause with evidence BEFORE changing anything. Graceful shutdown is
    already correctly wired (exec-form ENTRYPOINT, signal.Notify on SIGINT/SIGTERM in both
    core and gateway, os.Exit which runs Go's exit hooks) — do not re-litigate that; it is
    eliminated.

    Diagnostic sequence, in order:
    (a) Run `task test:e2e:cover` once and, before the deferred cleanup removes it, capture
        what landed under `.coverdata/core` and `.coverdata/gateway` — file count, byte
        sizes, and owning uid. To observe this you will need to temporarily run the compose
        stack by hand rather than through the task's `defer:` teardown, or add a transient
        listing step; do not commit a listing step.
    (b) While the stack is up, probe writability from inside the container as the runtime
        user: exec into the `core` service and attempt to create a file under `/coverdata`.
        A permission failure confirms the bind-mount uid mismatch hypothesis (the host
        `mkdir -p` creates the directories under the host uid; the container runs as the
        `holomush` user created by `adduser`).
    (c) Capture the container exit codes after `docker compose stop core gateway`. Exit
        code 137 indicates SIGKILL after the grace period elapsed, confirming the
        stop-grace-period hypothesis; note there is currently no `stop_grace_period:` key
        anywhere in the compose files, so the default 10s applies.

    Apply only the fix the evidence supports:
    - uid mismatch: set the container user for the coverage overlay so the runtime can write
      the mount (a `user:` key on the `core` and `gateway` services in
      compose.e2e.cover.yaml, matching the host uid), or make the host-created directories
      world-writable at creation time in the `mkdir -p` step of `test:e2e:cover`. Prefer the
      compose-side `user:` key — it is scoped to the coverage overlay and leaves the
      production image's non-root posture untouched.
    - stop grace: add `stop_grace_period:` to the `core` and `gateway` services in
      compose.e2e.cover.yaml with a value comfortably above the observed orchestrated
      shutdown time, and state the observed time in the key's comment.
    Both may apply; apply both only if the evidence shows both.

    Also harden the `test:e2e:cover` task so an empty result is loud rather than silent:
    after `go tool covdata textfmt` runs, fail the task when the produced profile has no
    body (a coverage profile with only its `mode:` header line is an empty profile). Use the
    exit code of that check to fail the task, not a grep of prior output. Add a comment on
    the check naming the failure it exists to catch.

    Carry a comment on every edit naming the settled finding it implements, per the
    repo's comment-cites-the-decision convention.
