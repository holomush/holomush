<objective>
Cover the deliberate-termination transitions and the telnet reattach case: quit, explicit
logout, administrator boot, and a telnet client reconnecting to the same player session.

Purpose: these four rows are where the matrix distinguishes ending a session from merely
losing its connections. The distinction matters — a quit that only detaches leaves the
character apparently present until the reaper runs. The telnet column is deliberately the
highest-value one here: the telnet integration directory currently contains nothing but a
suite bootstrap, so every telnet cell is genuinely new coverage.

Output: specs for the transitions the registry marks as spec-covered — quit, explicit logout, and
telnet reattach — with the multi-session cells cited rather than duplicated, and the
administrator-boot row left uncovered with its true reason recorded. That row's existing entry
point (`resetpassword --kick`) delivers only half the semantics the row asserts and is unreachable
from harness defaults; both facts are recorded rather than either being papered over with an
approximating spec or misreported as an absent capability.

Decisions implemented: D-12 (the termination rows and the telnet-reattach row of the matrix,
with the telnet column included deliberately as the highest-value one), D-16 (the existing
multi-tab authentication suite is cited for the logout multi-session cells rather than
duplicated).
</objective>
