<objective>
Invert the gateway's cookie-and-header security default so secure cookies, HSTS, and CSP are
on unless an operator explicitly opts out, and carry the consequences through the compose
stacks and the operator documentation.

Purpose: the flag currently defaults off. Any deployment behind a TLS-terminating proxy —
which is the normal production shape — therefore serves session cookies without the Secure
attribute and without HSTS or CSP, unless the operator remembered a flag. That is fail-open
configuration in a codebase whose posture is default-deny everywhere else. The cookie
construction and header middleware are already correct and are not touched; only the default
and its plumbing change.

Output: a fail-safe default, an explicit and documented opt-out, compose stacks that still
work, and a release-note-grade entry in the operating reference.

Decisions implemented: D-17 (one of the four Medium-cluster items that land), D-18 (invert the
default and keep the existing flag name, with an explicit false spelling for local development;
release note required), D-21 (the cookie-and-transport-coupling residue item is this change, so
it is handled here rather than filed separately).
</objective>
