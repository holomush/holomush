### Warnings

**W1 (was WR-07, deliberately not fixed) — the contributor doc states unimplemented flusher
registration in the present tense.** `background-job-authorization.md:185-189` reads: "it
**registers a `job:` identity and its declared capability class** in `jobs.Registry` at subsystem
Start and unregisters at Stop, exactly like every other background consumer." This is false against
the tree. There is no `last_active_at` flusher subsystem in-tree at all
(`rg 'Flusher|flusher' --glob '*.go' -g '!*_test.go'` returns only unrelated `http.Flusher`
matches and prose), and `jobRegistry.Register(...)` appears only inside a comment at
`cmd/holomush/core.go:408`. The ROADMAP itself names the flusher as "Phase 3's". The surrounding
coarse-authority claim — criterion 4's actual ask — is correct; only this concrete example
over-claims. A contributor reading it would believe a wiring exists that does not. One-paragraph
fix (future tense, or delete the paragraph).

**W2 (WR-02, unaddressed) — `JobProvider.ResolveSubject` reads liveness through two separate
`RLock`s** (`IsJobRunning` then `DeclaredWrites`, `job_provider.go:75,93`). Under a concurrent
`Unregister` the provider can stamp `{name, has_writes:false}` where INV-ACCESS-13 clause (1)
promises `(nil, nil)`. The race FAILS CLOSED (the capability conjunct then evaluates false and the
write is denied), so it is not a security regression — but the invariant summary is stricter than
the code under concurrency.

**W3 (WR-03, unaddressed) — `Registry.Register` silently last-writer-wins on a duplicate job name**
(`registry.go:83`), replacing a security-gating capability class with no error and no log line.

**W4 (WR-05, unaddressed) — four integration-tier compilation sites still build compilers with no
`action` namespace**, so "the branch behaves identically at every compilation site" is true of the
five production sites verified here but not of those four.

**W5 (WR-06, unaddressed) — stale comment in `caller_test.go`** stating this phase's own work as
still-future.

All five are recorded in `02.2-REVIEW-FIXES.md` as knowingly out of scope for the fix pass. None
blocks the phase goal.
