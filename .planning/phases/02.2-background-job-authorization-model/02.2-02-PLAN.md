<objective>
Give the production ABAC stack a real, shared `jobs.Registry` to gate liveness against, and make a
job's denial say which kind of principal was denied as well as which kind of resource.

Purpose: plan 01's tracer commit already registered `attribute.JobProvider` in `BuildABACStack`,
because introducing `principal.job.*` into the shipped seed corpus without it would have left both
seed-coverage guards red for a whole commit interval. What that registration does NOT yet have is a
registry: it is wired to `cfg.JobRegistry`, which no entrypoint populates, so it fails closed for
every job. This plan closes that — one `jobs.Registry` constructed in `cmd/holomush/core.go` and
threaded through the subsystem — and adds the explicit `setup_test.go` assertions that pin the
registration by name rather than by the seed-coverage guards' side effect. D-58's deny code is what
lets alerting distinguish "a job was denied on a character" from "a player was denied on a
character" without parsing log attributes.

Output: a single injected `jobs.Registry`, the subsystem accessor family extended, and the composed
`JOB_<ENTITY>_ACCESS_DENIED` code.

(The `<assumption_delta_decision>` block for this phase lives in `02.2-01-PLAN.md`; its consequence
binds here too — every job authorization path in this plan goes through `world.Caller`.)
</objective>
