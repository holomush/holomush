## 🔴 THE D-67 UPGRADE RISK — release-note-ready wording

> **Upgrade risk (knowingly accepted by D-67).** After Phase 02.2 lands, the ABAC policy compiler validates `action.*` attribute references against a declared schema, and an undeclared reference is **fatal for every policy source** — in-tree seeds and operator-authored database rows alike. A deployment carrying an operator-authored policy that references an `action.*` key outside the declared set (`name`, `dispatch_location`, `job.trigger_event_id`, `job.trigger_event_type`, `job.trigger_subject`) **will fail to boot on upgrade**. The remedy is an operator edit to the offending `policies` row; run the pre-flight query below **before** upgrading to identify any such row. This behaviour was chosen deliberately in preference to the alternative — a typo'd `action.*` reference silently default-denying — which is the same fail-closed posture the rest of the ABAC stack takes.

Operator pre-flight, run **before** the upgrade:

```sql
SELECT id, name, dsl_text FROM policies WHERE dsl_text LIKE '%action.%';
```

Every `action.<key>` in any returned row must be a member of the declared set above. A row returning `action.event_type`, `action.plugin_name`, `action.plugin_inst`, or anything else is an actionable finding: edit the policy, or add the key to `attribute.ActionNamespaceSchema()` and rebuild. There is no third option and **no runtime override** — none was added, deliberately.

The boot error names the policy, its database id, and the key:

```text
cache initial reload failed: policy cache reload: compile "operator-authored-audit-grant" (id=01JQ00000000000000000000D1): unregistered action attribute "action.event_type": action namespace is registered but attribute is not
```

This is published where an operator will see it, not only in a planning artifact: `site/src/content/docs/contributing/explanation/background-job-authorization.md`, final section.

### `trigger_subject` normalization — copy byte-for-byte

`trigger_subject` carries the **BARE aggregate ULID** — byte-identical to `bags.Resource["id"]`, which the resolver stamps as the substring after the first `:` of the resource ref.

It is **NOT** a dotted NATS subject (`events.<game>.character.<id>`) and **NOT** a prefixed entity ref (`character:<id>`). Either compares unequal against `resource.id`, and every job write silently default-denies — a failure with no error, only an absence.

Action bag keys as the engine sees them:

```text
job.trigger_event_id
job.trigger_event_type
job.trigger_subject
```

### D-68's answer for `03-05-PLAN.md:100`'s reserved timer-job decision

D-68 is option **A + D**, not option A alone. **Every** background consumer gets a `job:` identity and a declared capability class; **only event-driven** consumers additionally get per-execution instance scoping.

So, for the `last_active_at` flusher: **it registers a `job:` identity and its declared capability class in `jobs.Registry`** at subsystem Start (and unregisters at Stop) like every other background consumer, and it takes **NO per-execution attributes** because it is timer-driven.
