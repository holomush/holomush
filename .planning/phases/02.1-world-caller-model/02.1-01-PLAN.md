mechanically), not by necessity. Do not re-split Plan 02's flip on the strength of this note.

  <action>
Create `internal/world/caller.go` (`package world`) defining an exported opaque value type
`Caller` with three unexported fields: a subject string, a system bool, and an attribute map of
`map[string]any`. Export exactly two constructors — `HumanCaller(subjectID string) Caller` and
`SystemCaller() Caller`. `SystemCaller` derives its system flag itself and hardcodes the bare
subject the S1 gate compares against; it takes no parameters, so a system caller cannot be
misconstructed. `HumanCaller` never sets the system flag and never re-derives or re-prefixes the
string it is handed — it wraps the already-built subject verbatim, because that same string becomes
the world-change outbox envelope actor. Neither constructor populates the attribute map in 02.1.

Model the type on `internal/access/policy/types/types.go`'s `Decision` (unexported fields, a
constructor that derives the dependent field, value receivers). Give it ONE unexported method used

non-system caller and `access.WithSystemSubject(ctx)` for a system caller. Do NOT add exported
accessors: the subject and attribute map are read only from inside `package world` via direct field
access, and `internal/property` (Plan 02, D-66) threads the whole value without ever needing the
