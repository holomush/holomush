## 1. Summary

The plans have a strong authorization model and correctly preserve the critical distinction between `"system"` and `"system:bootstrap"`. However, they are not execution-ready. # Cross-AI Plan Review — Phase 02.1 (World Caller Model)

## 1. Summary

These are unusually well-grounded plans: the S1 double-gate mechanics, the `system:bootstrap` hazard, the grouped-declaration codemod trap, the unnamed-parameter blind spot, and the census-test reuse of `test/meta` machinery all check out against the source, and the key security invariants (exact-equality bypass, byte-identical subject strings, marker confined to a derived context) are correctly understood and correctly mitigated. There is also a factual error about the `recordingWorldMutator` double's unnamed-parameter methods, and several acceptance criteria use the `rg -c ... returns 0` shape that can never be literally satisfied.

## 2. Strengths

- **S1 gate mechanics verified exactly as described.** `internal/access/policy/engine.go:92-93` is exact string equality `req.Subject == "system"` AND `access.IsSystemContext(ctx)`, with a hard `SYSTEM_SUBJECT_REJECTED` on bare subject without marker. The plans' central security reasoning (mapping `system:bootstrap` to `SystemCaller` would create four total bypasses; the exact-equality gate is what makes `HumanCaller("system:bootstrap")` safe) is correct. The four `system:bootstrap` sites exist at `internal/bootstrap/setting.go:134,272,276,331` as cited.
- **The derived-context design preserves semantics.** `IsSystemContext` has exactly one non-test consumer in the tree (`engine.go:93`), so confining the marker to a derived ctx passed only to `Engine.Evaluate` changes nothing downstream — repositories and the outbox never read it. Plan 01's "never reassign the incoming ctx" rule is the right shape.
- **The `location_follow.go` criterion-4 migration is fully verified.** `const systemSubjectID = "system"` at `:28`, `sysCtx := access.WithSystemSubject(ctx)` at `:197`, world calls at `:203`/`:216` — all as cited; the plan's warning against `HumanCaller(systemSubjectID)` is correct (it would hard-fail S1).
