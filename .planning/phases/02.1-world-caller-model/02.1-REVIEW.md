# Phase 02.1: Code Review Report

**Reviewed:** 2026-08-08
**Depth:** standard
**Files Reviewed:** 57
**Status:** issues_found

## Summary

The migration itself is semantically clean. I traced the full ABAC and audit path
and found **no behavioral regression**:

- `checkAccess` (`internal/world/service.go:209-262`) forwards `caller.attrs`
  where a hardcoded `nil` used to sit; no production constructor populates
  `attrs`, so `types.NewAccessRequest` normalizes identically.
- The outbox envelope `Actor` value is unchanged at every write site: all 20
  `world.HumanCaller(...)` production call sites pass the pre-flip subject string
  verbatim, and the only two `world.SystemCaller()` production sites
  (`internal/grpc/location_follow.go:200,213`) are reads that write no envelope.
- Dropping the ambient `access.WithSystemSubject` from `location_follow.go` is
  safe: `access.IsSystemContext` has exactly one non-test reader,
  `internal/access/policy/engine.go:93`, and `Caller.evalContext` re-derives the
  marker for that call. Nothing downstream (repos, outbox) read it.
- I ran the codemod rules read-only. The re-run contract holds: all four rewrite
  rules produce 0 hunks on the post-flip tree, and `probe-subject-param.yml`
  reports exactly the pinned 8 residual sites.

The defects are concentrated in the *enforcement and documentation* layer that
this phase shipped as its headline deliverable — the meta-test has a real bypass,
three call sites use the exact spelling `caller.go` forbids, and several
justifying comments are factually wrong about the code they justify.

No Critical findings. ABAC/authorization surface deliberately not re-litigated
(prior `abac-reviewer` pass).

## Warnings

### WR-01: The INV-WORLD-8 census is blind to unnamed-receiver `*Service` methods

**File:** `test/meta/world_caller_census_test.go:134` (via
`test/meta/world_envelope_census_test.go:154-156`)

**Issue:** `worldServiceCommands` builds its command universe from
`serviceReceiverName(fn.Recv.List[0])`, which returns `("", false)` when
`len(recv.Names) == 0` — i.e. for a method declared with an **anonymous
receiver**:

```go
func (*Service) GetThing(ctx context.Context, subjectID string, id ulid.ULID) (*Thing, error)
```

That is legal Go, it is used elsewhere in this very codebase
(`internal/property/definition_name.go:36` `func (nameDefinition) Set(...)`,
`internal/world/caller_test.go:122` `func (stubLocationReader) ListByType(...)`),
and such a method is dropped from the universe entirely — not just from the
`authorizing` predicate but from **all three** census tests, including
`TestWorldServiceCallerParamSlotHoldsNoBareStringOnAnyCommand`
(`:258-270`), which the file's own header calls "the no-escape-hatch half".

This matters because it directly contradicts the registered invariant text:
`docs/architecture/invariants.md:483` states the census "catches a future command
written with a bare `subjectID string` — which the compiler would accept". For an
anonymous-receiver command it does not. The hole is latent today (zero
anonymous-receiver `*Service` methods exist) but the whole point of the census is
future commands.

**Fix:** make the receiver-name lookup total rather than dropping the method.
`serviceReceiverName` is shared with `serviceMutatingMethods`, so do not change
its contract in place — add a census-local variant, or return a sentinel:

```go
// in world_caller_census_test.go, replacing the shared call:
recvName, isService := serviceReceiverNameAllowingAnonymous(fn.Recv.List[0])
// returns ("", true) for `func (*Service) F(...)`; bodyReferencesSelector on an
// empty recv name can never match, so such a method lands as non-authorizing and
// is caught by the exemption test AND by the bare-string test.
```

Add a fixture asserting an anonymous-receiver command is seen by the universe.

### WR-02: Three call sites use `world.HumanCaller("system")` — the exact spelling `caller.go` forbids

**File:** `internal/world/postgres/cascade_delete_test.go:338`, `:377`, `:416`

**Issue:** `internal/world/caller.go:85-87` states, as the justifying rationale
for `SystemCaller` existing at all:

> A bare "system" subject WITHOUT the context marker is a hard
> `SYSTEM_SUBJECT_REJECTED`, which is why a system call site must never be
> spelled `HumanCaller("system")`.

`scripts/codemod/README.md:325-326` repeats the prohibition. Yet the codemod
mechanically produced exactly that spelling at three sites:

```go
err := svc.DeleteLocation(ctx, world.HumanCaller("system"), locID)   // :338
err := svc.DeleteObject(ctx, world.HumanCaller("system"), objID)     // :377
err := svc.DeleteCharacter(ctx, world.HumanCaller("system"), charID) // :416
```

These pass only because the fixture wires `policytest.AllowAllEngine()`
(`:326`), which never reaches the S1 gate. Swap in a real engine — the direction
this suite would naturally evolve — and all three fail with a
`SYSTEM_SUBJECT_REJECTED` that reads as an unrelated infrastructure error. They
also write the literal `"system"` into the envelope `Actor` of three write
commands, which is precisely the audit-fidelity hazard
`internal/world/outbox_actor_test.go:52-58` was written to guard.

Worse, `scripts/codemod/README.md:158-162` explicitly *blesses* these three lines
by name — it cites `cascade_delete_test.go:338, :377, :416` as the "real" hunks
that prove the `RECV` blocklist does not over-suppress. A future reader following
the README will reproduce the forbidden rewrite.

**Fix:** change all three to `world.SystemCaller()`, and amend
`scripts/codemod/README.md`'s "Other hand-migrated surfaces" section (`:320-327`)
to list `internal/world/postgres/cascade_delete_test.go` alongside
`internal/grpc/location_follow.go` as a hand-migration target rather than as a
retention-proof example.

### WR-03: The migrated parameter is still named `subjectID` while typed `Caller`

**File:** `internal/world/service.go:265` (and 22 sibling commands),
`internal/world/mutator.go:30`, `internal/command/types.go:40`,
`internal/plugin/hostfunc/adapter.go:24`,
`internal/plugin/hostfunc/helpers.go:112`

**Issue:** `world-caller-decl.yml:83` emits `fix: '$NAME world.Caller'`, deliberately
preserving the old parameter name. The result is systemic across the whole
public surface:

```go
func (s *Service) GetLocation(ctx context.Context, subjectID Caller, id ulid.ULID) (*Location, error)
...
intent := s.buildIntent(kindLocationCreated, wmodel.AggregateLocation, loc.ID, subjectID.subject, payload)
```

`subjectID` is not an ID and the expression `subjectID.subject` reads as a
tautology. The phase's stated goal was to make the execution identity an opaque
*value* rather than a subject string; the parameter name still asserts the old
model at 61 sites in `service.go` alone, on 5 exported interfaces, and in the
Lua callback signature. It also degrades the census's own error messages, which
tell a contributor to fix "world.Service.X ... its second parameter type is
string" while the surrounding code models the correct shape under the wrong name.

**Fix:** rename to `caller` across the 23 commands, `Mutator`,
`command.WorldService`, `hostfunc.WorldService`/`WorldMutator`, and
`withMutatorContext`'s callback. This is a pure rename and can be driven by the
same ast-grep machinery (a `world-caller-rename.yml` scoped to the same method
allowlist). Update `internal/world/mutator.go:20-25`, which already describes the
value correctly, and the 23 command doc comments, which do not mention the caller
at all.

### WR-04: `outbox_actor_test.go` does not exercise the `Caller` on the path it claims to cover

**File:** `internal/world/outbox_actor_test.go:75-93`

**Issue:** The test's header (`:15-31`) claims it is "the automated detector" for
"a normalization applied INSIDE the caller value", reachable only by "driving
buildIntent / buildMoveIntent from a real Caller". But the assertions do not
drive them from a Caller — they extract the string first and pass it in:

```go
require.Equal(t, tt.wantActor, tt.caller.subject, ...)   // :72 — this is the real check
intent := svc.buildIntent(..., tt.caller.subject, ...)   // :79 — plain string in
require.Equal(t, tt.wantActor, intent.Actor, ...)        // :82
```

Line 72 already fully covers the stated normalization hazard. Lines 75-93 then
prove only that `buildIntent`/`buildMoveIntent` are identity pass-throughs for a
`string` — a property unrelated to the caller model and unchanged by this phase.
The link the migration actually edited — each command body's
`subjectID.subject` at `service.go:310, 340, 394, 456, 489, 521, 618, 651, 688,
736, 777, 833, 1029` — is bypassed. Command-level `Actor` coverage exists only at
`internal/world/service_test.go:271` (CreateLocation) and `:4026` (MoveCharacter),
2 of the 13 envelope-writing commands.

**Fix:** drive the table through a real command instead of the builders, e.g.
reuse the `service_test.go` outbox-recording fixture and assert
`outbox.lastIntent.Actor` after `svc.CreateLocation(ctx, tt.caller, loc)`. That
version fails if any command body swaps `subjectID.subject` for something else;
the current one cannot.

### WR-05: `caller_test.go`'s justification for its hand-rolled doubles is factually wrong

**File:** `internal/world/caller_test.go:111-113`

**Issue:**

```go
// stubLocationReader is a minimal world.LocationReader. package world cannot
// import internal/world/worldtest (that package imports world, so an in-package
// test file importing it is an import cycle), hence the hand-rolled double.
type stubLocationReader struct{ loc *world.Location }
```

`caller_test.go:4` declares `package world_test`, not `package world` — and
`internal/world/export_test.go:12-21`, added in this same phase, explains at
length that an external test package is *exempt* from exactly this cycle. The
sibling file `internal/world/service_test.go` is `package world_test` (`:4`) and
imports `worldtest` (`:27`), using `worldtest.NewMockLocationRepository(t)`
throughout. So the stated blocker does not apply and the ~35 lines of
`stubLocationReader` (`:113-151`) duplicate an existing generated mock, including
a bespoke `errProbeWriteUnsupported` code.

**Fix:** either replace `stubLocationReader` with
`worldtest.NewMockLocationRepository(t)` + `EXPECT().Get(...).Return(loc, nil)`,
or — if the hand-rolled double is preferred for other reasons (no `EXPECT()`
ceremony in a 4-test file) — correct the comment to say so, because the current
text will mislead the next contributor into duplicating a mock they could import.

### WR-06: `world.SystemCaller()` is a single-token, unpinned, exported ABAC bypass

**File:** `internal/world/caller.go:88-90`

**Issue:** Before this phase, taking the S1 bypass on a world command required
two coordinated tokens at the call site — the literal subject `"system"` **and**
`access.WithSystemSubject(ctx)` — which is why the pre-flip tree had exactly one
such site (`internal/grpc/location_follow.go:197` at `e4f58beb1`), and why it was
trivially greppable via `WithSystemSubject`. After this phase, full ABAC bypass on
any of the 23 commands is one argument: `world.SystemCaller()`.

That is the intended ergonomic improvement, but nothing pins the resulting call-site
set. `SystemCaller()` is the natural thing a contributor reaches for when a test or
a new internal path is denied, and the census
(`test/meta/world_caller_census_test.go`) checks parameter *shape* only — it says
nothing about who constructs a system caller. This repo already has the idiom for
pinning such a set (`worldCallerExemptCommands` at `:76-88`, and the
`outOfServiceOnlyKinds` pattern it cites).

**Fix:** add a fourth census test enumerating every non-test `world.SystemCaller()`
call site against a documented allowlist, mirroring
`worldCallerExemptCommands`'s one-commented-member-per-decision shape. Today the
allowlist is exactly `internal/grpc/location_follow.go` (2 sites).

### WR-07: `Caller.attrs` is a shared-reference map on a type documented as an opaque value

**File:** `internal/world/caller.go:50`, consumed at
`internal/world/service.go:216`

**Issue:** `Caller` is documented (`:23-25`) as "modelled on
`internal/access/policy/types.Decision`: unexported fields, a constructor that
derives the dependent field, value receivers", i.e. as an immutable value. But
`attrs map[string]any` is a reference: copying a `Caller` aliases the same map,
and `checkAccess` hands that live map straight to `types.NewAccessRequest`
(`service.go:216`), where it is retained on `AccessRequest.Attributes`. A caller
built once and reused across commands — the obvious 02.2 shape — shares mutable
state with every request it produced, and a mutation after construction
retroactively changes an already-issued authorization request.

It also makes `Caller` non-comparable (`==` will not compile), which is why the
migrated tests had to switch to
`assert.Equal(t, world.HumanCaller("plugin:core-scenes"), m.lastFindSubject)`
(`internal/plugin/hostcap/world_test.go:513`) rather than comparing a string.

This is latent — no production constructor populates `attrs` in 02.1 — but the
fix is one line now and a migration later.

**Fix:** clone on construction and on read, in the same commit that introduces the
attribute-populating constructor:

```go
func newCallerWithAttrs(subject string, attrs map[string]any) Caller {
    c := Caller{subject: subject}
    if len(attrs) > 0 {
        c.attrs = maps.Clone(attrs)
    }
    return c
}
```

and have `checkAccess` pass `maps.Clone(caller.attrs)` (or document explicitly
that `AccessRequest` takes ownership).
