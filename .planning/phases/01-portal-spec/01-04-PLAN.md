<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| non-admin caller -> an admin RPC invoked directly, bypassing the route | the route guard is not the boundary; the RPC gate is |
| admin -> the character edit field mask | a privileged actor whose mask must not reach a role field |
| two concurrent writers -> one character row | lost-update surface the version guard exists to close |
| any caller -> an ordering, count, or filter over profile fields | an aggregate side channel around per-field omission |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-20 | Elevation of privilege | Section 10 admin gate placement | high | mitigate | Specify the decision as ABAC on an admin-section resource through one shared helper called first at every entry point, explicitly never a bare role lookup and never a route-guard decision; require every admin RPC to re-assert its own gate. |
| T-01-21 | Elevation of privilege | Section 10 field-mask allowlist | high | mitigate | Mandate an allowlist with exact-string path matching and no prefix or wildcard expansion, and record role mutation as an explicit exclusion so an omission cannot later be read as permission. |
