<review_disposition>
**R1 — Consensus HIGH (Codex HIGH, pi MEDIUM): unconditional `kv.Delete` after flush destroys a concurrent listener Put. ADOPTED: revision-conditional deletes.** The flusher models each buffered entry as `(characterID, timestamp, revision)`: `ListKeys` yields key names only, so the flusher `Get`s each key and carries the entry's `Revision()` through the flush, then deletes with `kv.Delete(ctx, key, jetstream.LastRevision(rev))` — the pinned API built for exactly this race (`nats.go@v1.52.0/jetstream/kv_options.go:96-98`: deletes only if the latest revision matches). A revision-mismatch error means newer activity arrived between read and delete: the key is LEFT for the next tick (the already-written older timestamp is harmless — the monotonic writer absorbs it). Task 2 carries the behavior line and a unit test for the concurrent-Put-during-flush interleave.

**R2 — Codex MEDIUMs on the same task, adopted as pins:** (a) `ActivityWriter` is a NAMED FUNCTION TYPE (`type ActivityWriter func(ctx context.Context, characterID ulid.ULID, nanos int64) error`) — a bare free function does not implement a method-bearing interface, and core.go wires it as a closure over the world pool calling `worldpostgres.UpdateCharacterLastActive`; (b) `Stop` ordering is producers-first: stop and JOIN the listener consume loop and the flush ticker goroutine, THEN optionally run one final drain, THEN release substrate — a final flush may never race a still-live listener.

**R3 — SG-1/SG-2 (false-green `-run` filter; the integrationtest harness neither runs the new subsystems nor exposes the WithStorage seam). ADOPTED:** the full-stack proof moves to a NEW suite package `test/integration/charactivity/` whose entry function `TestCharacterActivityFlush` makes the `-run` filter real (one `RunSpecs` per package), and Task 3 OWNS the harness `StartOption` (`WithCharacterActivity`) that boots the charactivity subsystem inside `integrationtest.Start` with the MemoryStorage override and a short flush interval — harness files are in this plan's `files_modified`. `test/integration/world/` is untouched by this plan (its hand-built `testEnv` has no bus; adding a second stack there was the SG-2 knock-on).
</review_disposition>
