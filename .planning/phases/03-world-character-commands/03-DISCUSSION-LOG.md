Taxonomy kinds were **not** a choice: the census bijection (`world_envelope_census_test.go:84-88`)

event, we need to ensure that there's a plan, or existing system, for handling/reacting to those."*
Investigation confirmed there was none — no server-side reactor existed, and nothing subscribed to
`character_deleted` either. Without one, criterion 2 would have verified false.

## `last_active_at` seam — NOT RESOLVED

Maintainer pushback on the options offered: *"Why wouldn't this be an event listener from any session
start/end + events generated by the character during the session? (scene / world poses, DMs, ?)"* —
a better definition of "active" than session-create-only. Research confirmed the shape works but

## The pivot

Reading `INV-WORLD-6` surfaced that rename frees the old name, contradicting its "only via
tombstone-emitting hard delete, exactly two paths" text — and that the shipped operator CLI already
does so, so the text is false in production today.

Maintainer asked for the concern in plain terms with evidence, then reframed the problem:

> *"I'm trying to decide if we should _disallow_ renames after the character has participated in any
> scenes, or ever been approved for play. We might allow for 'aliases/display names' to change, but
> not the core character name: Stephen Strange will always be Stephen Strange, but maybe Dr Strange,
> or Joe Bob in particular IC situations, etc."*

and then:

> *"I think it is 2 - but only before _approval_, which we will need a first class character attribute
> for. I think character.status right now may be wrong. It probably needs to be _two_ attributes:
> session_status, and something like 'approval_status' … not_approved, approved, rostered, retired"*

Two frictions surfaced against that value set (the session/lifecycle split is already structural;
`rostered` and `retired` have reserved meanings) — recorded in D-44 for the backlog design work.

**Final decision:** *"move rename entirely out of the milestone, put it in backlog, link it to
rostering, add this discussion context."*
