**Layer 1 — generator.** Create `cmd/internal/gen-confusables/main.go` (package
`main`), following the `cmd/internal/fsmdiagram` precedent. It downloads
`https://www.unicode.org/Public/security/17.0.0/confusables.txt` (pinned,
version-addressed — never the `/latest/` form), accepts a `-input` flag naming a
local copy for offline runs, parses the `# Version:` header into the emitted
`const UnicodeVersion`, parses the `source ; target ; MA #` mapping lines into a
`map[rune]string`, and writes `internal/charname/confusables_table_gen.go` with
the SPDX header, a `// Code generated by gen-confusables. DO NOT EDIT.` line, the
`UnicodeVersion` constant, and an unexported `confusables` map literal.

**Content-address the input (review finding, MEDIUM — 02-REVIEWS.md 02-01).**
Version-addressing the URL prevents an accidental *upgrade*; it does not prevent
upstream replacement of the bytes at that URL, and it makes `task generate` depend
on a healthy network. So the generator MUST verify the input's SHA-256 against a
checked-in digest **before it emits any code**, and fail with an error naming both
the expected and the observed digest. Carry the digest as a `const` in the
generator source (not a side file, so `sources:` drift detection already covers it)
and record in the generator's doc comment how to refresh it deliberately: download,
review the diff, update the constant, re-run. The `-input` flag is verified the same
way, so an offline run cannot skip the check.

**Layer 2 — skeleton.** Create `internal/charname/skeleton.go` with
`func Skeleton(s string) string` implementing UTS #39 §4's core: `norm.NFD` →
per-rune substitution from `confusables` → `norm.NFD` again. Record in a doc
comment that this is `bidiSkeleton(LTR, ·)` reduced for same-direction comparison,
that no surveyed Go package implements the RTL form, and that the comparison in
this system is always same-direction (stored skeleton vs candidate skeleton).

**Layer 3 — pipeline.** Create `internal/charname/pipeline.go` with
`type Normalized struct { Display, Key string }` and
`func Normalize(submitted string) (Normalized, error)` implementing §6.1.1 in

folding. Return `oops.Code("NAME_EMPTY_NORMAL_FORM")` when `Display` is empty.

**Why the leaf rather than `charname → world` (D-28, settling cross-AI review B-1).**
`Gate.Check` must run the syntactic rules (see below) and plan `02-06` must put
`charname.Admitted` on `world.CharacterRepository.Create`. Those two demands are
`charname → world` and `world → charname` — a cycle Go rejects, and the earlier shape
of this plan had BOTH directions as `<automated>` gates, so the phase could not go
green in either direction. Copying the rules into `charname` is the other obvious

because each side has its own passing table. The leaf keeps one implementation and
leaves exactly one surviving edge.

**Layer 4 — gate.** Create `internal/charname/gate.go` with:

- `type SkeletonLookup interface { SkeletonExists(ctx context.Context, skeleton string, excluding *ulid.ULID) (exists bool, unverifiable bool, err error) }`
- `type CheckOption func(*checkOptions)` and `func ExcludingCharacter(id ulid.ULID) CheckOption`
- `type Gate struct { Skeletons SkeletonLookup }`
- `func (g *Gate) Check(ctx context.Context, submitted string, opts ...CheckOption) (Normalized, string, error)`

returning the normalized pair and the skeleton. `Check` runs `Normalize`, then
`syntax.ValidateName` on the display form, then computes `Skeleton(n.Key)`, calls
`SkeletonExists` passing the excluded id from the options (nil when none was given),
and returns `oops.Code("NAME_CONFUSABLE")` on a hit. The error message MUST NOT name
or identify the colliding character. `gate.go` is the single composition point every
later mechanism plugs into — later plans add steps here rather than at call sites.
Variadic options are deliberate: `Check(ctx, name)` keeps compiling at every call
site plans `02-02`, `02-05` and `02-06` add, so the self-exclusion channel is
additive rather than a signature churn across four plans.

**Self-exclusion is required by the SPEC, not a nicety (B-18).**
`01-SPEC.md:702-706` settles that a request whose normalized uniqueness key matches
the current one but whose display form differs — a case or spacing variant — is a
**real rename**, and "does not collide with itself … because the row it would collide
with is its own". Without an excluded-id channel, renaming `Alaric` → `ALARIC`
computes the identical skeleton, matches the character's own row and returns
`NAME_CONFUSABLE` — the SPEC-decided case is structurally impossible. Because
`charname.Admitted`'s only constructor is the gate (`02-06`), Phase 3's
`RenameCharacter` cannot route around it, and `02-06`'s census rule C pins the
constructor set, so retrofitting after that lands is expensive. It goes in here, with
the matching normalized-name half in `02-06`'s `ExistsByNormalizedName`.

**Fail closed on an unverifiable corpus (D-30 sequencing constraint).**
`SkeletonExists` returns a second boolean, `unverifiable`, which its implementations
set when at least one `characters` row still has `name_skeleton IS NULL`. When it is
true, `Check` MUST return `oops.Code("NAME_SKELETON_UNVERIFIABLE")` rather than
treating a miss as "no collision" — a gate adjudicating against a half-populated
skeleton column admits a new confusable of an existing row. This is the durable form
of D-30's sequencing constraint: it holds not only across this phase's waves but
also after a future Unicode-version upgrade whose recompute is interrupted, which is
precisely the case D-23's per-row version column exists to make visible. Record that
rationale in the interface's doc comment.

**`Check` SUBSUMES the syntactic rules — one verdict proves the whole contract.**
Immediately after `Normalize` and before the skeleton computation, call
`syntax.ValidateName(n.Display)` and, on error, return
`oops.Code("NAME_INVALID_SYNTAX").Wrap(err)` so the underlying
`*syntax.ValidationError` survives in the chain and the create path's existing
`CHARACTER_INVALID_NAME` mapping keeps working.

This is the settlement of a cross-AI review finding (02-REVIEWS.md, C2-1) and it is
a **decision, not a convenience**. `Gate.Check` covers normalization, mixed script,
the block list and the skeleton; the syntactic rules separately own min and max rune
length, "letters and spaces only", leading and trailing spaces, and consecutive
spaces. Leaving them apart means the admission token plan `02-06` mints from a
successful `Check` attests **less** than every writer requires — so a name carrying
digits, punctuation, or 200 runes receives an `Admitted` and is written by any call
site that forgot the second call, which plan `02-12`'s CLI rename path is. The two
candidate fixes were "the gate subsumes the validator" and "every writer requires
both proofs"; the second reintroduces the exact remember-to-call-it class the
`Admitted` type exists to remove, so the gate subsumes.

**One rule, one implementation.** Do NOT copy the rules into `internal/charname`
itself — the leaf is the shared home. `internal/world` importing
`internal/charname/syntax` is correct and expected; `internal/world` importing
`internal/charname` is what plan `02-06` legitimately adds and this plan MUST NOT
forbid.
