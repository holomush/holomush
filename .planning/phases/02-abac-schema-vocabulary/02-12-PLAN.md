Write `internal/store/migrations/000056_character_normalized_name_unique.sql` as

`ALTER TABLE characters ALTER COLUMN normalized_name SET NOT NULL;` **then**

Carry the ordering rationale as a comment in substance: Postgres treats NULLs as
distinct for uniqueness, so a unique index over an unbackfilled nullable column
succeeds and enforces nothing — a green deploy with IDENT-09's guarantee silently

had not run, every `normalized_name` would still be NULL and this ALTER would fail
with "column contains null values" before the index was ever considered. Down drops
the index then drops the NOT NULL, in that order.

**State and enforce the write-exclusion precondition between B and C.** Goose's
advisory lock serializes *migrators*, not application writers, so nothing in the
framework prevents an old binary inserting a NULL `normalized_name` after the
backfill commits but before `SET NOT NULL`, or a new binary inserting a duplicate
before the index exists. Both failures are **loud** — the ALTER fails with "column
contains null values", the index creation fails with a duplicate-key error — so the
risk is a repeatedly-failing rollout, not silent corruption. Record that
distinction; it is what makes a stated precondition sufficient rather than requiring
a redesign.

Scope it honestly rather than overstating it. Today's `compose.prod.yaml` runs a
single `core` service with no `replicas:` key, and migrations complete before
`orch.StartAll`, so the migrating process never serves during its own migration —
the window is empty by construction in the default topology. It is NOT empty for
`compose.cluster.yaml` or any multi-replica posture, which is exactly the posture
D-16 assumes elsewhere in this phase.

So: write a `## Deployment precondition` block into `000056`'s header comment and
into this plan's SUMMARY stating that character writers MUST be quiesced across the
`000055`→`000056` boundary; naming the three acceptable ways to satisfy it (drain
all character writers before `000055`; run the pair while only one replica is up; or
rely on the single-replica topology where the window is empty by construction); and
naming the loud failure mode if it is violated, so an operator who hits it
recognizes it rather than debugging it. Do **not** redesign the chain into one
transaction: combining a whole-table backfill with `ALTER TABLE … SET NOT NULL`
holds an ACCESS EXCLUSIVE lock for the backfill's full duration, trading a bounded,
loud, retryable failure for an unbounded outage.

**Remove the transitional NULL branch from all five existence checks.** Plan `02-06`
landed `normalized_name = $1 OR (normalized_name IS NULL AND LOWER(name) = LOWER($1))`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| concurrent create requests → `characters.name` | Two requests race for one in-world identity; the window between the existence check and the insert is the vulnerability. |
| operator → duplicate resolution | A human decides which of two colliding characters keeps its name, and supplies the replacement. |
| migration runner → production schema | A DDL step whose precondition is another step having run. |
| operator → a server that will not start | The resolution command must work in exactly the state that makes the server refuse to boot. |
