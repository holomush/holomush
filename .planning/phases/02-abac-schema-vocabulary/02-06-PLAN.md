<objective>
Close IDENT-09: land the stored normalized name, its `UNIQUE` index, the one-shot
duplicate detection that must precede it, and the operator command that resolves a
collision — with the gate demonstrated RED against today's unindexed schema first.

Purpose: uniqueness today is a check-then-insert sequence with a window between the
check and the write, and the shared existence query compares `LOWER(name)` — an
ASCII-oriented fold over a column that permits any script, so a pair differing only
by NFKC-collapsible compatibility characters was never even a candidate for
rejection. §6.1.3 is explicit: uniqueness is a database constraint, not an
application check.
Output: migrations `000055` (Go backfill + detection) and `000056` (constrain), a
`holomush character name` resolution command, the four-site `ExistsByName`
migration, and the write-site census.

**Research blocker incorporated (RESEARCH § Concerns 2).** D-20 gated Phase 2
execution on goose adoption. That work has landed: `internal/store/migrations/`
holds single-file goose migrations through `000053`, `internal/store/migrate.go`
wraps `goose.Provider`, Go migrations are supported, and
`internal/store/migrate_gointerleave_integration_test.go` already ships a fixture
chain demonstrating D-21's exact A→B→C sequence with C's ordering rationale
documented in its own constants. **Treat that file as the worked example rather
than deriving the shape again.** One caution the fixture itself flags: it passes
`goose.WithDisableGlobalRegistry(true)` because it is a fixture, and the production
provider MUST NOT — doing so would make `000055` invisible to the real chain.

**Research blocker incorporated (RESEARCH § Concerns 4).** IDENT-09 and §6.1.3 both
enumerate **two** writers on the shared existence query. There are **three**
implementations of `ExistsByName` and the third is
`internal/testsupport/integrationtest/harness.go`, whose own comment records that
the production guest service depends on the retry-on-collision behaviour. A plan
that migrates two sites leaves the integration harness diverging from production —
the worst place for a divergence in a phase whose criteria are integration-tier.
Additionally, the guest path never runs the normalization pipeline at all: it
builds a display name by replacing underscores with spaces and calls `ExistsByName`
directly. Both are fixed here.

**Research blocker incorporated (PATTERNS § No Analog / criterion 1's rename
half).** Success criterion 1 and IDENT-07 both require the checks at "create **and**
rename". **No rename path exists in this codebase** — `Rename` returns zero
production matches under `internal/world` and `internal/auth`, and
`RenameCharacter` is Phase 3's. There is therefore nothing to edit for the rename
half, and this plan does **not** quietly satisfy only the create half. It
discharges the rename half **structurally**: `charname.Gate.Check` is made the only
way a character name is admitted, and Task 3's write-site census — derived from the
tree, compared by set equality — turns RED the moment Phase 3 adds
`RenameCharacter` without routing it through the gate. The behavioural rename
assertion lands in Phase 3, against the path that will exist. This is a recorded
decision, not a scope reduction: criterion 1 is **not** amended.
