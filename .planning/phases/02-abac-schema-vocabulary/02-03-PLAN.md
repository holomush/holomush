<objective>
Land the ABAC *vocabulary* every later plan in this phase and Phase 4 gate on: the
three new entity prefixes with their panic-on-empty constructors, the `viewer:`
subject namespace and its attribute provider, and the player-scoped `roles`
attribute §10.5's per-player admin verdict requires.

No policies are seeded here — plan `02-07` owns `internal/access/policy/seed.go`
in a single append. This plan ships only the subjects, resources and attributes
those policies will reference, so that the policies land against a vocabulary that
already resolves.

Purpose: an unregistered attribute namespace does not error — `principal.viewer.tier`
is simply absent from the bag, every condition referencing it evaluates false, and
the whole tier-floor family silently default-denies in production while a unit test
that stubs the bag stays green (RESEARCH P-7). Registering the provider *before*
the policies exist makes that failure mode unreachable by construction.
Output: `internal/access/policy/attribute/viewer.go`, three prefix families, a
player-scoped roles attribute, and their registration.

**Dependency note.** This plan shares no file with the tracer (`02-01`) — it touches
`internal/access/` and `internal/store/role_store.go`, the tracer touches
`internal/charname/`, `internal/world/`, `internal/auth/` and the migrations. The
`depends_on` is an **ordering** dependency, not a file one: tracer-first means the
end-to-end slice is verified before any expansion task runs, and this plan is
expansion.

**Open Question 2 settled here.** RESEARCH flagged the principal type for
`seed:admin-section-access` as the phase's highest-risk unresolved detail: a wrong
principal type makes the policy match nothing and criterion 5 pass vacuously via
default-deny. §10.5's verdict is normative — *the admin gate is evaluated PER
PLAYER* — and the tree's shipped operator path already reads roles per player
(`PostgresRoleStore.PlayerHasRole`, "true iff any character of playerID has role").
The `player` namespace today carries `id`, `grants`, `is_guest`, `has_is_guest`
and **no roles**, so `principal is player` gated on roles is not expressible until
this plan lands it. `principal is character` with `principal.character.roles` is
rejected: it would put two different answers to "is this caller an admin" over one
table, the operator socket saying yes and the web saying no for the same human at
the same moment.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web request → viewer subject construction | The viewer's tier is decided here. A tier sourced from anything the client controls is an authorization decision made by the attacker. |
| `character_roles` storage → player-scoped role read | A character-scoped table read with player-scoped semantics; the blast radius of a role is the player, not the character. |
| policy DSL → attribute bag | An attribute the provider omits evaluates false; an attribute the provider sentinels can match a peer. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-11 | Elevation of privilege | `ViewerSubject` | high | mitigate | A client-supplied tier would let a logged-out visitor present as `player`. Closed by constructing the subject only from server-side session state, by panicking on any token outside the three tier constants, and by a doc comment fixing the trust position. |
| T-02-12 | Elevation of privilege | `ViewerTierProvider` anonymous rung | high | mitigate | An empty-string `player_id` sentinel satisfies `"" == ""` against any other unresolved peer attribute and creates a fail-open match in a default-deny system. Closed by omitting the key and asserting its absence by key presence. |
| T-02-13 | Elevation of privilege | unregistered `viewer` namespace | high | mitigate | An unregistered provider makes every `principal.viewer.*` condition false and the whole family default-deny — fail-closed, but invisible, and the tempting repair is to widen the policies. Closed by registering in `BuildABACStack` and asserting the seed-coverage sweep is silent. |
| T-02-14 | Spoofing | `ViewerTierProvider` id parse | medium | mitigate | A non-ULID player identifier is rejected rather than carried into the bag, matching `PlayerAttributeProvider`. |
