<objective>
Ship the small caller-side helper that performs §8.5.1's conjunction, and the three
behavioural gates that make the conjunction's correctness mechanically enforceable
rather than advisory.

Phase 2 ships no UI and no RPCs, so this helper has no production caller yet —
Phase 4's `CharacterAccessService` is its consumer. Shipping it here is deliberate
and matches D-08's principle that the phase that builds the gate proves the gate.
The alternative — deferring the helper to Phase 4 — would leave §8.5.1.1's
prohibition enforceable only by review, and would leave D-04's mandated regression
test with nothing to test.

Purpose: §8.5.1.1 records the exact failure mode this plan closes. Term B issued
with a `viewer:` subject against the six shipped character-flavored property
policies matches zero policies and resolves default-deny, making `A AND B`
permanently false and every profile empty. That is fail-closed, so it leaks
nothing. **The danger is the repair.** Confronted with a profile that renders empty
for every viewer, the cheapest-looking fix is to drop term B — which restores the
additive-permit exposure and does so quietly, because the symptom it relieves looks
like a bug and the hole it reopens has no symptom at all. Plan `02-07` gave term B
a shape that can match; this plan installs the test that goes RED if anyone ever
drops it.
Output: `internal/access/profilevis` and its three RED-first gates.

**Three cross-AI review findings incorporated (02-REVIEWS.md, all confirmed).**

1. **`createSeedEngine` is unreachable from here.** It is unexported, declared in a
   `_test.go` file, and belongs to `package policy`
   (`internal/access/policy/seed_smoke_test.go:4,21`); `_test.go` symbols do not
   cross package boundaries, so a separate `profilevis` package can never use it.
   Plan `02-07` now ships `internal/testsupport/abactest` — a non-`_test.go` package
   exposing `NewSeedEngine` over the full corpus plus schema-pinned provider doubles
   — and this plan consumes that.
2. **The fixtures could have been falsely green.** Under the earlier
   `principal.viewer.player_id`-against-character-ids twins, the only way to make a
   behavioural test pass would have been to write player ids into `owner` /
   `visible_to` / `excluded_from` — validating an identity model production does not
   have. The mapping is settled in plans `02-13` and `02-07`: rows stay
   character-keyed, and the policies read derived player-keyed peers. This plan's
   fixtures MUST write real character ids into the row fields and let the provider
   derive the peers. **Reshaping a fixture to match a policy is forbidden here**; if
   a fixture will not pass, the policy is wrong.
3. **`Evaluate` is not positional.** The real signature is
   `Evaluate(ctx context.Context, req types.AccessRequest) (types.Decision, error)`
   (`internal/access/policy/engine.go:82`), with requests built by
   `types.NewAccessRequest(subject, action, resource, attrs)`
   (`internal/access/policy/types/types.go:143`). Every call and every recording
   double in this plan uses that exact shape.
