<objective>
Discharge PROFILE-11 and success criterion 4: prove the `seed:profile-public-read-*`
widening actually widens, and establish — from real data, before it merges — exactly
which existing rows and which existing character descriptions it exposes.

Purpose: criterion 4 says the widening ships **only after** an audit. That audit is
a *data* question about live rows, not a design one, and no assertion can stand in
for reading what is actually there. The audit's real job is not to count rows — it
is to find rows that were relying on colocation as **de-facto privacy**, which the
widening removes. D-11 fixes the remedy for any such row in advance: **change the
row's `visibility`, never narrow the policy.**
Output: a committed re-runnable query, its recorded result with a per-row verdict,
and the paired integration proof.

**This plan is the gate on plan `02-07`'s widening.** The two
`seed:profile-public-read-*` entries are seeded in `02-07` but the phase MUST NOT
merge until `02-AUDIT-RESULT.md` exists, is non-empty, AND records a query that
actually ran. That ordering is the whole point of criterion 4's "shipped only after"
clause.

**Two cross-AI review blockers incorporated (02-REVIEWS.md, both confirmed).**

1. **The gate was fail-open.** The earlier Task 2 said "if the database is empty **or
   unavailable**, that is a recorded result and not a missing one". Unavailability is
   not a result — it is the absence of one, and accepting it lets the phase's single
   genuinely one-way change merge without anyone having looked at the data it
   exposes. A gate that a `connection refused` discharges is not a gate. Task 2 is
   now a **blocking checkpoint** on unavailability: only a query that reached a
   database discharges the audit, and a genuine zero-row result from a reached
   database does.
2. **The prescribed remedy is impossible for descriptions.** The earlier human-check
   said a sensitive description should be remediated by changing its row's
   `visibility`. `characters.description` is an intrinsic column on `characters`
   (`internal/store/migrations/000001_baseline.sql:71-76`) with no visibility field
   at all; `visibility` exists only on `entity_properties`. An operator following
   that instruction finds nothing to change and either invents something or does
   nothing. Task 2 now carries a **separate three-option verdict vocabulary** for
   descriptions.
</objective>
