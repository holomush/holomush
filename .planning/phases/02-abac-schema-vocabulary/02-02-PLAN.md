<objective>
Complete IDENT-06 by adding §6.1.2 Mechanism A — the UTS #39 Moderately
Restrictive mixed-script restriction — to the gate the tracer established, and pin
IDENT-08's username rule with the regression guard §6.2 asks for.

The two land together deliberately. §6 opens by stating that character-name
normalization and player-username validation are two separate policies that MUST
NOT share an implementation; IDENT-08's guard exists precisely to fail if a future
change to the character-name pipeline reaches the username path. The plan that
grows the character-name pipeline is therefore the right plan to install the guard
that watches it.

Purpose: close cross-script splicing (`раypal` — Cyrillic а and р inside a Latin
word), which the skeleton check alone does not catch early, and make the
two-policy separation mechanically enforced.
Output: `charname.MixedScript`, its eight-row verdict table, and an extended
`internal/auth/player_test.go`.

**Research blocker incorporated (RESEARCH § Concerns 1).** `02-CONTEXT.md` states
`golang.org/x/text` supplies script extensions for UTS #24. It does not — x/text
has no script package at all. Go's stdlib `unicode.Scripts` supplies the **Script**
property at Unicode 15.0.0, not **Script_Extensions**, which UTS #39's Moderately
Restrictive profile is defined over. This plan takes RESEARCH's disposition (a):
implement §6.1.2's closed eight-row table over `unicode.Scripts`, and record the
divergence. Disposition (b) — generating a second Script_Extensions table — is
**deferred**, with the reason recorded: the marginal fidelity gain is confined to
names whose only second-script evidence is a Common-category codepoint, the
divergence is closed-direction for all three of §6.1.2's named rejections (Cyrillic
and Greek letters carry real `sc` values), and Mechanism B is the defense against
whole-script confusables regardless.

  <action>
Create `internal/charname/mixedscript.go` with
`func ScriptSet(s string) ([]string, error)` and
`func MixedScript(s string) error`.

`ScriptSet` walks the runes of `s`, and for each rune finds the `unicode.Scripts`
range table it belongs to by `unicode.Is`. Runes in `Common` or `Inherited` are
script-neutral and excluded from the set. A rune matching **no** script table is
the Unicode-version-skew case (RESEARCH P-12): return an error carrying
`oops.Code("NAME_UNASSIGNED_SCRIPT")`. Reject is the fail-closed choice and it is
consistent with `characterNameRegex`'s existing letters-only shape, which already
rejects most such runes; document that reasoning in the function's doc comment so
the rule is explicit rather than emergent (RESEARCH Open Question 4). Return the
set as a sorted, deduplicated `[]string` so the verdict is order-independent and
the error message is stable.

`MixedScript` evaluates the resulting set against §6.1.2's table as a closed
enumeration — set size 0 or 1 permits; the three permitted multi-script sets are
`{Latin}` unioned with a non-empty subset of `{Han, Hiragana, Katakana}`,
`{Latin, Han, Bopomofo}` and its subsets containing Bopomofo, and
`{Latin, Han, Hangul}` and its subsets containing Hangul; every other set of size
≥ 2 is rejected with `oops.Code("NAME_MIXED_SCRIPT")`. Express the permitted
combinations as explicit set membership, never as an ordered comparison or a
"count the scripts" heuristic — a heuristic re-derives the table in a second place.

Add a package doc comment on `mixedscript.go` recording, in one paragraph: that
this is UTS #39's Moderately Restrictive profile; that it is computed over the
**Script** property from stdlib `unicode.Scripts` (Unicode `unicode.Version`) and
not over **Script_Extensions**; that the approximation can only ever *miss* a
rejection the faithful profile would make, never add one; and that the confusables
data is at a different Unicode version, which is why an unassigned-script rune is
rejected rather than treated as neutral.

Then extend `charname.Gate.Check` to evaluate `MixedScript(n.Display)` after
`Normalize` and **before** the skeleton lookup, so a mixed-script name never
reaches a database round trip.

Write the tests as a table-driven suite with one row per `<behavior>` case, ACE
sentence names, and non-ASCII fixtures spelled as `\uXXXX` escapes rather than
literal characters.
